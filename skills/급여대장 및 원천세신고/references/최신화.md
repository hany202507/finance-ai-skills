# 최신화 순서

근거목록(`references/근거목록.json`)에 적힌 값이 지금 법령 판과 맞는지 본다. 값을 고치는 일은 사람이 확인한 뒤에만 한다.

## 근거목록의 꼴

```json
{
 "기준일": "2026-11-02",
 "근거": {
  "소득세법 제129조": {"출처": "TaxDoctor", "도구": "get_article", "법령": "소득세법", "조문": "제129조",
                    "스냅샷": "moleg-eflaw:280405@20260701#…", "시행일": "2026-07-01", "최근개정": "2025-12-23",
                    "확인일": "2026-11-02", "링크": "…"}
 },
 "값": [
  {"id": "사업소득_세율", "이름": "사업소득 원천징수세율", "값": 0.03, "근거": ["소득세법 제129조"],
   "구절": "제1항 제3호 100분의 3", "코드": "float(withholding_engine.사업_세율)",
   "쓰는곳": "모듈/원천세/scripts/withholding_engine.py", "등급": "★★★"}
 ]
}
```

- **근거** 하나가 조문 · 별표 하나다. TaxDoctor 의 원천 스냅샷은 법령 판 단위라(`법령id@시행일#해시`) 같은 법의 조문들이 같은 스냅샷을 가진다. 그래서 그 조문의 마지막 개정일을 `최근개정` 으로 함께 적는다. 조문 첫머리의 개정 표시만 보지 않고, 조문 안 모든 항의 `<개정 …>` · `<신설 …>` 표시 가운데 가장 늦은 날짜를 적는다.
- 도구마다 적는 법.

  | 도구 | 스냅샷 | 시행일 | 최근개정 |
  |---|---|---|---|
  | `get_article` | 응답 끝 「원천 스냅샷」 그대로 | 머리의 「현행, 시행」 날짜 | 위 기준 |
  | `get_reference_article` | 같음 | 「시행 구간」 의 시작일(「법령 현행 시행」 날짜가 아니다) | 위 기준 |
  | `get_annex`(별표) | 개정 표시 `<개정 2026. 2. 27.>` | 응답에 없다. korean-law 로 그 개정 부칙의 적용일을 읽는다 | 개정 표시의 날짜 |
  | `get_amendments`(부칙) | 「법률 제20903호(2025-04-02)」 꼴 공포 번호 | 부칙의 시행일 | 공포일 |
  | korean-law `get_law_text` | 「MST 286011 · 대통령령 제36325호」 꼴 | 현행 판 시행일 | 비운다(도구가 개정 표시를 주지 않는다) |
- **값** 하나가 엔진 코드나 항목규칙 csv 의 숫자 하나다. `코드` 는 시험이 그 값을 엔진에서 꺼내는 식이다.
- 등급. ★★★ 은 세법이면 TaxDoctor 와 korean-law 두 곳에서 같은 판을 확인한 것, 비세법 · 부칙이면 원문과 링크를 확인한 것. ★★☆ 은 한 곳에서만 확인한 것. ☆ 은 원문을 못 열어 사람이 확인할 것(고시 · 규격서 등).

## 조회 파일 꼴

`python scripts/최신화.py 목록` 이 낸 근거를 하나씩 읽고 아래 꼴로 적는다. 키는 근거목록 「근거」 의 키 그대로다.

```json
{
 "조회일": "2026-11-02",
 "조회": {
  "소득세법 제129조": {"스냅샷": "도구가 준 원천 스냅샷", "시행일": "2026-07-01", "최근개정": "2025-12-23",
                    "시행예정": [{"시행일": "2027-01-01", "바뀌는점": "제3호는 그대로"}]},
  "소득세법 시행령 별표 2": {"스냅샷": "<개정 2026. 2. 27.>", "시행일": "2026-03-01", "최근개정": "2026-02-27"},
  "최저임금법 제5조": {"열지못함": true, "까닭": "korean-law 응답 없음"}
 }
}
```

- 스냅샷 · 시행일 · 최근개정은 도구 응답을 그대로 옮긴다. 기억으로 채우지 않는다.
- 시행예정은 `get_article` 응답의 「시행예정 개정」 절과 `list_upcoming` 에서 그 조문이 걸린 것만 적는다. 바뀌는점에는 근거목록 값에 영향이 있는지 한 문장으로 적는다. 개정문이 중간에서 잘려 값이 든 호를 못 보면 korean-law `get_law_text` 에 시행일(`effective_date`)을 주어 그 판의 조문을 읽는다.
- 비세법 참조 법령과 korean-law 법령은 `list_upcoming` 대상이 아니다. `get_reference_article` 응답이나 korean-law 판 목록에 시행 전인 판이 있으면 그 판의 조문을 읽어 같은지 적는다.
- 열지 못한 근거는 `열지못함` 으로 적는다. `비교` 명령이 이것을 고칠 후보 목록에 올린다. 다시 읽어 보고, 그래도 못 열면 사람 확인으로 남긴다.

## 비교 결과

| 상태 | 뜻 | 할 일 |
|---|---|---|
| 같음 | 스냅샷 · 시행일 · 최근개정이 그대로 | 없음 |
| 판만 바뀜 | 법령 판은 새로 나왔지만 이 조문의 마지막 개정일은 그대로 | 확인받고 `반영` 으로 판 기록만 고친다 |
| 조문 바뀜 | 조문의 마지막 개정일이 달라졌거나 별표 개정 표시가 달라졌다 | 원문을 읽어 값이 바뀌었는지 본다. 바뀌었으면 고칠 값을 보이고 확인받는다. 바뀐 곳이 값과 무관한 항이면 그 사실을 보이고 확인받은 뒤 `반영` 으로 판 기록만 고친다 |
| 조회 없음 · 열지 못함 | 근거를 읽지 못했다 | 다시 읽거나 사람 확인으로 남긴다 |
| 시행예정 | 공포됐으나 시행 전인 개정이 이 조문에 걸린다 | 시행일과 바뀌는 점을 보고에 적는다. 시행일 전 귀속분에는 지금 값을 쓴다 |

## 값을 고칠 때

1. 고칠 후보마다 근거 원문 구절, 지금 값, 바뀔 값, 적용 시작일을 표로 보이고 확인받는다.
2. 확인받은 값만 고친다. 엔진 코드(`쓰는곳`)와 근거목록 `값` · `근거` 를 함께 고친다. 적용 시작일이 있는 값(요율표 · 간이세액표)은 기존 구간을 지우지 않고 새 구간을 더한다.
3. 시험 코드(`tests/`)가 있으면 `python -m pytest -q tests` 를 돌린다. `test_근거목록.py` 는 근거목록 값과 코드 값이 같은지 보고, 샘플 시험은 금액을 본다. 샘플 기대값이 법 개정으로 달라지면 그 사실을 보고하고 기대값을 고친다.
4. 근거목록 `기준일` 을 조회일로 바꾼다.
