# 규칙세트 스키마

세율, 공제율, 기준금액, 처분기한, 한시배제 양도기한은 판정과 계산 코드가 `rules/ruleset.json` 에서 읽습니다. 신고기한, 분납 기준, 전자신고세액공제, 가산세율은 신고값 생성기(`yangdo/return_values.py`)와 가산세 계산 모듈(`yangdo/penalty.py`)이 같은 파일에서 읽습니다. 코드에 남은 고정 날짜와 햇수는 아래 「코드에 남은 고정값」에 근거와 함께 적었습니다.

사람이 확인한 값은 `rules/추출규칙.json` 에 적고, `scripts/build_ruleset.py` 가 그 값의 원문 발췌가 법제처 조문 본문에 글자 그대로 있는지 대조해 `ruleset.json` 을 만듭니다. 규칙 키 이름의 정본은 `yangdo/keys.py` 입니다. 추출규칙과 판정·계산 코드가 그 이름을 함께 씁니다.

법령의 `판` 은 시행일이 다른 조문 버전이고, `기준정보 판` 은 아래 파일 묶음의 버전입니다.

## rules/ 파일

|---|---|---|

| `ruleset.json` | 규칙세트. 값과 근거 조문, 근거 판의 해시, 시행예정 변경 | `build_ruleset.py build` |
| `기준정보판.json` | 판 id, 확인일, 아래 파일들의 해시 | `build_ruleset.py` |

| `행정구역_대응.json` | 고시 이력과 주소를 같은 이름으로 맞추는 표(이름 변경, 시도 통합, 구 분리, 재편) | 운영자 |

| `법령목록.json`, `법령별칭.json` | 양도소득세에 필요한 법령 목록과 법령 짧은 이름 | 운영자 |

## 추출규칙.json

```json
{"설명": "...",
 "규칙": [
  {"key": "중과.한시배제.가목.양도기한", "설명": "...", "단위": "날짜", "이력": [
   {"시작": "2025-01-01", "끝": "2025-02-27", "기준일": "양도일", "값": "2025-05-09",
    "근거": [{"법령": "소득세법 시행령", "조": "167의10", "항": "①12호의2", "발췌": ["2025년 5월 9일까지 양도하는 경우"]}]},
   {"시작": "2025-02-28", "끝": null, "기준일": "양도일", "값": "2026-05-09",
    "근거": [{"법령": "소득세법 시행령", "조": "167의10", "항": "①12호의2가목", "발췌": ["2026년 5월 9일까지 양도하는 주택"]}]}]}],
 "계류": [{"id": "2026세제개편안-중과", "내용": "...", "영향키": ["중과.2주택", "중과.3주택"],
           "기준일": "양도일", "시작": "2026-05-10", "출처": "...", "등급": "★★☆"}]}
```

- `key` 는 `yangdo/keys.py` 의 `VALUE_KEYS`(값이 있는 키)와 `CITE_KEYS`(근거 조문만 있는 키)에 있는 이름입니다.
- `이력` 은 기준일에 따라 값이 달라지는 구간입니다. 구간이 겹치면 실패합니다. 마지막 구간의 `끝` 은 `null` 입니다.
- `기준일` 은 어느 날짜로 구간을 고를지입니다. `전자신고세액공제.예정`, `지방.전자신고세액공제.예정`, `가산세.무신고.율`, `가산세.무신고.확정신고감면율`, `지방.가산세.무신고.율`, `지방.가산세.무신고.확정신고감면율` 은 `신고일` 이고(전자신고세액공제는 조세특례제한법 시행령 부칙 제36127호 제25조가 전자신고한 날로 적용을 가른다), `가산세.납부지연.일이자율`, `가산세.납부지연.납부일산입`, `지방.가산세.납부지연.일이자율`, `지방.가산세.납부지연.납부일산입` 은 `납부일` 입니다. 나머지는 `양도일` 입니다. 부르는 코드가 그 날짜를 넘깁니다.
- `근거` 의 `조` 는 `"167의10"` 꼴이고, 부칙이면 `"부칙"` 과 `공포번호` 를 함께 적습니다. `판구간` 을 `[시작, 끝]` 으로 주면 그 구간에 시행된 판만 대조합니다.
- `발췌` 는 조문 본문에 있는 글자입니다. 공백과 표 선 문자(`│┌┐└┘├┤┬┴┼─|`)는 지우고 비교합니다.
- 값을 원문에서 자동으로 뽑지 않습니다. 값은 사람이 TaxDoctor 와 korean-law 로 확인해 적습니다.

### 단위와 값 변환

`Ruleset.value(key, 기준일)` 이 단위에 따라 값을 바꿔 돌려줍니다.

| 단위 | 돌려주는 값 |
|---|---|
| `원`, `년`, `개월`, `월`, `일` | 정수 |
| `율` | `Decimal` |
| `날짜` | 문자열 그대로 |
| `세율표` | `[[정수 하한, 정수 기준액, Decimal 세율], ...]` |
| `율표` | `[[정수 햇수, Decimal 율], ...]` |
| `근거` | 없음. 근거 조문만 인용한다 |

## 대조 규칙

`python scripts/build_ruleset.py build` 는 규칙마다 구간마다 다음을 확인합니다.

1. **판 구간.** 근거의 대조 구간(`판구간`, 없으면 이력 구간)과 시행 기간이 겹치는 판을 모두 봅니다. 판마다 발췌가 그 조문 본문에 있어야 합니다. 구간 안에 판이 하나도 없으면 실패합니다.
2. **부칙.** 조가 `부칙` 이면 공포번호가 같은 판의 부칙 본문에서 발췌를 찾습니다.
3. **시행예정 판.** 아직 시행 전인 판에서 발췌가 사라졌으면 실패하지 않고 `예정변경` 으로 적습니다. 결과의 경고에 「시행예정 개정으로 바뀔 수 있다」가 나옵니다. 연혁 판이나 현행 판에서 사라졌으면 실패입니다.
4. **TaxDoctor 대조.** `확인기록.json` 에 현행 판의 DRF 본문과 TaxDoctor 본문이 다르다는 기록이 있으면 실패합니다.
5. **나머지 실패.** 단위를 모르거나, 값이 비었거나, 근거나 발췌가 비었거나, 이력 구간이 겹치면 실패합니다.

실패가 하나라도 있으면 `ruleset.json` 과 `기준정보판.json` 을 쓰지 않고 종료코드 1 로 끝납니다. 이때 값은 고치지 않습니다. 발췌 표기가 원문과 다르면 발췌만 고치고, 값이 원문과 다르면 멈추고 사람이 원문을 확인합니다. 발췌가 어느 판에 있는지는 `python scripts/build_ruleset.py 찾기 --법령 "소득세법 시행령" --조 167의10 --발췌 "2026년 5월 9일까지"` 로 판마다 볼 수 있습니다.

## ruleset.json

```json
{"기준시작": "2025-01-01", "확인일": "2026-10-09",
 "법령판": {"소득세법": ["267581@2025-01-01", "..."]},
 "규칙": {"기본공제": {"설명": "...", "단위": "원", "이력": [
   {"시작": "2025-01-01", "끝": null, "기준일": "양도일", "값": 2500000,
    "근거": [{"법령": "소득세법", "조": "103", "항": "①", "발췌": ["연 250만원"],
              "판": [{"MST": "280405", "시행일": "2026-07-01", "sha256": "..."}],
              "URL": "https://www.law.go.kr/법령/소득세법/제103조"}],
    "예정변경": []}]}},
 "계류": [{"id": "...", "내용": "...", "영향키": ["..."], "기준일": "양도일", "시작": "...", "출처": "...", "등급": "..."}]}
```

- `법령판` 은 받은 판의 `MST@시행일` 목록입니다.
- 근거의 `판` 은 발췌 대조를 통과한 판과 그 조문 본문의 해시입니다.
- `예정변경` 의 항목은 `{"시행일", "법령", "조", "내용"}` 입니다.
- `계류` 는 공포 전이라 계산에 쓰지 않은 개정안입니다. 양도일이 `시작` 이후이고 `영향키` 의 규칙을 쓰면 결과의 경고에 나옵니다.

### 읽는 방법

판정과 계산 코드는 `yangdo/ruleset.py` 의 `Ruleset` 으로만 읽습니다.

| 메서드 | 돌려주는 것 |
|---|---|
| `value(key, 기준일)` | 기준일에 맞는 구간의 값. 맞는 구간이 없으면 `RuleError` |
| `cite(key, 기준일)` | 근거 목록 `{key, 법령, 조항, 시행일, 발췌, URL}`. `시행일` 은 대조를 통과한 판 가운데 기준일에 시행 중이던 판의 시행일 |
| `notes(key, 기준일)` | 시행예정 개정과 계류 개정 경고 문장 |
| `entry(key, 기준일)` | 기준일에 맞는 이력 항목 전체 |

## 공휴일.json

신고기한이 토요일·일요일, 「공휴일에 관한 법률」에 따른 공휴일·대체공휴일, 노동절이면 그 다음 날이 기한입니다(국세기본법 제5조①). `yangdo/dates.py` 의 `filing_deadline` 이 이 표로 기한을 옮깁니다. `ruleset.load()` 가 표를 읽어 `Ruleset.공휴일`(`dates.Holidays`)에 둡니다.

```json
{"설명": "...",
 "법령확인": {"확인일": "2026-10-11", "법령": [{"이름": "공휴일에 관한 법률", "판": "...", "URL": "...", "내용": "..."}]},
 "고정": [{"월": 3, "일": 1, "이름": "3·1절", "시작": null, "끝": null, "근거": "..."},
          {"월": 7, "일": 17, "이름": "제헌절", "시작": "2026-05-11", "끝": null, "근거": "..."}],
 "연도": {"2027": {"확인일": "2026-10-11",
                   "출처": [{"이름": "우주항공청 공고 ... 2027년 월력요항", "URL": "https://..."}],
                   "날짜": [{"날짜": "2027-02-09", "이름": "대체공휴일(설날)"}]}}}
```

- `고정` 은 날짜가 해마다 같은 공휴일과 노동절입니다. 월·일로 세므로 어느 해에나 적용합니다. 공휴일이 된 날과 공휴일에서 빠진 날은 `시작`, `끝` 으로 적습니다. 제헌절은 2026-05-11 부터입니다.
- `연도` 는 해마다 날짜가 달라지는 공휴일입니다. 설날·추석 연휴, 부처님 오신 날, 대체공휴일, 선거일, 임시공휴일을 날짜로 적습니다. 고정 공휴일이 토요일·일요일과 겹쳐 생기는 대체공휴일도 여기에 날짜로 적습니다. 대체공휴일을 규칙으로 계산하지 않고 음력을 환산하지 않습니다.
- `연도` 에는 정부 발표(우주항공청 월력요항, 인사혁신처 임시공휴일 공고)로 확인한 해만 넣습니다. 해마다 `출처` 의 이름과 URL, `확인일` 을 적습니다. 날짜는 그 해의 것이어야 하고 날짜순으로 적습니다. 이름 표기는 해마다 같게 씁니다(「부처님 오신 날」). 해에 `확인일`, `출처`, `날짜` 중 하나라도 없거나 비었으면, 다른 해의 날짜가 섞였으면, 같은 날짜가 두 번 있으면 읽을 때 `ValueError` 입니다.
- 지방공휴일(지방자치단체 관공서만 쉬는 날)은 넣지 않습니다. 국세기본법 제5조①에 없는 날입니다.
- 표에 없는 해는 토·일과 `고정` 만 옮깁니다. 그 해의 연휴와 대체공휴일을 모르므로 실제 기한이 더 늦을 수 있습니다.
- `확인일` 뒤에 지정된 임시공휴일과 선거일은 표에 없습니다. 지정되면 날짜와 출처를 더하고 판을 다시 만듭니다.

`filing_deadline(kind, base, rs)` 은 `(명목 기한, 옮긴 기한)` 을 돌려줍니다. 명목 기한은 옮기기 전 기한입니다. 이 값에 속성 두 개가 붙습니다.

| 속성 | 뜻 |
|---|---|
| `공휴일표` | 명목 기한부터 옮긴 기한까지의 해가 모두 `연도` 에 있으면 `True`. `False` 면 그 해의 연휴·대체공휴일·선거일·임시공휴일을 모르고 옮긴 기한이다 |
| `옮긴이유` | 건너뛴 날과 까닭의 목록. 예: `((2027-02-28, "일요일"), (2027-03-01, "3·1절"))`. 옮기지 않았으면 빈 튜플 |

튜플에 다른 값을 이어 붙이면(`+`) 속성이 사라집니다. 속성을 쓰려면 돌려받은 값을 그대로 둡니다. `copy`, `deepcopy`, `pickle` 로 복사한 값에는 속성이 남습니다.

## 기준정보 판

`rules/기준정보판.json` 은 이 계산에 쓴 기준정보의 판 id, 확인일, 파일별 해시를 담습니다.

```json
{"id": "<16글자>", "확인일": "YYYY-MM-DD", "파일": {"ruleset.json": "<sha256>", "코드표.json": "<sha256>", "...": "..."}}
```

- 해시 대상은 `ruleset.json`, `코드표.json`, `행정구역_대응.json`, `고시/조정대상지역.json`, `고시/투기과열지구.json`, `고시/투기지역.json`, `공휴일.json` 중 있는 파일입니다. 서식 판과 전자신고 규격 판 파일(`forms/서식판.json`, `efile/` 의 규격판·법정동코드·레이아웃·코드)도 있으면 함께 넣습니다. 서식 매핑(`forms/매핑/*.json`)과 필드목록(`forms/필드목록/*.json`)도 넣습니다. 이 파일을 고치면 `python scripts/build_ruleset.py 판` 을 다시 돌립니다. 묶음 목록은 `yangdo/ruleset.py` 의 `EDITION_EXTRA` 에 있고, 두 폴더에 파일을 더하면 그 목록에도 더합니다.
- 파일 해시는 JSON 을 키 순서대로 정렬하고 공백 없이 다시 쓴 문자열의 sha256 입니다. 줄바꿈 방식(CRLF 또는 LF)과 상관없습니다.
- 판 id 는 파일 해시 묶음을 같은 방식으로 다시 쓴 문자열의 sha256 앞 16글자입니다.
- `ruleset.load()` 는 나열된 파일의 해시가 모두 맞을 때만 읽습니다. 하나라도 다르거나 파일이 없으면 `RuleError` 이고, `scripts/run.py` 는 종료코드 3 으로 끝납니다. 고시, 코드표, 공휴일 표를 고친 뒤에는 `python scripts/build_ruleset.py 판` 으로 판을 다시 만듭니다. `공휴일.json` 과 서식·전자신고 판 파일은 `rules` 폴더만 따로 쓸 때 없을 수 있어, 파일이 없으면 대조하지 않습니다. 공휴일 표가 없는 규칙세트는 신고기한이 토·일일 때만 옮깁니다. `공휴일.json` 이 있는데 판의 파일 목록에 없으면(표를 더하고 판을 다시 만들지 않은 경우) `RuleError` 입니다.
- 확인일은 `fetch_articles.py` 를 돌린 날입니다. 오늘이 확인일보다 7일 넘게 뒤면 모든 결과에 기준정보를 갱신하라는 경고가 붙습니다.
- 판 id 와 확인일은 계산 결과의 `기준정보` 와 검토 문서 맨 위에 나옵니다.
