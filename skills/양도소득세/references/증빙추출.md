# 증빙으로 시작하기

매매계약서, 취득세 영수증, 공사 세금계산서 같은 증빙 파일을 먼저 받아 읽고, 읽은 값을 사실관계에 넣은 뒤 남은 문항만 묻는 흐름입니다. 사용자가 같은 금액과 날짜를 두 번 말하지 않아도 됩니다.

읽는 일은 Claude 가 하고, 엔진은 읽은 값이 증빙 원문에 실제로 있는지 대조해 통과한 것만 넣습니다. 계산은 이전과 같이 엔진이 합니다.

## 흐름

| 순서 | 하는 일 | 도구 |
|---|---|---|
| 1 | 증빙 폴더의 파일 목록을 만든다. 문서마다 id(D01...)와 글자층 여부가 나온다 | `yangdo_evidence_inventory` 또는 `python scripts/evidence.py inventory <폴더> --출력 <폴더>` |
| 2 | 문서를 읽고 값을 `증빙추출.json` 으로 적는다. 아래 「서류별로 채우는 문항」을 따른다 | Claude |
| 3 | 원문과 대조해 통과한 값만 사실관계에 넣고 `증빙_확인표.md` 를 만든다 | `yangdo_evidence_apply` 또는 `python scripts/evidence.py apply ...` |
| 4 | 확인표를 사용자에게 보여 주고, 확인이 필요한 값은 사용자가 고르게 한다. 고른 값은 `yangdo_answer` 로 넣는다 | `yangdo_answer` |
| 5 | 남은 문항만 `yangdo_next_questions` 로 묻고 계산한다 | 이전과 같다 |

## 증빙추출.json 형식

```json
[{"문항": "A11", "자산": "A", "값": "2026-11-15",
  "출처": {"문서": "D01", "쪽": 2, "발췌": "잔금은 2026년 11월 15일에 지급한다"},
  "확신": "확실", "비고": ""}]
```

| 키 | 적는 법 |
|---|---|
| `문항` | 문항 id. 값의 형식은 그 문항의 답형식을 따른다(날짜는 YYYY-MM-DD, 금액은 원 단위 정수) |
| `자산` | 자산마다 묻는 문항이면 자산 id. 자산이 하나뿐이면 생략해도 된다 |
| `값` | 문서에서 읽은 값 |
| `출처.문서` | 목록의 문서 id |
| `출처.쪽` | 값이 나온 쪽(1부터). 틀려도 원문에 그 문장이 있으면 받는다 |
| `출처.발췌` | 값이 나온 문장을 **문서에 적힌 그대로** 옮긴다. 고쳐 쓰거나 줄이지 않는다. 날짜와 금액을 적을 때는 값과 함께 들어 있게 한다 |
| `확신` | 글자가 또렷하고 값이 한 가지로 읽히면 「확실」. 흐리거나, 둘 이상으로 읽히거나, 문서 안에서 서로 다르면 「불확실」 |
| `비고` | 읽다가 걸린 점. 인적사항은 적지 않는다 |

목록 문항(자본적지출, 취득부대, 기타, 양도비)은 서류마다 따로 냅니다. 값은 그 서류에 나온 지출의 목록이고, 발췌는 그 서류의 문장입니다. 엔진은 이번에 넣은 목록에 다음 서류의 줄을 이어 붙입니다. 같은 줄이 다시 오면 일치로 세고, 지급일·금액이 같은데 다른 칸이 다른 줄은 같은 지출을 서류 두 장(세금계산서와 이체 확인증 등)으로 낸 것일 수 있어 충돌로 올립니다. 항목 하나는 `{내용, 지급일, 금액, 증빙종류, 상대방, 사업자번호}` 입니다.

## 서류별로 채우는 문항

| 서류 | 채우는 문항 |
|---|---|
| 양도 매매계약서 | A09 계약일, A10 계약금 수령일, A11 잔금일, A13 용도변경 특약, A14 매수인이 대신 내는 세액, A22 토지·건물 가액 구분, M01 전체 양도가액 |
| 취득 매매계약서, 분양계약서 | A16 계약일·계약금 지급일, A17 잔금일·등기접수일, M06 전체 취득가액 |
| 경매 낙찰대금 완납 증명 | A19 대금완납일, M06 |
| 취득세 영수증·납부확인서 | M07 취득세 |
| 취득 때 중개수수료·법무사 영수증 | M08 취득부대(지출마다 지급일, 금액, 증빙종류, 상대방, 사업자번호) |
| 공사 세금계산서, 카드·현금영수증, 공사계약서, 이체 내역 | M09 자본적지출(공사마다) |
| 소송비용, 개발부담금, 도로 개설비 영수증 | M10 기타 |
| 양도 때 중개수수료, 계약서 작성비, 채권 매각 거래내역 | M11 양도비 |
| 건축물대장, 토지대장 | P02 자산 종류, A01 소재지(시도, 시군구, 읍면동까지. 번지는 받지 않는다) |

각 문항이 요구하는 증빙은 질문지 문항 은행의 `증빙서류` 에 적혀 있고, 확인표의 「아직 묻지 못한 문항」에도 문항마다 나옵니다.

## 읽을 때 지킬 것

- 값이 문서에 없으면 적지 않는다. 계산해서 만든 값(합계, 환산)도 적지 않는다. 문서에 합계가 적혀 있으면 그 문장을 발췌로 쓴다
- 성명, 주민등록번호, 전화번호, 계좌번호, 도로명·지번 주소는 값에도 발췌에도 옮기지 않는다. 주민등록번호 모양은 엔진이 가려 두지만 처음부터 적지 않는다. 사업자등록번호는 공사업체 것만 M08~M11 항목에 적는다
- 문서끼리 값이 다르면 둘 다 내고 확신을 「불확실」로 한다. 어느 쪽이 맞는지는 사용자가 정한다
- 자본적지출과 일반 수선의 구분은 판단하지 않는다. 공사 내용은 문항의 선택지 코드에서 문서에 가장 가까운 것을 고르고 `비고` 에 문서의 표현을 적는다. 일반 수선 코드(`일반수선`)는 경비로 인정되지 않는다고 확인사항에 나온다
- `증빙종류` 는 세금계산서, 계산서, 카드영수증, 현금영수증, 계좌이체, 간이영수증, 없음 가운데 하나를 그 글자 그대로 적는다. 이체 확인증이나 통장 거래내역은 계좌이체다. 이 일곱 글자가 아니면 엔진이 그 문항을 다시 묻는다. 증빙 요건을 갖췄는지는 판단하지 않는다

## 엔진이 하는 대조와 판정

| 판정 | 조건 | 결과 |
|---|---|---|
| 반영 | 글자층이 있는 문서에서 발췌가 원문에 있고, 값의 날짜·금액이 발췌에 있으며, 확신이 「확실」이고, 사실관계에 다른 값이 없다 | 사실관계에 넣는다 |
| 일치 | 사실관계에 같은 값이 이미 있다. 경비 목록은 이번에 넣은 줄과 같은 줄이 다시 왔다 | 교차 확인으로 센다 |
| 충돌 | 사실관계에 다른 값이 이미 있거나 같은 문항에 다른 값을 두 번 냈다. 경비 목록은 지급일·금액이 같은 줄이 다른 모양으로 왔다 | 넣지 않고 확인표에 올린다 |
| 확인필요 | 스캔본·사진이거나, 확신이 불확실이거나, 값의 날짜·금액이 발췌에 없다 | 넣지 않고 확인표에 올린다 |
| 거절 | 없는 문항, 없는 문서, 글자층 원문에 없는 발췌, 형식이 틀린 값, 인적사항 | 받지 않고 사유를 적는다 |

금액은 숫자(`1,500,000,000원`)와 「5억 3천만원」, 「3,000만원」 꼴을 대조합니다. 「오억 삼천만원」 같은 한글 숫자는 대조하지 못해 확인필요로 갑니다.

## 이 기능이 보지 않는 것

- 문서가 진짜인지, 위조나 수정이 없는지
- 계약서 금액과 입금 내역처럼 문서끼리 맞는지. 같은 값이 두 문서에서 나오면 「일치」로 보여 줄 뿐입니다
- 스캔본·사진의 글자. 화면으로 읽은 값은 전부 사용자 확인을 거칩니다
- 증빙이 경비로 인정되는 요건(자본적지출 여부, 증빙 적격성)을 갖췄는지. 계산 결과의 확인사항을 따릅니다
