# 전자신고 변환파일 만들기와 홈택스 확인

전자신고 파일은 홈택스에 올리는 양도소득세 변환파일입니다. 규격은 국세청 「양도소득세 전자신고 파일설명서」 V5.17(2026-04-28 게시)입니다. 아래에서는 규격서라고 적습니다. 생성기(`yangdo/efile.py`)는 신고값(`신고값.json`)을 고정길이 레코드로 옮기기만 하고 값을 계산하거나 판정하지 않습니다. 칸의 위치와 길이는 `efile/layout_c116300.json`, 코드는 `efile/codes_c116300.json` 에서 읽습니다.

만드는 건은 예정신고 정기분과, 예정신고를 하지 않은 확정신고 정기분입니다. 전액 비과세 자산이 있는 건, 가산세를 계산하지 못한 확정신고, 기한후신고는 만들지 않습니다(`references/적용한계.md`). 확정신고 파일은 03 레코드의 가산세 칸(15 신고불성실, 16 납부불성실, 17 계)에 예정신고 무신고가산세와 납부지연가산세를 적습니다. 세율구분 행에는 본지의 같은 세율구분 열 금액을, 국내 소계와 합계 행에는 합계를 적고(규격서 p41), 19 자진납부할세액에 가산세가 들어갑니다. 홈택스 로그인, 형식검증, 내용검증, 제출은 사람이 합니다.

## 파일 모양

| 항목 | 내용 | 규격서 |
|---|---|---|
| 파일명 | `<작성일자 YYYYMMDD>C116300.<신고구분상세코드>`. 정기신고만 만들어 상세코드는 `01` 이다. 예: `20261220C116300.01` | p20 |
| 인코딩 | CP949. 한글은 KS X 1001 완성형 2바이트(첫 바이트 0xB0~0xC8, 둘째 0xA1~0xFE), 기호는 첫 바이트 0xA1~0xAC 행, 나머지는 ASCII 0x20~0x7E 만 쓴다. 한자와 「똠」 같은 확장 한글은 쓸 수 없다 | p15 |
| 줄 끝 | 레코드마다 CRLF. 마지막 레코드 뒤에도 붙인다 | p15 |
| 문자 칸 | 왼쪽부터 쓰고 남는 바이트는 공백 | p19~23 |
| 수치 칸 | 오른쪽 맞춤, 앞은 0. 음수는 맨 앞에 `-`. 비율, 면적, 지분은 소수점 없이 소수 자릿수만큼 늘려 쓴다(53.05 는 `05305`) | p19~23 |
| 일련번호 | 문자 칸이어도 앞을 0 으로 채운 6자리(04-3, 05-3, 07-3, 07-5) | p23 |

칸은 「레코드-번호」로 부릅니다. 「03-31」은 03 레코드의 31번째 칸입니다.

## 레코드

레코드는 여섯 가지이고 순서는 01, 02, 03, 04, 05, 07 입니다(규격서 p104).

| 자료구분 | 이름 | 길이(바이트) | 줄 수 | 내용 |
|---|---|---|---|---|
| 01 | HEADER | 350 | 1 | 납세자 ID, 신고 구분, 과세기간, 홈택스 사용자 ID, 성명, 작성일자, 양도일자, 세무프로그램코드 |
| 02 | 기본사항 | 400 | 1 | 신고인 주소(법정동코드, 지번, 아파트), 전화, 전자메일, 내외국인, 거주구분, 거주지국, 국적 |
| 03 | 세율별내역 | 450 | 세율구분 수 + 2 | 국내분 소계 행, 세율구분 행, 합계 행. 본지의 금액 |
| 04 | 양수인내역 | 150 | 양수인 수 | 양수인 번호, 성명, 지분, 양도인과의 관계 |
| 05 | 양도소득금액계산명세 | 700 | 자산 수 | 부표1 의 값. 소재지 법정동코드와 지번, 등기목적과 등기원인 코드 |
| 07 | 취득가액및필요경비계산상세명세 | 200 | 지출 수 | 부표3 의 명세 행 |

레코드의 둘째 칸 서식코드는 01~04 가 `C116300`, 05 가 `C116400`, 07 이 `C116600` 입니다. 03 은 국내외분과 세율구분 순서, 05 는 일련번호 순서, 07 은 일련번호, 구분코드, 상세일련번호 순서로 적습니다. 07 은 부표3 이 있는 자산에만 생깁니다.

쓰지 않는 레코드는 아래와 같습니다. 검증기는 이 레코드가 파일에 있으면 실패로 봅니다.

| 레코드 | 쓰지 않는 까닭 |
|---|---|
| 06 | 주식 양도분이다. 이 스킬은 주식을 다루지 않는다 |
| 08~13 (매매계약서) | 규격서가 「계약서 사본을 세무서로 제출하는 경우에는 기재를 생략할 수 있습니다」라고 적었다(p62~63). 계약서 사본은 `부속서류.md` 에 올릴 서류로 적는다 |
| 15 (1세대1주택 특례적용신고서) | 일시적 2주택은 05 레코드의 과세구분, 비과세 양도차익, 보유·거주기간 코드로 나타낸다(p53). 15 는 소득세법 시행령 제155조⑬ 의 농어촌주택 등에만 쓴다 |
| 14, 16~30 | 국내 부동산의 예정·확정 정기신고에 쓰지 않는다 |

## 만들고 검증하는 순서

`efile.write` 가 아래 순서로 만들고 검증합니다. 검증을 통과하지 못한 파일은 출력 폴더에 남기지 않습니다.

1. 규격판 잠금을 확인합니다. 잠겨 있으면 만들지 않습니다(아래 「규격판 잠금」).
2. 출력 폴더에서 같은 이름의 옛 파일과 앞선 실행이 남긴 임시 폴더(`.efile-*`)를 지웁니다.
3. 레코드를 조립합니다. 칸 길이를 넘는 값, 완성형에 없는 글자, 비어 있는 필수 칸, 규격서에 없는 코드가 있으면 파일을 만들지 않고 오류 문장을 검증 결과에 적습니다.
4. 출력 폴더 아래 임시 폴더에 최종 파일명으로 씁니다. 검증기가 파일명도 보기 때문에 임시 파일도 같은 이름을 씁니다.
5. 검증기를 별도 프로세스로 돌립니다.
6. 검증기가 종료코드 0 으로 끝나면 파일을 출력 폴더로 옮기고, 실패하면 파일을 남기지 않습니다. 임시 폴더는 지웁니다. 지우지 못하면 `신고_확인.md` 에 알립니다.

검증기(`yangdo/efile_check.py`)는 생성기, 신고값 생성기, 엔진 계산을 부르지 않습니다. 생성기와 같은 코드를 쓰면 같이 틀리기 때문입니다. 파일 바이트를 처음부터 다시 읽고, 레코드 길이와 서식코드 표를 따로 갖고 있어 레이아웃 파일이 그 표와 다르면 검사 전에 실패합니다.

| 검증기가 보는 것 | 내용 |
|---|---|
| 파일 | 파일명 꼴과 작성일자, 줄 끝, 레코드 길이, 레코드 순서, 01~05 가 있는지, 01·02 가 한 줄인지 |
| 칸 | 문자·수치 형식, 고정값, 코드 목록, 필수 칸, 완성형 글자 |
| 레코드 사이 | 03 합계 행이 세율구분 행의 합인지, 양수인 지분, 05 와 07 의 일련번호 연결, 07 정렬 순서, 법정동코드가 법정동코드표에 있는지 |
| 신고값 대사 | `--신고값` 을 주면 01·02·04 의 신고 구분·인적사항 칸과 03·05·07 의 모든 칸(자료구분, 서식코드, 공란 제외)을 신고값과 대조한다. 05 의 날짜, 면적, 법정동코드, 지번, 등기목적·등기원인, 자산종류·과세구분·세율구분과 07 의 구분코드, 상호, 사업자등록번호, 지급일자, 증빙종류, 지급금액이 여기에 든다. 금액이 아닌 칸이 다르면 문장에 값은 싣지 않고 칸 이름과 신고값 경로만 싣는다 |

주민등록번호의 검증번호가 옛 규칙과 다르면 실패로 보지 않고 경고로 알립니다. 2020년 10월 이후 발급되거나 변경된 번호는 옛 규칙과 맞지 않을 수 있습니다.

만든 파일을 따로 검증하려면 스킬 폴더에서 아래 명령을 씁니다. 통과하면 `검증 통과 (n줄)` 을 내고 종료코드 0 으로 끝납니다. 실패하면 실패 문장을 한 줄씩 내고 종료코드 1 로 끝납니다.

```bash
python -m yangdo.efile_check <파일> --신고값 <신고값.json>
```

검증 문장과 경고에는 칸 이름, 코드, 금액, 날짜만 나옵니다. 성명, 주민등록번호, 주소, 전화는 나오지 않습니다.

## 규격판 잠금

`efile/규격판.json` 에 이 스킬이 따르는 규격서의 판과 sha256 을 적어 둡니다.

| 키 | 값 |
|---|---|
| `판` | V5.17 |
| `게시` | 2026-04-28 |
| `sha256` | `77992bde9f6cea4b4c7fe4b38a9bc00a8d25126865eadfa5723455e76032db40`(규격서 원본 파일) |
| `잠금` | false |
| `확인일` | 2026-10-11 |

`잠금` 이 false 가 아니거나, 규격판의 판과 sha256 이 레이아웃 파일의 규격과 다르거나, 파일을 읽을 수 없으면 전자신고 파일을 만들지 않습니다. `make_return.py` 는 종료코드 3 으로 끝나고 신고서 PDF 와 입력 안내서까지만 남습니다. 잠금은 새 규격서가 나왔는데 옛 레이아웃으로 파일을 만드는 일을 막으려고 둡니다.

잠금은 운영자가 `규격판.json` 을 고쳐서 겁니다. 자동으로 거는 절차는 없습니다. 이 파일의 해시가 기준정보 판 id 에 들어가므로 고친 뒤에는 `python scripts/build_ruleset.py 판` 을 함께 돌립니다. 돌리지 않으면 계산 단계부터 종료코드 3 으로 멈춥니다.

규격서 원본과 추출본은 저장소에 넣지 않습니다. 저장소에는 규격서에서 뽑은 레이아웃과 코드표만 있습니다.

### 규격서에 코드가 없어 따로 받는 값

| 값 | 처리 |
|---|---|
| 경매로 취득하거나 양도한 자산의 등기원인 | 엔진이 임의경매와 강제경매를 나누지 않는다. 신고인 JSON `자산[id].등기원인` 에 4자리 코드로 받는다. 없으면 질문 F04 가 후보 코드와 함께 묻는다 |
| 분양, 공공매입으로 취득한 자산의 등기목적과 등기원인 | 기본값 `A1ZZCZ`, `0055` 를 쓰고 확인사항을 붙인다. 등기사항증명서와 다르면 신고인 JSON `자산[id].등기목적`(6자리), `자산[id].등기원인`(4자리)으로 고쳐 쓴다 |
| 타인이 아닌 양수인의 관계코드 | 사실관계의 매수인관계(배우자, 직계, 친족, 법인, 기타 특수관계)마다 규격서 코드가 여럿이다. 신고인 JSON `양수인[].관계코드` 로 받는다. 없으면 질문 F02 |
| 법정동코드 | 주소의 시도, 시군구, 읍면동으로 `efile/법정동코드.json` 에서 찾는다. 찾지 못하거나 후보가 여럿이면 질문 F01(신고인), F04(자산)로 10자리 코드를 받는다 |
| 필수 구분코드 지출의 사업자등록번호 | 사실관계 필요경비 항목의 `사업자번호`. 없으면 질문 F07 |
| 매입가액 행(`11101`)의 상호 | 신고인 JSON `자산[id].취득상대방`. 없으면 질문 F08 |

간이영수증만 있거나 증빙이 없는 지출은 엔진이 필요경비에서 빼므로 07 레코드에 오지 않습니다.

### 합산 비교세액이 클 때

합산 비교세액이 같은 세율 자산 합산 세액보다 크면 본지 서식과 03 레코드의 처리가 다릅니다.

| | 본지 서식 | 03 레코드 |
|---|---|---|
| 세율구분 열(행)의 산출세액 | 엔진의 세율별 산출세액 그대로 | 합계 산출세액을 과세표준 비율로 나눈 금액. 원 미만은 버리고 남는 원은 과세표준이 가장 큰 행에 더한다 |
| 합계의 산출세액 | 합산 비교세액. 세율구분 열의 합과 다르다 | 합산 비교세액. 세율구분 행의 합과 같다 |
| 세율 | 세율구분 열은 적용 세율, 합계 열은 비운다 | 세율구분 행은 적용 세율, 합계 행은 0 |

03 레코드는 합계 행이 세율구분 행의 합과 같아야 해서 나눠 적습니다(규격서 p37 10번, p40). 이 경우 확인사항에 문장이 나옵니다.

### 지방소득세 칸

지방소득세는 위택스에서 따로 신고합니다. 03 레코드의 주민세 금액 칸(03-30, 03-32, 03-33)은 0 으로 둡니다. 2020-01-01 이후 국세 파일의 지방소득세 란은 0 으로 적습니다. 03-31 주민세_세율만 합계 행에 `01000`(10.00%)을 적고 나머지 행은 0 을 적습니다(규격서 p43).

## 홈택스에서 확인하는 순서

사용자가 자기 정보로 `신고인_양식.json` 을 채워 `make_return.py` 를 직접 돌린 파일로 확인합니다. 에이전트는 홈택스에 로그인하지 않고 주민등록번호를 다루지 않습니다.

1. `신고_확인.md` 가 종료코드 0 인지, 서식 검산과 전자신고 검증이 통과인지 봅니다.
2. 신고서 PDF 두 벌과 `신고값.json` 을 계약서, 증빙과 대조합니다.
3. 홈택스에 로그인해 양도소득세 변환파일을 올리는 메뉴로 갑니다. 메뉴 이름과 경로는 확인하지 못했습니다(확인 필요).
4. 전자신고 파일을 올리고 형식검증을 돌립니다. 오류가 나오면 제출하지 않고 오류 문장을 그대로 운영자에게 알립니다.
5. 형식검증이 통과하면 내용검증을 돌립니다. 오류가 나오면 같은 방법으로 알립니다.
6. 둘 다 통과하면 사람이 제출하고 접수증을 보관합니다.
7. `부속서류.md` 의 서류를 홈택스 「신고 부속·증빙서류 제출」로 올립니다.
8. 위택스에서 지방소득세(양도소득분)를 따로 신고합니다. 값은 `지방소득세_신고서.pdf` 에 있습니다.

형식검증이 통과하지 않으면 `홈택스_입력안내.md` 순서로 화면에 직접 입력합니다. 화면 경로는 「세금신고 > 양도소득세 신고 > 양도소득세 신고하기 > 정기신고(일반)」이고, 2025-11-27 국세청 홈택스 신고 대본의 화면 순서를 따랐습니다. 확인하지 못한 화면 이름에는 안내서가 「(화면 이름 확인 필요)」를 붙입니다. 홈택스가 자동으로 채우거나 계산한 값이 안내서의 값과 다르면 제출하지 않습니다.

## 규격서 새 판이 나왔을 때 할 일

1. `efile/규격판.json` 의 `잠금` 을 true 로 바꾸고 `python scripts/build_ruleset.py 판` 을 돌립니다. 이때부터 전자신고 파일을 만들지 않습니다.
2. 새 규격서의 변경내역을 읽고 레코드 01, 02, 03, 04, 05, 07 과 별첨 코드표에서 바뀐 곳을 찾습니다.
3. 규격서 원본에서 추출본 두 가지를 만듭니다. 표마다 셀을 이은 글(`_표.txt`)과 쪽마다 뽑은 글(`_쪽별.txt`)입니다. 추출본을 만드는 스크립트는 저장소에 없습니다(확인 필요).
4. `규격판.json` 의 판, 게시일, 원본 이름, sha256 을 새 판으로 고칩니다.
5. `python scripts/refresh/extract_layout.py --표 <표.txt> --쪽 <쪽별.txt>` 로 `efile/layout_c116300.json` 을 다시 만듭니다. 칸 길이 합이 규격서의 길이 표와 다르면 종료코드 1 로 끝나고 파일을 쓰지 않습니다. 고쳐 읽어야 하는 곳은 스크립트의 `FIXUPS` 에 근거와 함께 적습니다.
6. `efile/codes_c116300.json` 을 새 판의 코드 설명과 별첨 표에 맞춥니다. 이 파일을 만드는 스크립트는 저장소에 없어 손으로 고칩니다.
7. 검증기(`yangdo/efile_check.py`)가 따로 가진 표(레코드 길이, 서식코드, 세율구분 목록, 세무프로그램코드 목록)를 새 판에 맞춥니다.
8. 계산 결과의 코드(`rules/코드표.json`)가 새 판과 같은지 봅니다.
9. `python scripts/build_ruleset.py 판` 으로 기준정보 판을 다시 만들고 시험 전체를 돌립니다.
10. 합성 사례로 파일을 만들어 검증기를 통과하는지 보고, `잠금` 을 false 로 돌린 뒤 판을 다시 만듭니다.
11. 홈택스 형식검증을 다시 돌려 위 「홈택스 형식검증으로 확인할 칸」을 확인합니다.
