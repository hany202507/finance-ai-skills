# 기준정보 초판 절차

운영자가 기준정보(규칙세트, 고시 이력, 코드표, 공휴일 표)를 처음 만들거나 다시 만드는 순서입니다. 사용자 작업에서는 하지 않습니다. 모든 명령은 스킬 폴더에서 실행합니다.

1. 조문을 받습니다.

   ```bash
   python scripts/refresh/fetch_articles.py
   ```

   `rules/감시조문.json` 의 조문을 법제처 DRF 에서 받아 `rules/조문/` 에 정규화 본문으로 저장하고, 현행 판을 TaxDoctor 와 대조합니다. 법제처 OC 가 필요합니다. 환경변수 `LAW_OC` 에서 읽고, 없으면 `claude mcp get korean-law` 에서 읽습니다. OC 값은 화면에 출력하지 않습니다. 법령조회 스킬의 `scripts/coverage_check.py` 를 함께 쓰므로 `skills/법령조회/` 폴더가 이 스킬과 같은 `skills/` 아래에 있어야 합니다.

   끝에 `TaxDoctor 불일치 0건` 이 나와야 합니다. 불일치나 수집 오류가 있으면 종료코드 1 입니다.

   TaxDoctor 대조 결과는 조문마다 `확인기록.json` 의 `TaxDoctor` 목록에 `일치` 값과 함께 남습니다. 수집 오류는 화면에 `오류:` 줄로만 나오고 파일에는 남지 않습니다.

   수집 오류가 하나라도 있으면 `판목록.json` 과 `확인기록.json` 을 덮어쓰지 않고, 그 사실을 한 줄 알립니다. 일부만 담긴 목록으로 옛 색인을 지우지 않기 위해서입니다. 이미 받은 판 파일은 그대로 남으므로 다시 돌리면 이어서 받습니다.

   이미 받은 판 파일은 다시 받지 않고, 시행예정 판은 매번 다시 받습니다. `감시조문.json` 에 조문을 더하면 그 조문이 없는 판 파일도 다시 받습니다. 조문 본문을 정규화하는 코드(`fetch_articles.py`)를 고쳤다면 받아 둔 판 파일은 옛 모양 그대로입니다. 그때는 `rules/조문/` 아래 법령 폴더의 판 파일(`<MST>@<시행일>.json`)을 지우고 다시 받은 뒤 3번으로 규칙세트를 다시 만듭니다. 근거 해시가 바뀌므로 기준정보 판 id 도 바뀝니다. `--오늘 YYYY-MM-DD` 로 확인일을 바꿀 수 있습니다.

2. `rules/추출규칙.json` 에 값과 원문 발췌를 적습니다. 값은 TaxDoctor 와 korean-law 로 사람이 확인한 것만 적습니다. 모양은 `references/규칙세트_스키마.md` 에 있습니다.

3. 규칙세트를 만듭니다.

   ```bash
   python scripts/build_ruleset.py build
   ```

   발췌가 판 본문에 있는지 판마다 대조합니다. 실패하면 아무 파일도 쓰지 않고 종료코드 1 입니다. 발췌 표기만 원문대로 고치고, 값이 원문과 다르면 멈춥니다. 발췌가 어느 판에 있는지는 `python scripts/build_ruleset.py 찾기 --법령 "소득세법 시행령" --조 167의10 --발췌 "2026년 5월 9일까지"` 로 봅니다.

4. 고시를 바꿨으면 고시 이력을 가져온 뒤 판을 다시 만듭니다.

   ```bash
   python scripts/refresh/import_notices.py --입력 <조정대상지역_이력.json>
   python scripts/build_ruleset.py 판
   ```

   `import_notices.py` 는 조사한 이력 파일을 `rules/고시/` 로 옮깁니다. 공고 이벤트는 고치지 않고 그대로 옮기고, 조사 PC 의 로컬 파일 경로(`증거파일`)는 빼서 옮깁니다. `판` 명령은 `ruleset.json` 의 확인일로 `기준정보판.json` 의 해시와 id 를 다시 씁니다. 코드표, 행정구역 대응표, 공휴일 표를 고쳤을 때도 이 명령을 씁니다. 서식 매핑(`forms/매핑/`), 필드목록(`forms/필드목록/`), 서식 원본 판(`forms/서식판.json`), 전자신고 규격서 판과 레이아웃(`efile/`)을 고쳤을 때도 같습니다. 이 파일들의 해시가 기준정보 판 id 에 들어갑니다.

5. 공휴일 표(`rules/공휴일.json`)를 채웁니다. 해마다 한 번, 그리고 임시공휴일이나 선거일이 새로 정해졌을 때 합니다. 모양은 `references/규칙세트_스키마.md` 의 「공휴일.json」에 있습니다.

   1. 다음 해 월력요항을 받습니다. 우주항공청이 해마다 6월 무렵 관보와 누리집(kasa.go.kr 의 보도자료, 공고)에 다음 해 월력요항을 싣습니다. 2025년분은 2024-06-20, 2026년분은 2025-06-30, 2027년분은 2026-06-29 에 나왔습니다.
   2. 월력요항의 「공휴일」 표에서 「관공서의 공휴일」 줄을 봅니다. `고정` 에 있는 날(1월 1일, 3·1절, 노동절, 어린이날, 현충일, 제헌절, 광복절, 개천절, 한글날, 기독탄신일)을 뺀 나머지를 `연도` 에 날짜로 옮깁니다. 설날·추석 연휴는 사흘을 하루씩 적고, 대체공휴일과 선거일도 적습니다. 지방공휴일 줄은 옮기지 않습니다.
   3. 옮긴 날짜의 요일이 월력요항에 적힌 요일과 같은지 봅니다. 다르면 넣지 않습니다.
   4. 그 해 `출처` 에 자료 이름과 URL 을, `확인일` 에 확인한 날을 적습니다.
   5. 임시공휴일은 국무회의 심의를 거쳐 인사혁신처가 공고합니다(인사혁신처 누리집의 공고, 정책브리핑 korea.kr 의 보도자료). 지정된 날을 해당 해 `날짜` 에 더하고 출처를 적습니다. 월력요항이 나온 뒤에 지정되므로 월력요항에는 없습니다. 임기만료 선거가 아닌 선거(궐위에 따른 대통령선거 등)의 선거일도 임시공휴일로 공고된 것만 넣습니다.
   6. 공휴일 목록 자체가 바뀌었는지 「공휴일에 관한 법률」과 「관공서의 공휴일에 관한 규정」의 연혁으로 봅니다. 날짜가 고정된 공휴일이 생기거나 없어졌으면 `고정` 에 `시작`, `끝` 과 함께 적고 `법령확인` 을 고칩니다. 2026년에는 노동절(2026-05-01)과 제헌절(2026-05-11)이 공휴일이 됐습니다.
   7. `python scripts/build_ruleset.py 판` 으로 판을 다시 만듭니다.

   발표로 확인하지 못한 해는 넣지 않고, 음력 환산이나 대체공휴일 규칙으로 날짜를 만들지도 않습니다. 출처끼리 날짜가 다르면 원문을 다시 확인한 뒤 넣습니다. 2026-10-11 현재 2025년, 2026년, 2027년이 들어 있고, 2028년 월력요항은 아직 나오지 않아 넣지 않았습니다. 2028년에 끝나는 신고기한(2027년 11월 이후 양도의 예정신고, 2027년 양도의 확정신고)은 토·일과 고정 공휴일만 옮깁니다. 2027년 6월 무렵 2028년 월력요항이 나오면 채웁니다.

6. 시험을 돌립니다.

   ```bash
   python -m pytest -q tests
   ```

7. 공개 저장소에 반영하기 전에 `rules/` 에 OC 값, 로컬 경로, 이메일이 없는지 확인합니다. 결과가 없어야 합니다.

   ```bash
   grep -rEn 'OC=|C:(\\\\|\\|/)+Users|[A-Za-z][A-Za-z0-9._%+-]*@[A-Za-z0-9-]+\.[A-Za-z]{2,}' rules
   ```

   판 id 는 `267581@2025-01-01` 꼴이라 `@` 만으로 찾으면 판 목록이 전부 걸립니다. 위 식은 글자로 시작하는 이메일 주소만 찾습니다.

기준정보 확인일은 `fetch_articles.py` 를 돌린 날입니다. 매일 자동 갱신과 운영자 확인 절차는 계획 4 에서 만들고(`references/적용한계.md`), 그 전에는 운영자가 주 1회 1번과 3번을 다시 돌립니다. 공휴일 표(5번)는 조문 갱신과 따로 해마다 채웁니다. 7일이 지나면 모든 계산 결과에 기준정보를 갱신하라는 경고가 붙습니다.
