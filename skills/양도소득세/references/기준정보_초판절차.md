# 기준정보 초판 절차

운영자가 기준정보(규칙세트, 고시 이력, 코드표)를 처음 만들거나 다시 만드는 순서입니다. 사용자 작업에서는 하지 않습니다. 모든 명령은 스킬 폴더에서 실행합니다.

1. 조문을 받습니다.

   ```bash
   python scripts/refresh/fetch_articles.py
   ```

   `rules/감시조문.json` 의 조문을 법제처 DRF 에서 받아 `rules/조문/` 에 정규화 본문으로 저장하고, 현행 판을 TaxDoctor 와 대조합니다. 법제처 OC 가 필요합니다. 환경변수 `LAW_OC` 에서 읽고, 없으면 `claude mcp get korean-law` 에서 읽습니다. OC 값은 화면에 출력하지 않습니다. 법령조회 스킬의 `scripts/coverage_check.py` 를 함께 쓰므로 `skills/법령조회/` 가 옆에 있어야 합니다.

   끝에 `TaxDoctor 불일치 0건` 이 나와야 합니다. 불일치나 수집 오류가 있으면 종료코드 1 입니다. TaxDoctor 대조 결과는 조문마다 `확인기록.json` 의 `TaxDoctor` 목록에 `일치` 값과 함께 남고, 수집 오류는 화면에 `오류:` 줄로만 나오고 파일에는 남지 않습니다. 이미 받은 판 파일은 다시 받지 않고, 시행예정 판은 매번 다시 받습니다. `--오늘 YYYY-MM-DD` 로 확인일을 바꿀 수 있습니다.

2. `rules/추출규칙.json` 에 값과 원문 발췌를 적습니다. 값은 TaxDoctor 와 korean-law 로 사람이 확인한 것만 적습니다. 모양은 `references/규칙세트_스키마.md` 에 있습니다.

3. 규칙세트를 만듭니다.

   ```bash
   python scripts/build_ruleset.py build
   ```

   발췌가 판 본문에 있는지 판마다 대조합니다. 실패하면 아무 파일도 쓰지 않고 종료코드 1 입니다. 발췌 표기만 원문대로 고치고, 값이 원문과 다르면 멈춥니다. 발췌가 어느 판에 있는지는 `python scripts/build_ruleset.py 찾기 --법령 "소득세법 시행령" --조 167의10 --발췌 "2026년 5월 9일까지"` 로 봅니다.

4. 고시를 바꿨으면 고시 이력을 가져온 뒤 판을 다시 만듭니다.

   ```bash
   python scripts/refresh/import_notices.py --입력 <조정대상지역_이력.json>
   python scripts/build_ruleset.py 판
   ```

   `import_notices.py` 는 조사한 이력 파일을 `rules/고시/` 로 옮깁니다. 공고 이벤트는 고치지 않고 그대로 옮기고, 조사 PC 의 로컬 파일 경로(`증거파일`)는 빼서 옮깁니다. `판` 명령은 `ruleset.json` 의 확인일로 `기준정보판.json` 의 해시와 id 를 다시 씁니다. 코드표나 행정구역 대응표를 고쳤을 때도 이 명령을 씁니다.

5. 시험을 돌립니다.

   ```bash
   python -m pytest -q tests
   ```

6. 공개 저장소에 반영하기 전에 `rules/` 에 OC 값, 로컬 경로, 이메일이 없는지 확인합니다. 결과가 없어야 합니다.

   ```bash
   grep -rEn 'OC=|C:(\\\\|\\|/)+Users|[A-Za-z][A-Za-z0-9._%+-]*@[A-Za-z0-9-]+\.[A-Za-z]{2,}' rules
   ```

   판 id 는 `267581@2025-01-01` 꼴이라 `@` 만으로 찾으면 판 목록이 전부 걸립니다. 위 식은 글자로 시작하는 이메일 주소만 찾습니다.

기준정보 확인일은 `fetch_articles.py` 를 돌린 날입니다. 매일 자동 갱신과 운영자 확인 절차는 계획 4 에서 만들고(`references/적용한계.md`), 그 전에는 운영자가 주 1회 1번과 3번을 다시 돌립니다. 7일이 지나면 모든 계산 결과에 기준정보를 갱신하라는 경고가 붙습니다.
