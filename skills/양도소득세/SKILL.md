# 양도소득세

주택·토지·건물 양도건의 세액을 근거 조문과 함께 계산합니다. 매매와 경매(매각대금 완납일이 양도일)로 양도한 건이 대상입니다. 수용, 교환, 부담부증여, 기타 원인으로 양도한 건은 다루지 않습니다(계획 5, `references/적용한계.md`). 조세특례제한법 감면은 계산하지 않습니다.

사용자에게는 계약일, 잔금일, 등기접수일, 읍면동 주소, 세대가 가진 주택 목록 같은 원자료만 묻고, 조정대상지역 여부·보유햇수·세율은 묻지 않습니다. 판정과 계산은 엔진이 하고, 세율·공제율·기준금액·처분기한은 `rules/` 의 규칙세트에서 읽습니다. 코드에 남은 고정값은 `references/규칙세트_스키마.md` 에 적혀 있습니다. 값은 2025-01-01 양도분부터 있습니다.

결과는 검토용 초안입니다. 신고 전 최종 판단은 세무 전문가가 합니다.

## 시험해 보기

스킬의 `tests/cases.py` 에 있는 합성 사례 A(서울 아파트 1세대1주택, 고가주택)로 한 번 돌려 봅니다. 스킬 폴더에서:

```bash
pip install -r requirements.txt
python -c "import sys,json; sys.path.insert(0,'tests'); from cases import CASES; json.dump(CASES['A'], open('a.json','w',encoding='utf-8'), ensure_ascii=False, indent=1)"
python scripts/run.py --사실관계 a.json --출력 out
```

`산출세액 2,565,000원, 지방소득세 256,500원, 검산 통과` 가 나오고 `out/` 에 결과 파일 세 개가 생깁니다. 테스트는 `python -m pytest -q tests`.

## 0. 기준정보

기준정보(규칙세트, 고시 이력, 코드표)는 `rules/` 에 있고 운영자가 만듭니다. 사용자 작업에서는 고치지 않습니다.

계산 결과의 `기준정보` 에 판 id 와 확인일이 나옵니다. 확인일이 7일 넘게 지났으면 검토 문서 맨 위와 경고에 그 사실이 나옵니다. 그대로 보고합니다.

## 1. 사실 모으기

로컬 MCP `yangdo` 가 등록돼 있으면 그것을 씁니다. 등록은 한 번만 합니다.

```bash
claude mcp add yangdo -- python <스킬 경로>/scripts/mcp_server.py
```

| 도구 | 하는 일 |
|---|---|
| `yangdo_next_questions` | 사실관계에 비어 있는 것 중 다음에 물을 문항을 돌려준다. 인자는 `facts_path`(파일 경로)나 `facts`(JSON 객체) 중 하나, `limit`(한 번에 받을 문항 수, 기본 1). `서식` 인자는 서식 단계 문항용(`references/적용한계.md` 의 계획 2)이라 지금은 쓰지 않는다 |
| `yangdo_answer` | 문항 답을 사실관계에 넣는다. 인자는 `facts_path` 나 `facts`, `문항`, `값`, 자산이나 주택마다 묻는 문항이면 `자산`, `주택`. 값에 문자열 「모름」을 주면 모름으로 기록한다. `facts_path` 를 주면 그 파일을 고쳐 쓰고, `facts` 를 주면 고친 사실관계를 `사실관계` 로 돌려준다 |
| `yangdo_calculate` | 판정, 세액, 근거, 파일설명서 코드를 낸다. 인자는 `facts_path` 나 `facts`, `오늘`(YYYY-MM-DD, 비우면 한국 시간 오늘), `out_dir`. `out_dir` 를 주면 그 폴더의 이전 결과 파일을 지우고 검토 문서, 워크북, 결과 JSON 을 쓴다 |
| `regulated_area` | 기준일에 조정대상지역·투기과열지구·투기지역인지 공고 이력으로 판정한다. 필수 인자 `시도`, `시군구`, `기준일`, 선택 인자 `읍면동`, `지구해당` |
| `ruleset_info` | 기준정보 판 id, 확인일, 시행예정 개정, 계류 개정 |

`facts` 와 `facts_path` 는 하나만 줍니다. 둘 다 주거나 둘 다 빼면 오류입니다. `yangdo_answer` 에 `facts_path` 를 주려면 그 파일이 먼저 있어야 합니다.

새 사건은 `{"자산": [{"id": "A"}]}` 로 시작합니다. 양도한 자산마다 id 를 하나씩 정해 넣습니다. `{}` 로 시작하면 자산과 상관없는 문항(P01, P05)만 묻습니다. 문항이 자산을 만들지 않으므로 계산하면 「양도한 자산이 하나도 없습니다」(P02) 질문이 나옵니다. `facts` 로 쓸 때는 돌려받은 `사실관계` 를 다음 호출에 그대로 넘깁니다.

`yangdo_next_questions` 로 문항을 받아 사용자에게 묻고 `yangdo_answer` 로 넣습니다. `다음` 이 빌 때까지 되풀이한 뒤 `yangdo_calculate` 를 부릅니다.

MCP 가 없으면 같은 일을 스크립트로 합니다. `{skill}` 은 스킬 폴더 경로로 바꿔 읽습니다. 새 사건은 위와 같이 `{"자산": [{"id": "A"}]}` 를 담은 파일을 먼저 만듭니다.

```bash
# 다음 문항
python -c "import sys,json; sys.path.insert(0, r'{skill}'); from yangdo import questions as Q; r=Q.next_questions(json.load(open(r'<facts.json>', encoding='utf-8'))); print(json.dumps({k: r[k] for k in ('다음', '남은')}, ensure_ascii=False, indent=1))"

# 답 넣기(자산이나 주택마다 묻는 문항은 자산=, 주택= 를 함께 준다)
python -c "import sys,json; sys.path.insert(0, r'{skill}'); from yangdo import questions as Q; p=r'<facts.json>'; f=Q.answer(json.load(open(p, encoding='utf-8')), '<문항id>', <값>, 자산='<자산id>'); json.dump(f, open(p, 'w', encoding='utf-8'), ensure_ascii=False, indent=1)"
```

문항을 물을 때 지킬 것:

- 문항마다 `질문` 을 그대로 읽어 줍니다. `도움말`, `증빙서류`, `안내` 가 있으면 함께 전합니다.
- 모르겠다고 하면 `모를때확인처` 를 알려 줍니다. 끝내 모르면 값에 「모름」을 넣습니다. 엔진이 추정하지 않고 확인사항이나 질문으로 돌려줍니다.
- 답 형식은 `답형식` 을 따릅니다. 날짜는 `YYYY-MM-DD`, 금액은 원 단위 정수, 예/아니오는 `true`/`false` 로 답합니다. 선택은 `선택지` 의 코드값 하나, 복수선택은 코드값의 목록(하나만 골라도 목록)입니다. 키가 여럿인 문항은 `{"마지막 키 이름": 값}` 으로 답합니다.
- 사실관계 JSON 에 성명, 주민등록번호, 주소 문자열, 전화번호, 계좌를 넣지 않습니다. 넣으면 엔진이 거부합니다. 소재지는 `{"시도": ..., "시군구": ..., "읍면동": ...}` 로 나눠 적습니다. 서식에 필요한 인적사항은 계획 2 에서 `신고인.json` 으로 따로 받습니다(계획 번호 설명은 `references/적용한계.md` 에 있습니다).
- 양도 원인(P03)이 수용, 교환, 부담부증여, 기타면 나머지 문항을 묻지 말고 바로 알립니다. 취득 원인(A15)이 상속, 증여, 부담부증여, 조합원, 기타일 때도 같습니다. `yangdo_next_questions` 는 이때도 문항을 돌려주지만 따르지 말고, 계산해서 나오는 다루지않음 결과를 알립니다.
- 양도 원인이 경매면 잔금일 문항(A11)에 매수인이 매각대금을 다 낸 날을 받습니다. 사실관계에 `양도.대금완납일` 로 넣어도 되고, 둘 다 있으면 대금완납일을 씁니다.
- 고객이 직접 채우는 HTML 양식은 아직 없습니다(계획 2). 만들어도 문항 정의는 `질문지/문항.json` 하나를 같이 씁니다.

엔진은 사실관계 입력도 검사합니다. 인적사항이나 주소 문자열이 있으면 오류 문장을 내고 멈춥니다. 정수가 아닌 금액, 음수 금액, 형식이 틀린 날짜와 거주기간, 양도일보다 늦은 취득일은 해당 문항을 질문으로 돌려줍니다. 날짜는 `YYYY-MM-DD` 글자만 받으므로 `20261115` 처럼 붙여 쓴 날짜도 형식이 틀린 날짜입니다. 자산 `id` 는 글자 그대로 세대 주택목록의 `자산id` 와 같아야 하고 겹치면 안 됩니다.

자료형도 문항 정의의 `답형식` 대로 검사합니다. 예/아니오 문항에 `"false"` 같은 글자를 넣거나 복수선택 문항에 목록 대신 글자를 넣으면, 그 값을 참이나 거짓으로 읽지 않고 해당 문항을 질문으로 돌려줍니다. 글자 하나를 목록으로 읽어 중과배제 사유가 생기는 일을 막는 검사입니다.

엔진이 반영하지 못하는 사실이 사실관계에 있으면 낮은 세액을 내지 않고 다루지않음으로 돌려줍니다. 같은 날 주택 여러 채 양도, 다가구 호실별 양도, 매수인이 부담한 양도소득세, 특수관계인에게 시가보다 낮게 양도 등이 해당하고, 전체 목록은 `references/적용한계.md` 에 있습니다.

## 2. 계산

```bash
python "{skill}/scripts/run.py" --사실관계 <facts.json> --출력 <폴더>
```

선택 인자는 `--오늘 YYYY-MM-DD`(기준정보가 7일 넘게 지났는지 가리는 데 쓰는 날짜), `--rules <폴더>`(다른 기준정보 폴더)입니다. 같은 출력 폴더에 다시 실행하면 이 스크립트가 쓰는 파일 네 개만 지우고 시작합니다.

| 종료코드 | 뜻 | 다음 |
|---|---|---|
| 0 | 완료 | `양도소득세_검토.md` 의 판정, 근거, 확인사항, 경고를 요약해 보고하고 워크북 경로를 알린다 |
| 1 | 검산 실패 | 검토 문서의 「검산」 절에 실패 줄이 나온다. 그대로 보고하고 이 결과를 신고에 쓰지 말라고 알린다 |
| 2 | 질문 또는 다루지않음 | `질문.md` 의 문항을 사용자에게 묻는다. 다루지않음이면 그 사실과 해당 계획을 알린다. `질문.md` 가 없고 화면에 오류 문장만 나왔으면 사실관계 파일 자체의 문제다(인적사항, 주소 문자열, 자산 id, 읽을 수 없는 파일, 맞지 않는 값 형식). 그 문장을 보고하고 파일을 고치게 한다 |
| 3 | 기준정보 오류 | 규칙세트, 코드표, 고시 파일이 기준정보 판과 다르거나 없다. 계산하지 않고 운영자에게 알린다 |
| 4 | 출력 파일 쓰기 실패 | 이전 워크북을 엑셀이 열어 둔 경우가 많다. 파일을 닫고 같은 명령을 다시 실행하라고 알린다 |

출력 폴더에 쓰는 파일은 다음과 같습니다.

| 파일 | 언제 | 내용 |
|---|---|---|
| `result.json` | 종료코드 0, 1, 2 | 상태, 기준정보, 질문, 다루지않음, 확인사항, 경고, 자산별 판정과 계산, 합계, 검산. 종료코드 2 라도 화면에 오류 문장만 나온 경우는 파일이 없다 |
| `질문.md` | 종료코드 2(질문 또는 다루지않음) | 묻는 문항과 모를 때 확인하는 곳, 다루지않는 항목 |
| `양도소득세_검토.md` | 종료코드 0, 1 | 자산별 판정표와 계산표, 근거 조문, 합계, 확인사항, 경고, 검산 |
| `양도소득세_계산근거.xlsx` | 종료코드 0, 1 | 수식이 들어 있는 계산근거. 수식을 다시 계산해 엔진 값과 대조한다 |

## 3. 보고할 때

- 결론 옆에 근거 조문과 시행일을 붙입니다. 검토 문서의 「근거」 목록에 있습니다.
- 합계는 세액 둘을 모두 보여 줍니다. 같은 세율 자산 합산 세액과 합산 비교 세액 중 큰 값이 산출세액입니다(소득세법 제104조⑤). 자산이 하나면 합산 비교 세액은 0 으로 나옵니다. 지방소득세도 같은 방식입니다. `yangdo_calculate` 결과의 `참고` 문장은 자산별 합과 산출세액이 다른 이유를 적은 것이니 함께 전합니다.
- 확인사항을 전부 보고합니다. 조정대상지역 판정에 쓴 공고, 일시적 2주택 부칙, 한시배제, 추계 순서, 합산 비교는 특히 빠뜨리지 않습니다. 중과의 다른 주택 배제 사유(10호), 해외 출국 예외의 출국일 현재 1주택, 특수관계인 거래의 시가 비교도 같습니다. 「이 답은 이번 계산에 반영하지 않았다」 로 시작하는 확인사항(세대원 목록, 따로 산 세대원, 취득 상대방, 1990년 이전 취득 토지의 토지등급)은 사용자가 답한 사실을 계산에 쓰지 않았다는 뜻이므로 그대로 전합니다.
- 경고를 전부 보고합니다. 계류 중인 개정(2026 세제개편안 중과 완화)과 시행예정 개정이 여기에 나옵니다.
- 「이 결과는 검토용입니다. 신고 전 최종 판단은 세무 전문가가 합니다」를 붙입니다.
- `references/적용한계.md` 에 걸리는 건이면 그 사실을 알립니다.

## 4. 법령을 더 찾아야 할 때

이 스킬의 규칙세트 값은 바꾸지 않습니다. 값이 틀렸다고 보이면 운영자에게 알립니다(`references/기준정보_초판절차.md`).
