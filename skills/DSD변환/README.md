# DSD변환

DART 에 공시된 감사보고서 · 연결감사보고서를 DART 편집기 파일(dsd)로 바꿉니다. 회사가 dsd 를 주지 않았거나 초도 감사라 전기 dsd 가 없을 때, 작년 공시로 올해 dsd 를 시작할 때 씁니다.

- **원문 그대로.** 문단 · 표 · 칸 · 숫자 · 서식 표시는 공시 원문 그대로 두고, 공시 때 빠진 편집기 요소(삽입 위치 13곳 · 목차 · 안내문 · 문서 머리 · meta.xml)만 되살립니다. 공시 원문 xml 에서 빠진 문단 · 칸 안 줄바꿈은 같은 보고서의 DART 공시 화면을 함께 받아 화면대로 넣습니다.
- **다음 기수 초안.** 요청하면 당기 숫자를 전기 칸으로 옮기고 기수 · 해를 하나씩 올린 초안과 원고 엑셀을 만듭니다. 유형자산 같은 변동표는 새 당기 기초를 작년 기말로 채웁니다.
- **입력.** 접수번호(14자리), DART 에서 받은 PDF, 공시서류원본 xml 가운데 하나. 접수번호 · PDF 는 OpenDART 인증키(환경변수 `DART_API_KEY`)가 있어야 받습니다.

## 쓰는 법(Claude 에게 이렇게 말합니다)

1. 「<접수번호> dsd 로 바꿔 줘」 또는 「<PDF · xml 경로> dsd 로 바꿔 줘」.
2. 「다음 기수 초안까지 만들어 줘」. 원고 엑셀에서 고친 뒤 「이 원고로 dsd 다시 만들어 줘」.
3. 만든 dsd 는 DART 편집기로 열어 본 뒤에 씁니다. 숫자 검증은 [DSD푸팅](../DSD푸팅/) 스킬로 합니다.

## 검증

- 같은 보고서의 공시 원문과 편집기 저장 dsd 짝 두 건에서, 변환 결과의 삽입 위치 · 안내문 · 목차의 차례와 앞뒤 요소가 편집기 파일과 같았습니다.
- 2026년 3월 공시된 감사보고서 13건 · 연결감사보고서 8건을 바꿔 원문과 판 비교를 하니 추가 · 삭제 · 변경이 모두 0건이었습니다. dart4 꼴 공개 원문 49건 모두 본문이 원문과 같았습니다.
- DART 편집기 5.1 에서 감사보고서 · 연결감사보고서 두 건 · 다음 기수 초안을 열어 목차 · 재무제표 · 주석이 보이고 파일형식 검사의 구조 검사를 넘는 것을 확인했습니다(2026-11-06).
- 2026-11-09 공개 원문 다섯 건(2026년 3월 공시 감사보고서 둘 · 연결감사보고서 하나, FY2024 공시 둘)을 변환 · 다음 기수 초안 · 원고 다시 만들기까지 돌려 모두 본문이 원문과 같고 DART 편집기 규격(Dart4.xsd) 검사를 통과했습니다. FY2024 공시로 만든 2025 초안을 실제 2025 공시와 칸마다 견주니 재무상태표 · 손익계산서 · 현금흐름표의 옮긴 숫자가 모두 같았습니다. 이 대조는 엔진 코드를 쓰지 않았습니다.

## 한계

- 공시 원문에는 편집기의 재무제표 검사 기록이 없습니다. 편집기에서 재무제표마다 [재무제표 > 재무제표 검사] 를 돌린 뒤 파일형식 검사를 하십시오. 회사가 만든 계정은 재무제표 검사에서 「표준과 다릅니다」 로 나오니 편집기에서 표준 계정과 짝지어 주십시오.
- `--bare` 판은 편집기가 열지 않습니다. 견주어 볼 때만 쓰십시오.
- 연결 감사보고서 틀은 편집기 샘플이 없어 별도 감사보고서 틀의 서식 코드와 이름을 연결로 바꾼 추정입니다. 감사인의 감사보고서 절의 라이브러리 파일 이름(FILENAME)도 추정입니다.
- 요약 코드(자산총계 · 감사의견 구분 등)는 원문 값 그대로입니다. 편집기 「문서 헤더정보」 에서 고칩니다.
- 다음 기수 초안은 자본변동표, 해마다 줄이 다른 표(날짜별 변동 내역 등), 당기 아래 여러 열 · 전기 한 열처럼 머리가 두 줄인 표를 옮기지 않고 안내 파일에 「옮기지 않았다」 로 적습니다. 감사인의 감사보고서 · 외부감사 실시내용 · 문단 속 날짜는 작년 글로 남습니다(외부감사 실시내용의 감사대상 사업연도 칸은 다음 해로 옮깁니다).
- 공시서류원본에는 그림 파일이 없어, 그림이 든 원문(내부회계관리제도 운영실태보고서 등)은 그림이 빠집니다. 편집기에서 그림을 다시 넣어야 파일형식 검사를 통과합니다.
- 사업 · 반기 · 분기보고서 안의 감사보고서와 2019년 무렵 이전의 옛 dart3 원문은 바꾸지 않습니다.
