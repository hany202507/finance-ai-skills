# 최신화 점검

결론에 쓴 판이 기준일에 맞는지, 공포 전 개정안이 있는지 확인하는 절차다. SKILL.md 「최신화 점검」의 세부다. 세법뿐 아니라 민법·상법 등 모든 법에 같은 방법을 쓴다.

## 따로 하는 까닭

TaxDoctor 원천 스냅샷은 `moleg-eflaw:<MST>@<시행일>` 이다. TaxDoctor 와 korean-law 가 둘 다 법제처 DB 를 읽으므로 두 곳 대조로는 문구가 같은지만 알 수 있다. 기준일에 맞는 판을 골랐는지는 판 목록으로 따로 본다. 국회 계류 법안·입법예고·정부안은 법령 DB 에 없어서 웹으로 찾는다.

## 얼마나 하나

| 단계 | 언제 | 걸리는 시간 |
|---|---|---|
| 1 판 목록 대조 | 늘 | 몇십 초(`amendment_track` 법령마다 한 번, 스크립트 한 번) |
| 2-1 국회 의안 | 기준일이 오늘 뒤이거나 사용자가 개정 소식을 물었을 때 | `bill_search.py` 10초 안팎 |
| 2-2 입법예고·정부안 | 위와 같다 | 서브에이전트 하나, 웹 검색 3번까지(1~2분) |
| 관보 공포 조사 | 공포 소식이 있는데 판 목록에 그 판이 없을 때 | 서브에이전트 하나 |

2026-10-19 에 처음 만든 방식(관보·국회·입법예고 조사 셋을 늘 동시에)은 18~29분 걸렸다. 관보 공포 11건이 모두 판 목록에 있었고, 국회 조사는 결론과 상관없는 의원안 149건까지 훑었다. 그래서 위처럼 줄였다.

같은 날 잰 것: 판 목록 대조 1초 안, `bill_search.py`(소득세법 제89조, 키워드 「1세대 1주택」) 9.3초에 13건. 18분 걸린 수작업 조사가 찾은 제89조 계류 법안 6건이 모두 들어 있었다. 웹 검색만으로 국회 쪽을 찾게 한 서브에이전트(검색 4번)는 1분 46초에 끝났지만 의안을 한 건도 찾지 못했다.

## 1. 판 목록 대조

결론에 쓴 법령과 결론 조문이 인용·위임한 법령마다 korean-law `amendment_track` 을 한 메시지에서 함께 부른다. 쓴 판과 판 목록을 `기준.json` 에 적고 돌린다.

```bash
python scripts/freshness_check.py --기준 기준.json --출력 최신화점검.json
```

종료코드 0 은 조치할 것 없음, 1 은 조치 필요, 2 는 입력 오류다. 같은 이름의 `.md` 요약도 쓴다.

```json
{
 "기준일": "2027-02-15",
 "오늘": "2026-10-19",
 "법령": [
  {
   "법령": "소득세법 시행령",
   "조항": ["제155조 제1항"],
   "판": "283631@20270101",
   "DB판": [
    {"MST": "283631", "공포일": "2026-02-27", "시행일": "2027-01-01"},
    {"MST": "290841", "공포일": "2026-09-30", "시행일": "2026-10-01"}
   ]
  }
 ]
}
```

- `기준일` 은 판정 기준일(양도일, 계약일, 과세기간 끝 등)이다. 사건 날짜가 없으면 오늘이다
- `판` 은 `get_law_text(effective_date=기준일)` 머리줄의 MST·시행일이다
- `DB판` 은 `amendment_track` 결과를 옮긴다. 기준일 이전 시행 판이 하나 이상 나오도록 `display` 를 준다. 목록이 짧으면 「확인 불가」가 난다
- 같은 시행일에 판이 여럿이면 가장 늦게 공포된 판이 그날의 본문이다. 스크립트가 그렇게 고른다

## 2. 개정안 조사

기준일이 오늘 뒤이거나 사용자가 개정 소식을 물었을 때만 한다. 국회는 스크립트로, 입법예고·정부안은 서브에이전트 하나로 본다. 둘을 한 메시지에서 함께 시작한다.

### 2-1 국회 의안

```bash
python scripts/bill_search.py --대상 "소득세법:제89조" --키워드 "1세대 1주택" --출력 국회.json
python scripts/bill_search.py --대상 "상법:제341조,제341조의2" --키워드 "자기주식" --출력 국회.json
```

- 법령마다 의안명으로 22대 국회 의안을 검색하고, 계류 중이거나 가결됐지만 공포 전인 법안의 요약(제안이유·주요내용)을 읽는다
- 요약에 결론 조문이나 `--키워드` 가 나오는 법안만 항목으로 적는다. 의안 요약은 주된 조문만 「안 제N조 등」으로 적어서 조문 번호만 주면 빠진다(2026-10-19 의안 2221231 은 제89조 기준금액을 고치면서 요약에는 「안 제89조의2 신설 등」만 적었다)
- 예정 시행일은 의안 원문 PDF 부칙에만 있어 비워 둔다. 기준일 전 시행인지가 결론을 바꾸면 그 의안의 원문을 연다
- 조회가 실패하면 상태 「실패」와 까닭을 파일에 쓰고 종료코드 1 로 끝난다. 비교 스크립트가 「확인 불가」로 받는다

### 2-2 입법예고·정부안

서브에이전트 하나에 아래 글을 〈 〉 를 채워 보낸다.

```text
입법예고·정부안 조사다. 아래 결론 조문을 고치는 시행령·시행규칙 입법예고와 정부안(국회 제출 전 발표)이 있는지만 찾는다. 국회 의안은 따로 보니 찾지 않는다. 원문은 옮기지 않는다. 짧게 끝낸다.
오늘 〈YYYY-MM-DD〉, 기준일 〈YYYY-MM-DD〉
결론 조문: 〈법령 제N조 제N항〉 …
이미 공포돼 판 목록에 있는 판: 〈시행일(공포일)〉 … 이 판들을 만든 예고·정부안은 적지 않는다

1. 웹 검색은 3번까지, 페이지 열기는 3번까지 쓴다. 브라우저 창과 curl 은 쓰지 않는다.
   검색어 예: 「〈법령〉 시행령 입법예고 〈연도〉」, 「〈연도〉 세법개정안 〈법령〉」, 「〈법령〉 개정 정부안 〈조문 제목의 낱말〉」
2. 결론 조문을 고치는 안만 항목으로 적는다. 구분은 입법예고 / 정부안 중 하나다. 이미 공포됐으면 공포일을 적는다. 본문을 열어 대상 조문과 시행 예정일을 읽었으면 확인은 "본문", 기사·목록만 봤으면 "목록"이다. 시행일은 날짜로 적힌 것만 쓴다.
3. 찾은 안이 없으면 항목을 비우고 상태를 "완료"로 적는다. 검색을 끝내지 못했으면 "실패"와 까닭을 적는다. URL 은 검색 결과가 준 것만 옮긴다.
   `검색어` 칸에는 정식 법령명만 적는다(예: 「법인세법」). 실제로 친 검색 문장은 `검색문` 칸에 적는다.
4. 아래 모양의 JSON 을 〈출력 경로〉 에 쓰고 경로 한 줄만 답한다.
```

조사 파일 모양(국회.json 도 같은 모양이다):

```json
{
 "조사처": "개정안",
 "상태": "완료",
 "까닭": "",
 "검색": {"출처": "웹 검색", "기간": ["2026-01-01", "2026-10-19"], "검색어": ["소득세법", "소득세법 시행령"], "검색문": ["소득세법 시행령 입법예고 2026"]},
 "항목": [
  {
   "법령": "소득세법 시행령",
   "구분": "입법예고",
   "번호": "재정경제부공고 제0000-000호",
   "공포일": "",
   "시행일": "2027-01-01",
   "대상조문": ["제155조"],
   "요지": "예고문 문장 그대로",
   "URL": "검색 결과가 준 링크",
   "확인": "목록"
  }
 ]
}
```

- `검색어` 는 정식 법령명이나 그 앞부분이다. 「소득세법」 하나로 법률·시행령·시행규칙을 함께 찾은 것으로 본다. 약칭(「외부감사법」)만 적으면 그 법령을 찾지 않은 것으로 나온다
- `법령` 은 기준 파일과 같은 이름으로 적는다. 다른 이름은 「기준 목록에 없는 법령」으로 따로 모인다
- 기준 파일에 `"필수조사처": ["국회", "개정안"]` 을 적으면 조사 파일이 없을 때 「확인 불가」가 난다. 기준일이 오늘 뒤면 적어 둔다

## 관보 공포 조사(드물게)

공포 소식이 있는데 `amendment_track` 에 그 판이 없을 때만 한다. 조사처는 `공포`, 항목 구분은 `공포` 다. 검색 기간은 쓴 판 공포일부터 오늘까지로 적는다. 다른 법령의 부칙으로 고친 타법 개정은 관보 제목에 이 법령 이름이 없으므로 「〈법령명〉 일부를 다음과 같이 개정한다」 문장으로 본문 검색을 한 번 더 한다.

## 판정과 할 일

| 판정 | 등급 | 할 일 | 결론 옆에 적는 것 |
|---|---|---|---|
| 변경 없음 | 없음 | 없음 | 「최신화 점검 YYYY-MM-DD 변경 없음」 |
| 판 목록에 있음 · 다른 조문 개정 | 참고 | 없음 | 없음 |
| 판 다시 고르기 | 조치 | 기준일에 시행 중인 판(스크립트가 적은 MST@시행일)으로 조문과 부칙을 다시 읽는다 | 고친 판 |
| 기준일 뒤 시행 | 경고 | 결론을 그 뒤 사건에도 쓰면 그 판과 부칙 적용례를 본다 | 시행일과 판 |
| 공포 대기 · 개정안 | 경고 | 적용하지 않는다 | 개정안과 단계. 기준일 전 시행 예정이면 「확정되면 결론이 바뀔 수 있다」 |
| DB 미반영 | 조치 | 관보 공포문을 읽는다. 결론 조문이 바뀌었으면 공포문으로 고치고 그 조문은 ★★☆ 로 적는다 | 「DB 미반영 개정(공포번호) ★★☆」 |
| 시행일 불일치 · 불일치 | 조치 | 쓰지 않고 보고한다. 어느 쪽이 맞는지 추측하지 않는다 | `[불일치]` |
| 고시 변경 | 조치 | 고시 원문과 첨부 목록을 다시 본다 | 고친 고시 |
| 확인 불가 · 기준 오류 | 조치 | 판 목록을 늘려 다시 받거나 조사를 다시 돌린다. 끝내 안 되면 남긴다 | 「최신화 미확인」 |

조사 결과는 웹 자료다. 개정이 있다는 신호로만 쓰고 조문 근거는 법제처·관보 원문에서 읽는다.
