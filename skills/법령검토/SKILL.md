# 법령검토: 적용법을 먼저 정하고 근거를 원문으로 확인한다

예전 이름은 법령조회다(2026-10-19 에 바꿨다). 예전에 설치한 `~/.claude/skills/법령조회` 는 install 스크립트를 다시 돌리면 지워진다.

모든 한국 법령의 조문을 원문으로 확인한다. 노무와 상법을 가장 많이 쓴다. 무엇을 검토할지(쟁점, 회신 양식)는 사용자나 부르는 스킬이 정한다.

이 스킬은 **적용되지 않는 법으로 답하는 실수**, **다른 판·다른 법의 조문을 근거로 쓰는 실수**, **조회하지 못한 것을 없는 것으로 적는 실수**, **기준일에 맞지 않는 판을 쓰는 실수**를 막는다.

## 준비 (처음 한 번)

연결 확인에서 도구가 없으면 조회를 멈추고 이 절을 사용자에게 보여 준다.

| 필요한 것 | 언제 | 없으면 |
|---|---|---|
| korean-law 법령 서버(로컬, 법제처 OPEN API 인증값 OC 필요) | 늘 | 조문을 읽을 수 없다 |
| 법제처 통합검색 커넥터(korean-law-mcp, 주소 끝에 `?oc=<본인OC>`) | 행정해석·판례 본문 검색·고시 | 고용노동부 행정해석과 판례 본문 검색을 못 한다 |
| TaxDoctor 커넥터 | 세법을 볼 때 | 세법 조문이 ★★☆ 까지만 된다 |
| Node.js 18 이상, 파이썬 3.10 이상 | korean-law 서버, 최신화 점검 스크립트 | 서버가 뜨지 않거나 판 목록 대조를 못 한다 |

1. **설치 스크립트.** 스킬 폴더와 korean-law 서버(`~/.claude/mcp/korean-law`)를 함께 넣는다. 윈도우 PowerShell 은 `irm https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.ps1 | iex`, 맥·리눅스는 `curl -fsSL https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.sh | sh`
2. **법제처 OPEN API 인증값(OC).** `open.law.go.kr` 회원가입 → 「OPEN API 신청」에서 활용신청을 한다. 승인까지 하루 이틀 걸린다. OC 는 가입 아이디다(이메일이 `hong@gmail.com` 이면 `hong`). 같은 OC 를 korean-law 서버(3번)와 법제처 통합검색(4번)에 넣는다
   - 신청 화면에서 법령 본문·부칙, 행정규칙, 판례·법령해석례·헌재결정례, 별표·서식, 조세심판원 결정례를 모두 체크한다. 좁게 신청하면 오류 없이 0건이 나온다
   - IP 칸이 있으면 쓰는 PC 의 공인 IP 를 넣는다. 2026-07 법제처 답변으로는 아이디로 호출한다고 하니 신청 화면 안내를 따른다. 문의는 02-2109-6446
3. **korean-law 등록.** 경로는 절대경로로 적는다. `~` 를 쓰면 연결이 안 된다

   ```bash
   claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "<홈 폴더 절대경로>/.claude/mcp/korean-law/index.js"
   ```

   데스크톱 앱만 써서 `claude` 명령이 없으면 홈 폴더의 `.claude.json` 파일 `mcpServers` 에 넣는다.

   ```json
   "korean-law": {
     "type": "stdio",
     "command": "node",
     "args": ["<홈 폴더 절대경로>/.claude/mcp/korean-law/index.js"],
     "env": { "LAW_OC": "<본인OC>" }
   }
   ```

4. **법제처 통합검색(korean-law-mcp).** 클로드 설정 → 커넥터 → 커스텀 커넥터 추가에 `https://mcp.gomdori.app/law?oc=<본인OC>` 를 넣는다. 터미널에서는 `claude mcp add -s user --transport http law-search "https://mcp.gomdori.app/law?oc=<본인OC>"`
   - `?oc=` 를 빼면 키 없는 사용자 모두가 서버 키 한도 하나를 나눠 써서 요청 한도 초과(429)가 잦다. 통합검색이 429 를 내면 사용자에게 주소의 `?oc=` 를 확인하라고 알린다
   - 커넥터 주소는 고칠 수 없다. `?oc=` 없이 넣었으면 지우고 다시 추가한다
   - OC 가 이 서버(외부 운영)로 넘어간다. 꺼리면 korean-law-mcp 를 PC 에 직접 설치한다(패키지 README 「내 컴퓨터에 직접 설치」)
5. **TaxDoctor(세법을 볼 때).** `taxdoctorai.com` 에서 무료 가입한 뒤 커스텀 커넥터 추가에 `https://mcp.taxdoctorai.com/mcp` 를 넣는다. 터미널에서는 `claude mcp add --transport http taxdoctor https://mcp.taxdoctorai.com/mcp`
6. **확인.** 앱을 껐다 켜고 「민법 제162조 원문 찾아줘」를 묻는다. 법령명·시행일·`law.go.kr` 링크가 나오면 된다

두 서버가 모두 자기 이름을 korean-law 라고 한다. 로컬 서버 도구는 `mcp__korean-law__…` 이다. 통합검색 도구는 커넥터로 넣으면 `mcp__<id>__…`, 터미널로 넣으면 `mcp__law-search__…` 이고 설명이 「Korean-law-mcp」로 시작한다. ToolSearch 로 `search_decisions moel` 을 찾으면 통합검색 쪽이 나온다.

## 리서치 시간: 최대 10분

한 질문에 최대 10분을 쓴다. 기본 다섯 단계(5분 안팎)를 먼저 끝내고, 결론을 바꿀 수 있는 확인이 남았을 때만 「더 볼 것」으로 넘어간다. 남은 확인이 없으면 바로 끝낸다. 조문만 읽고 끝내지 않고, 그 조문이 실무에서 어떻게 적용되는지 행정해석이나 판례로 한 번은 확인한다.

| 단계 | 목표 시간 | 하는 일 |
|---|---|---|
| 1 적용법 | 30초 | 분야를 고르고 그 분야 문서의 「적용법 정하기」로 적용 법령과 확인할 사실을 정한다 |
| 2 조문 | 1분 | 출발 조문과 적용 범위 조문을 한 메시지에서 함께 연다 |
| 3 해석 | 2분 | 분야 문서의 출처에서 행정해석·판례·해석례를 출처마다 1~2건 찾아 본문을 읽는다. 검색은 한 메시지에서 함께 부른다 |
| 4 최신화 | 30초 | 판 목록 대조. 기준일이 오늘 뒤이거나 개정 소식을 물었으면 국회 의안 검색도 한다 |
| 5 정리 | 1분 | 「사용자에게 답할 때」 순서로 쓰고 인용을 도구 응답과 맞춘다 |

**더 볼 것(최대 5분 더).** 이 질문에 해당하는 것만, 결론에 크게 기댄 것부터 한다.

| 언제 | 하는 일 |
|---|---|
| 결론이 판례·해석에 기댄다 | 반대 근거를 찾는다. 결론과 반대인 판례·해석을 한두 번 검색하고, 있으면 무엇이 달라서 결론이 갈렸는지(사실관계, 시점) 적는다 |
| 이미 일어난 일의 효력을 묻는다(사후 추인, 소급, 시효, 무효·취소) | 3단계에서 읽은 것 말고, 그 효력을 다룬 대법원 판례를 2~3건 더 읽는다 |
| 판례·해석이 서로 엇갈리거나 판례가 바뀌었다 | 옛 판례와 새 판례, 다른 해석을 나란히 적고 적용 시점을 본다 |
| 결론의 요건·금액이 하위 법령에서 정해지는데 아직 열지 않았다 | 시행령·시행규칙·별표·고시까지 연다 |
| 사용자가 앞으로를 묻거나 개정 논의가 잦은 쟁점이다 | 기준일이 오늘이어도 국회 의안 검색을 한다 |
| 사용자가 「자세히」·「의견서용」을 원한다 | 위 항목을 모두 본다 |

**멈추는 기준.**
- 남은 확인이 결론과 금액을 바꾸지 않으면 끝낸다
- 10분이 되면 남은 확인을 실무해설에 「미확인: …」으로 적고 끝낸다
- 한 쟁점에 같은 출처로 세 번 넘게 찾지 않는다(기본 단계와 더 볼 것을 합쳐 센다). 그래도 없으면 「찾지 못함(검색어)」으로 적는다

**조회 요령.**
- 서로 기다리지 않는 조회는 한 메시지에서 함께 부른다. 같은 법의 여러 조, 서로 다른 출처의 검색이 그렇다
- 결론에 쓸 조문만 연다. 법 전체를 읽지 않는다(`get_law_text` 에 `article` 을 준다)
- 검색이 0건이면 낱말을 줄이거나 다른 표기로 한 번 더 찾는다. 법제처 검색은 띄어 쓴 낱말을 모두 포함해야 걸린다(AND)
- 서브에이전트는 입법예고 조사와, 도구로 읽지 않고 적은 인용을 검증할 때만 쓴다

## 분야 문서

1단계에서 분야를 고르고 그 문서를 연다. 문서마다 적용법 정하기, 자주 묻는 질문과 출발 조문, 출처, 시험한 예시 질문이 있다. 결론까지 적힌 예시는 사람이 보는 `references/분야/예시.md` 에 따로 두었다. 조사하는 동안에는 그 파일을 열지 않는다

| 분야 | 문서 | 예시 질문 |
|---|---|---|
| 노무 | `references/분야/노무.md` | 1년 미만 연차, 4명 회사의 가산수당·해고, 알바 퇴직금, 재직조건 상여금과 통상임금, 최저임금 |
| 상법(회사법) | `references/분야/상법.md` | 소규모회사의 이사·감사, 이사 보수·퇴직금 결의, 자기주식 취득 한도 |
| 세법 | `references/분야/세법.md` | 업무용승용차 비용, 장기보유특별공제, 1세대 1주택 |
| 민사 | `references/분야/민사.md` | 소멸시효, 임대차 보증금 반환 |

여러 분야에 걸치면(예: 대표이사 퇴직금은 상법과 노무) 문서를 함께 열되, 두 번째 분야는 쟁점에 걸리는 행만 본다. 거기서 열지 못한 조문은 실무해설에 「미확인」으로 적는다. 맞는 문서가 없으면 아래 「출처」와 「절차」만으로 한다.

## 출처

| 무엇 | 도구 |
|---|---|
| 세법 조문 | TaxDoctor `get_article` 과 korean-law `get_law_text` 같은 판 |
| 세법이 아닌 법 조문 | korean-law `get_law_text`. 실패하면 법제처 통합검색 `get_law_text` |
| 별표 | 법제처 통합검색 `get_annexes`, 세법은 TaxDoctor `get_annex` |
| 대법원 판례 | 법제처 통합검색 `search_decisions(domain="precedent")` → `get_decision_text`. 본문 검색은 `options={"search": "both", "court": "대법원"}`, 사건번호는 `options={"caseNumber": "…"}` |
| 고용노동부 행정해석 | 법제처 통합검색 `search_decisions(domain="moel")` → `get_decision_text(domain="moel")` |
| 노동위원회, 산재·고용보험 재심사 | 법제처 통합검색 `domain="nlrc"`, `"iaciac"`, `"eiac"` |
| 법제처 법령해석례 | korean-law `search_decisions(domain="expc")` 또는 통합검색 `domain="interpretation"` |
| 조세심판원, 국세청 예규 | korean-law `search_rulings`, 통합검색 `domain="tax_tribunal"`, `"nts"` |
| 고시·행정규칙 | 법제처 통합검색 `execute_tool("search_admin_rule")` → `execute_tool("get_admin_rule")`. 본문이 첨부 PDF 뿐이면 사용자 허락을 받고 내려받아 `pypdf` 로 읽는다 |

- TaxDoctor 는 세법 90개만 싣는다. 민법·상법·근로기준법 등은 없다
- 웹은 법령 원문을 대신하지 않는다. 사건번호처럼 찾을 단서를 얻는 데만 쓴다

첫 조회가 응답하면 연결 확인으로 친다. ToolSearch 로 korean-law 도구를 찾지 못하면 「준비」 절을 안내하고 멈춘다. 첫 조회가 실패하면 korean-law `search_law(법령명)`, TaxDoctor `list_laws` 로 서버가 살아 있는지 본다. 둘 다 응답하지 않으면 웹으로 잠정 조사하고 결과 첫 줄에 「법령 원문 미검증」을 적는다. TaxDoctor 가 없는 사용자는 세법도 korean-law 가 1차다.

## 대조 규칙과 등급

| 등급 | 조건 |
|---|---|
| ★★★ | 세법 조문은 TaxDoctor 와 korean-law 두 곳에서 같은 판을 읽었다. 세법이 아닌 법의 조문·부칙·별표는 법제처 원문을 읽었다. 판례·행정해석·심판례·해석례는 본문을 읽고 번호·날짜를 적었다. 고시는 법제처 행정규칙에서 본문(첨부 포함)을 읽었다 |
| ★★☆ | 세법 조문을 한 곳에서만 읽었다. 판례·해석은 목록·제목만 봤다. 고시는 보도·기사로만 확인했다 |
| ☆ | 확인하지 못했다 |

- 행정해석·판례의 번호나 날짜를 도구가 주지 않으면 일련번호와 「날짜 도구가 주지 않음」을 적는다. 본문을 읽었으면 ★★★ 다
- 옛 조문을 기준으로 한 행정해석·판례는 그 조문이 지금도 같은 내용인지 맞춰 본다. 달라졌으면 ★★☆ 로 적고 참고로만 쓴다
- 별표는 그 시행령의 판(MST@시행일)으로 적는다. 도구가 판을 주지 않으면 별표의 개정 표시(예: 「개정 2018. 6. 29.」)를 적는다
- OC 값이 들어간 링크(`OC=***` 꼴)는 옮기지 않고 「도구가 주지 않음」으로 적는다
- 결론에 쓰는 근거는 ★★★ 이어야 한다. ★★☆ 나 ☆ 가 하나라도 있으면 그 등급을 결론 옆에 적는다
- 두 곳이 같은 판인지는 `MST@시행일` 로 본다. TaxDoctor 원천 스냅샷 `moleg-eflaw:<MST>@<시행일>` 이 korean-law 머리줄의 `MST`·`시행일` 과 같아야 한다
- 기준일이 오늘 뒤면 TaxDoctor 는 시행예정 판 본문을 다 주지 않는다. 두 곳 대조는 오늘 판으로 하고, 기준일 판은 korean-law 로 읽어 결론 조문이 오늘 판과 같은지 본다. 같으면 ★★★, 다르면 기준일 판 문장은 ★★☆ 다
- 원문이 다르면 쓰지 않고 그 사실을 보고한다. 어느 쪽이 맞는지 추측하지 않는다
- URL 은 도구가 준 것만 옮긴다. 도구가 주지 않으면 「도구가 주지 않음」을 적고 만들지 않는다

## 절차

1. **적용법.** 분야를 고르고 분야 문서의 「적용법 정하기」로 적용 법령(일반법, 특별법, 시행령)과 확인할 사실을 정한다. 사실이 질문에 없으면 가정을 적고 답을 갈라 쓴다
2. **조문 특정.** 분야 문서의 출발 조문 가운데 이 질문에 걸리는 것이 있으면 건너뛴다. 없으면 쟁점 키워드로 korean-law `scan_articles` 를 돌린다. 그 법의 법률·시행령·시행규칙을 함께 넣고, 세법이면 조세특례제한법도 넣는다. 「훑기 실패」가 나온 법령은 「확인 불가」로 적는다
3. **원문.** 기준일에 시행 중인 판을 읽는다. 기준일은 사건 날짜(퇴직일, 해고일, 결의일, 양도일 등)다. 과세기간·사업연도를 물으면 그 기간 끝 날, 연도로 물으면 그해 1월 1일, 아무것도 없으면 오늘이다. 세법은 같은 판을 TaxDoctor 와 korean-law 에서 읽는다. 항·호·목까지 좁혀 인용한다
4. **조문 끝까지 읽기.** 단서, 괄호, 「다만」, 「각 호의 어느 하나」, 표 안의 목을 빼지 않는다. 같은 조 안에서 놓치는 일이 가장 잦다
5. **부칙.** 쓴 판이 오늘 판과 다르거나, 기준일 뒤 시행 판에서 결론 조문이 바뀌면 `get_addenda(keywords=["적용례","경과조치","시행일"], since=…)` 로 본다. 아니면 건너뛴다. 조문의 판정 기준일과 부칙의 적용 기준일은 다를 수 있다
6. **위임.** 결론의 숫자·요건이 하위 조문에서 정해질 때만 연다(예: 「대통령령으로 정하는 요건」이 결론을 가를 때). `trace_references` 로 찾고, 세법은 TaxDoctor 위임 목록과 합친다. 열지 않았으면 실무해설에 「위임 조문 미확인: 시행령 제N조」 한 줄을 적는다
7. **인용된 조문.** 결론 문장의 뜻이 인용된 조문에서 정해질 때만 연다. 같은 법 안의 조문도 마찬가지다(예: 상법 제341조의 배당가능이익은 제462조 제1항). 부르는 스킬에 `법령별칭.json` 이 있으면 그것부터 본다
8. **해석.** 분야 문서의 출처에서 찾는다. 노무는 고용노동부 행정해석과 대법원 판례, 상법·민사는 대법원 판례와 법제처 해석례, 세법은 조세심판원과 국세청 해석이다. 판례가 바뀐 적이 있는지와 새 판례의 적용 시점을 본다. 조문과 어긋나면 `[불일치]` 로 남긴다
9. **최신화 점검.** 아래 「최신화 점검」대로 한다
10. **인용 대조.** 결과에 쓴 조문번호·사건번호·해석번호를 조 단위·사건 단위로 뽑아, 반환 형식의 발췌가 도구 응답 문장과 같은지 직접 맞춘다. 도구로 읽지 않고 적은 인용이 하나라도 있으면, 초안을 보지 않은 서브에이전트에게 번호와 「이 취지로 인용했다」 한 줄만 주고 원문과 맞는지 판정받는다. 판정은 `일치` / `불일치(무엇이)` / `존재하지 않음`. 존재하지 않는 인용은 지운다

## 최신화 점검

두 곳 대조는 문구가 같은지만 본다. 기준일에 맞는 판인지와 개정안이 있는지는 따로 본다.

1. **판 목록 대조(늘 한다).** 결론에 쓴 법령마다 korean-law `amendment_track` 을 함께 부르고, 쓴 판과 판 목록을 `기준.json` 에 적어 돌린다. 몇십 초면 끝난다

   ```bash
   python scripts/freshness_check.py --기준 기준.json --출력 최신화점검.json
   ```

   기준일에 시행 중인 판을 썼는지(아니면 「판 다시 고르기」), 기준일 뒤에 시행될 판이 있는지(「기준일 뒤 시행」) 나온다
2. **개정안 조사(조건부).** 기준일이 오늘 뒤이거나 사용자가 개정·변경 소식을 물었을 때만 한다
   - 국회: 의안 검색 스크립트로 결론 조문을 고치는 계류·통과 법안을 모은다. 10초 안팎이다

     ```bash
     python scripts/bill_search.py --대상 "근로기준법:제60조" --키워드 "연차" --출력 국회.json
     ```

     의안 요약은 주된 조문만 「안 제N조 등」으로 적는다. 조문 번호만으로는 빠지니 조문 제목의 낱말을 `--키워드` 로 함께 준다. 정의 조항처럼 넓은 조문은 관계없는 법안이 많이 걸리므로 `--키워드필수` 를 붙여 키워드가 요약에 나온 법안만 남긴다. 법령이 여럿이면 `--대상` 을 여러 번 줘서 한 번에 돌린다(국회 파일이 하나여야 비교 스크립트가 받는다)
   - 입법예고·정부안: 서브에이전트 하나가 웹 검색 3번 안에서 시행령·시행규칙 입법예고와 정부안을 찾는다. 판 목록을 함께 줘서 이미 공포된 안은 빼게 한다
   - 두 파일을 `--조사 국회.json 개정안.json` 으로 넘긴다
3. **처리.**
   - 「판 다시 고르기」는 그 판으로 3~5번을 다시 한다
   - 「기준일 뒤 시행」은 결론 조문만 가장 늦은 시행일 판으로 한 번 열어, 결론에 쓴 항의 문구만 비교한다. 같으면 실무해설에 「YYYY-MM-DD 판까지 결론 조문 같음」 한 줄을 적는다. 항 번호만 바뀌었으면 「YYYY-MM-DD 판에서는 제N항」으로 적고 앞 판은 열지 않는다. 같은 조에 새 항이 생기면 무엇이 생기는지 한 줄 적는다. 문구가 다르면 앞 시행일 판을 열어 언제부터 바뀌는지 찾고 결론 옆에 「YYYY-MM-DD 부터 바뀜」을 적는다
   - 「확인 불가」·「불일치」는 처리하거나 결론 옆에 적는다
   - 개정안은 적용하지 않고 단계와 예정 시행일을 결론 옆에 적는다

관보 공포 조사는 공포 소식이 있는데 `amendment_track` 에 그 판이 없을 때만 한다. 파일 모양과 서브에이전트에게 주는 글은 `references/최신화점검.md` 에 있다.

## 사용자에게 답할 때

사용자가 직접 물으면 이 순서로 답한다. 다른 스킬이 불렀으면 아래 「반환 형식」으로 넘기고, 답변 양식은 그 스킬을 따른다.

1. **결론.** 2~3줄. 적용법을 가른 사실(예: 상시근로자 5명 이상)을 함께 적는다. ★★★ 가 아닌 근거에 기댄 문장은 옆에 등급을 적는다. 최신화 점검이 「경고」나 「조치 필요」면 한 줄 붙인다
2. **쟁점.** 결론을 가르는 지점 1~3개. 지점마다 무엇에 따라 답이 갈리는지 한 줄로 적는다
3. **실무해설.** 확인할 사실, 행정해석·판례가 정한 적용 방식, 반대 근거를 찾았으면 그 결과(찾지 못했으면 검색어), 기준일과 부칙 적용례, 기준일 뒤 개정과 계류 개정안, 건너뛴 위임·인용 조문을 적는다. 결론을 바꾸지 않는 해설은 쓰지 않는다
4. **관련 근거.** 결론에 쓴 조문·판례·해석만 한 줄씩 적는다. 판례·해석은 요지 한 줄과 적용 시점(있으면)을 붙인다

   ```text
   - 근로자퇴직급여 보장법 제4조 제1항 단서 (284455@20260918) ★★★ https://www.law.go.kr/법령/근로자퇴직급여%20보장법/제4조
   - 대법원 2024. 12. 19. 선고 2020다247190 전원합의체 판결 ★★★ (링크: 도구가 주지 않음): 재직 조건이 붙은 정기상여금도 통상임금. 판결일 뒤 산정분부터 적용
   ```

## 반환 형식

다른 스킬에 넘길 때는 이 형식을 쓴다.

```json
{
  "법령": "근로기준법",
  "조항": "제60조 제2항",
  "시행일": "2026-10-08",
  "판": "285279@20261008",
  "발췌": "도구가 준 문장 그대로. 줄인 곳은 … 로 표시",
  "URL": "korean-law 가 준 law.go.kr 링크",
  "출처": ["korean-law get_law_text"],
  "등급": "★★★",
  "최신화": {"점검일": "2026-10-20", "기준일": "2026-10-20", "결과": "변경 없음", "개정안조사": "안 함"}
}
```

`최신화.결과` 는 `변경 없음` / `경고` / `조치 필요` / `미점검` 중 하나다. `미점검` 이면 결론 옆에 「최신화 미확인」을 적는다. `개정안조사` 는 `함` / `안 함` 이다.

판례·행정해석·심판례·해석례는 이 형식으로 넘긴다.

```json
{
  "판례": "대법원 2024. 12. 19. 선고 2020다247190 전원합의체 판결",
  "사건번호": "2020다247190",
  "선고일": "2024-12-19",
  "일련번호": "600537",
  "요지": "한 줄",
  "적용 시점": "판결일 뒤 산정분부터. 없으면 빈칸",
  "발췌": "도구가 준 판시사항·판결요지 문장 그대로",
  "URL": "도구가 준 링크. 없으면 「도구가 주지 않음」",
  "출처": ["법제처 통합검색 search_decisions", "법제처 통합검색 get_decision_text"],
  "등급": "★★★"
}
```

## 법령 목록과 누락 검사

주제마다 필요한 법령을 목록으로 고정하고, 그 목록의 법령이 모두 조회되는지 `coverage_check.py` 로 확인한다. 목록은 그 주제 스킬이 갖는다(예: `양도소득세/rules/법령목록.json`, `법령별칭.json`).

```bash
python scripts/coverage_check.py --목록 <주제스킬>/rules/법령목록.json --별칭 <주제스킬>/rules/법령별칭.json --출력 <주제스킬>/rules/누락검사.json
```

- 법령마다 이름이 정확히 같은 현행 판(MST·시행일)을 법제처에서 찾는다. 세법은 TaxDoctor 수록 여부도 적는다
- 옛 이름은 별칭의 현행 이름으로 찾는다. 법령이 아닌 것(협약 등)은 근거가 적혀 있으면 `해소` 로 표시한다
- `해소` 가 아닌 항목이 하나라도 있으면 종료코드 1 이다. OC 는 환경변수 `LAW_OC` 또는 `claude mcp get korean-law` 에서 읽고 출력하지 않는다

## 틀리기 쉬운 판단

| 떠오른 생각 | 실제 |
|---|---|
| "조문부터 찾자" | 적용법부터 정한다. 4명 이하 사업장, 주 15시간 미만, 소규모회사, 상장회사는 같은 질문에 다른 조문이 적용된다 |
| "조문이 그렇게 써 있으니 끝" | 행정해석이나 판례가 적용 방식을 정한 경우가 많다(재직조건 상여금, 1년 계약직 연차). 3단계를 건너뛰지 않는다 |
| "판례 검색이 0건이니 판례가 없다" | 제목만 검색했을 수 있다. 통합검색에서 본문 검색(`search: "both"`)이나 사건번호(`caseNumber`)로 다시 찾는다 |
| "TaxDoctor 에 나왔으니 됐다" | 세법은 한 곳이면 ★★☆ 다. korean-law 로 같은 판을 열어 대조한다 |
| "검색했더니 비슷한 법이 나왔다" | 이름이 정확히 같은지 본다. 「주택법」 조회에 민간임대주택법이 나온 적이 있다 |
| "날짜를 안 줬으니 현행이다" | 기준일이 오늘이 아니면 그 날짜를 준다. 머리줄의 `시행일` 이 기준일 이전인지 본다 |
| "부칙 조회가 비었으니 적용례가 없다" | 원문을 직접 열거나 「부칙 미확인」으로 남긴다 |
| "웹에 잘 정리돼 있다" | 법령 원문을 웹으로 대신하지 않는다. 웹은 ★★☆ 다 |
| "링크는 이렇게 생겼을 것" | 도구가 준 URL 만 쓴다 |
| "두 곳이 같으니 최신이다" | 둘 다 법제처 DB 를 읽는다. 국회 개정안은 둘 다에 없다. 기준일이 오늘 뒤면 개정안 조사를 한다 |
| "개정 소식이 있으니 반영한다" | 공포 전 개정안은 적용하지 않는다. 결론 옆에 단계와 예정 시행일을 적는다 |

출처별 결함과 대응은 `references/출처별결함.md`, 최신화 점검 세부는 `references/최신화점검.md`, 분야별 적용법·출처·예시 질문은 `references/분야/` 에, 결론까지 적힌 예시는 `references/분야/예시.md` 에 있다.
