# 조특법 세액공제와 감면 (1-(4) 예측, 공제 · 감면 제안)

조특법 공제 · 감면은 판단이 많이 들어간다. 그래서 이 스킬은 적용 여부를 정하지 않고 **회계사가 판단할 재료를 내놓는다.** 방법은 하나다. 제도의 입법 취지를 확인하고, 그 취지에 맞는 거래를 분개장에서 찾아 「이 거래가 이 제도의 취지에 맞아 보입니다」 라고 제안한다.

취지부터 보는 까닭: 조특법은 특정 행동(투자, 고용, 연구, 창업, 이전)을 밀어주려고 만든 법이라 제도마다 장려하는 행동이 있고, 그 행동은 장부에 거래로 남는다. 요건 조문부터 대조하면 조문이 길고 예외가 많아 틀리기 쉽다. 취지에 맞는 거래를 먼저 내놓으면 요건은 회계사가 본다.

| 언제 | 할 일 |
|---|---|
| 1-(4) P4 | 전기 공제 · 감면 줄마다 당기 예측(c1, c2 …) |
| 이슈 메모 | 엔진의 공제감면 이슈(통합고용 · 통합투자 · 연구개발 · 중소기업 특별세액감면)에 판단을 쓴다 |
| 메모 뒤 | `ar.py credits` 로 제도별 제안. P4 예측 가운데 이슈 메모가 받지 않은 것은 여기 `answers` 로 받는다 |

## 순서

1. **전기에 적용한 제도를 본다.** P4 예측과 전기 신고서 8호(갑)(을), 세액공제조정명세서 이월액, 4호 최저한세, 3호 감면 · 공제 줄. 전기 명세가 비었다는 것은 이월액 0원의 확정 근거가 아니다. 「보이지 않는다」 고 쓰고 원본을 요청한다.
2. **아래 표의 제도마다 취지에 맞는 거래를 찾는다.** `_색인/전표.csv` 를 계정명(account_name)과 적요(memo)로 검색하고 장부.json 의 증감을 본다. 표의 「장부에서 찾을 흔적」 은 출발점이다. 비용 계정에 묻힌 자산 취득처럼 계정 이름과 실질이 다른 거래가 가장 값진 제안이다.
- `judge` · `purpose` · `point` 글 속 금액도 검사한다. 여러 줄 합계(월 급여 합계 등)는 `ar.py sum` 으로 먼저 적고 id 나 그 값을 쓴다. `purpose` 는 개정이유를 요약해도 된다(원문 인용은 아래 표). 「…이 아니라」 문장은 거절된다.
- 후보 전표가 없어도 상시근로자 수 · 연구개발 명세처럼 장부 밖 자료로 정해지는 제도는 `적용 가능` 으로 두고 `judge` 와 `ask` 에 받을 자료를 적는다. 전기에서 넘어온 이월분만 남은 제도는 `진행 중`.

3. **찾은 거래를 전표 줄로 내놓는다.** `line` 은 전표.csv 의 머리줄 다음부터 센 줄 번호(1부터), `amount` 는 그 줄의 차변이나 대변 금액 그대로다. 명령이 대조한다.
4. **흔적이 없으면 없다고 적는다.** 어떤 말로 검색했는지 함께 적어야 「안 찾아본 것」 과 구별된다.

전표 줄 번호 찾기 예:

```python
import csv
rows = list(csv.DictReader(open("_색인/전표.csv", encoding="utf-8-sig")))
for n, r in enumerate(rows, 1):
    if "구입" in r["memo"] or "설치" in r["memo"]:
        print(n, r["date"], r["account_name"], r["debit"], r["credit"], r["partner"], r["memo"])
```

## 나누어 보여 주기

| state | 뜻 |
|---|---|
| 적용 가능 | 취지에 맞는 거래가 장부에 보인다. 제안이다. 「적용된다」 가 아니다 |
| 진행 중 | 전기 신고서에 적용 내역이 있다. 이월과 사후관리를 이어서 본다 |

## 제안 파일 (ar.py credits)

```json
{"point": "전기에 무엇을 적용했고 당기에 무엇이 갈리는지 두 문장 안에",
 "items": [
  {"name": "통합투자세액공제", "basis": "조세특례제한법 제24조", "state": "적용 가능",
   "purpose": "사업용 자산 투자를 장려한다(위 표의 개정이유)",
   "candidates": [{"what": "2025-04-07 장비구매 적요, 용역비로 처리", "line": 1234, "amount": 4000000}],
   "judge": ["사업용 유형자산인지(실물 · 사용개시일)", "중복지원 배제 대상 감면이 있는지"],
   "ask": ["장비 구매 계약서와 세금계산서를 보내 주십시오"], "issues": [9], "answers": ["c1"]}
 ]}
```

```bash
python scripts/ar.py credits "<신고건>" <제안.json>
```

- 제안할 것이 없어도 `items: []` 로 넣는다(`finish` 가 이 파일을 본다).
- 적용 가능 · 진행 중 항목에는 회계사가 고를 질문지(`choices`, `references/memo.md` 의 「질문지」 절)를 붙일 수 있다. 적용 불가 항목의 질문지는 화면에 나오지 않는다.
- `issues` 는 관련 AR.json 이슈 번호, `answers` 는 이 제안에서 결론을 낸 P4 예측(c*) 등.
- `judge` 는 장부로 알 수 없어 회계사가 정할 것이다. 결론을 대신 내리지 않는다.
- 공제액을 계산해 적지 않는다. 금액은 후보 전표 금액만.
- 거래가 없는 묶음(진행 중, 적용 불가)은 `candidates` 를 비우고 `point` 나 `judge` 에 한두 문장.
- 결손이 예상되면 당기에 쓰지 못하고 이월되는 공제라는 점을 `point` 에 적는다.
- 검사: state 값, 비지 않은 name · basis · purpose, 후보의 줄 · 금액, 이슈 번호, answers, 글 속 금액, 「…주십시오」, 줄표 · 물음표.
