> 계정체계 · 거래처코드 · 전표 기준 · 부가세 판단 · 회계 프로그램 양식(더존 외)은 회사와 사무소마다 다릅니다.
> 실습 회사(글로우빔 · 메종블룸)는 가상 회사이고, 프로파일(`scripts/profile_*.py`)은 그 회사에 맞춘 예시입니다.
> 직접 만든 결산 스킬의 결과와 이 스킬의 결과를 같은 자료로 돌려 비교하고, 빠뜨린 처리를 찾는 데 쓰십시오.


# 월/분기 결산 에이전트 — 추출(AI) / 계산(코드) / 판단(전문가)

한 회계기간 raw를 받아 **결정적 엔진 + 살아있는 수식 워크북 + 전문가 확인사항**으로 결산 4종을 자율 산출한다.
분개 한 줄을 고치면 재무제표까지 자동 재계산되고, 두 검증 스크립트가 PASS여야 완성이다.
**규칙에 안 걸린 거래는 분개하지 않는다.** 가계정에 두고 미분류 목록으로 낸다.

## 핵심 원리 (이게 품질을 만든다)
- **초안작성자 vs 확정자**: 판단 항목(계정 분류 애매·증빙 부족·공제/불공제·실사 미도착)은 임의 확정하지 않는다. 가장 합리적인 안을 **추천안으로 잠정 기표**(`분류=잠정`)하고 **확인사항 5필드**(항목/상황/선택지/추천안·근거/재무제표 영향)로 등재한 뒤 결산은 끝까지 완성한다. 멈추고 되묻지 않는다(예외: 회사·기간 식별 불가).
- **계산은 결정적 엔진, 추출은 AI, 가정은 사람**: 숫자는 LLM 암산 금지. Python 엔진이 분개·부가세분리·상각·집계를 짜고 `assert`로 대차·앵커를 강제.
- **산출물은 살아있는 수식**: 시산표는 분개장을 SUMIFS로, 재무제표는 시산표 셀을 참조. 하드코딩 금지. (더존 업로드는 반대로 값·숫자형만.)
- **독립 이중검증**: ① `formulas`로 워크북을 실제 재계산해 자체검산과 대조. ② 별도 서브에이전트가 raw부터 다시 집계해 대사.
- **오류는 실질 신호**: 더존 반려·린트·에러를 꼼수로 통과시키지 않는다. "왜 막혔나"를 요건 미충족으로 먼저 해석.

## 절차 STEP 0~9

### 0. 자료 인벤토리
raw 폴더를 스캔해 회사·기간을 식별한다. 필요한 raw: 기초BS(또는 전기이월분개장)·은행거래내역·카드승인내역·세금계산서·급여대장·거래처마스터, (선택) 기말재고 실사표. **식별 불가 시에만** 사용자에게 묻는다(이때만 멈춤).

### 1. 처리 방식 로드 + 전기 참고(필수)
[처리기준.md](references/처리기준.md)의 **회사 프로파일**을 baseline으로 로드한다. 프로파일이 없으면 §C 템플릿으로 `scripts/profile_<회사>.py`를 만든다(예시: `profile_sample.py`). **전기 output이 있으면 `전기 확인사항`(확정 판단·플래그)과 `전기 결산확정`을 반드시 읽어** 확정 판단을 승계하고, 전기 플래그(예: 택시 재분류)를 당기에 확정한다. **전기와 달라지면 「전기 방식 승계·편차」에 편차로 등재**.

### 2. raw 적재·정합성 대사
기초BS↔전기말, 은행 입출금↔세금계산서/급여/카드 상호대사, 카드승인 합↔카드대금 결제를 대사한다. 불일치(예: 기초BS 이월이익잉여금 부호 오류)는 대차 맞는 쪽을 채택하고 **확인사항 등재**. 엔진이 `find`로 파일을 자동 매칭한다.

### 3~6. 결정적 엔진 실행 (분개→조정→재무제표→더존 업로드)
```
python "{skill}/scripts/run_close.py" "<raw_dir>" "<out_dir>" <기간라벨> [profile_모듈]
```
- 산출: `결산확정_{기간}.xlsx`(8시트 전부 수식) · `일반전표_업로드_더존_{기간}.xlsx` · `매입매출전표_업로드_더존_{기간}.xlsx`.
- 엔진(`close_engine.py`)이 원천별 분개(부가세 분리) → **매입공제 전 불공제 체크리스트 적용**(references §B) → 결산조정(감가·무형·원가대체·부가세정리) → 시산표/손익/재무상태표/현금흐름표를 **셀 참조 수식**으로 연결한다.
- 출력된 앵커(매출액·매출원가·미지급세금·카드공제세액·일반전표 차대·매입매출 공급·세액)를 프로파일 §D 기대값과 대조한다.

### 7. 확인사항 리포트 (.docx — 가장 중요)
```
python "{skill}/scripts/build_docx.py" "<raw_dir>" "<out_dir>" <기간라벨> [profile_모듈]
```
- `확인사항_{기간}.docx` 생성: 「확정·회신 필요 항목」 요약 + 판단 5필드 표 + 전기 승계·편차 + 채권채무 + 손익 + 검증 요약(부록 B).
- 회사별 특수 판단 항목은 `build_docx.py`를 복제해 편집한다. `pip install python-docx` 필요.

### 8. 검증 (필수 — 독립 이중검증)
```
python "{skill}/scripts/verify_upload.py" "<out_dir>" <기간라벨> [profile_모듈]
python "{skill}/scripts/verify_close.py" "<out>/결산확정_{기간}.xlsx" [expected.json]
```
- `verify_upload.py` 가 **먼저다.** 대차가 맞아도 더존에서 막히는 것은 양식과 거래처코드·사업자번호다.
  FAIL 이면 올리지 않는다. 임의값으로 통과시키지 않는다.
- `formulas`로 워크북을 재계산해 **엔진값 = 수식값**, 대차 균형, 현금흐름=BS 현금, 순이익 연결을 확인.
- **그리고 별도 서브에이전트를 디스패치**해 raw부터 재집계 → §9 대조. FAIL이면 원인 수정 후 재검증(임의 확정 금지).
- **검증을 확인사항 문서보다 먼저 돌린다.** 문서는 검증 결과 JSON(`_검증_업로드_*.json`·`_검증_워크북_*.json`)을 읽어 적는다. 결과가 없으면 문서에 「검증 미실행」이라고 쓴다. **검사하지 않은 것을 PASS로 적지 않는다.**

### 9. 회사 프로파일 갱신
새 확정판단·매핑·손익을 [처리기준.md](references/처리기준.md) 회사 프로파일과 `profile_<회사>.py`에 승계 기록한다(다음 기간 대비).

## 무엇을 자동으로 검증하고 무엇을 안 하는가

**PASS는 실행한 검사에만 붙인다.** 아래 표의 「어디서」가 빈 항목은 자동 판정이 없다.

| 검사 | 어디서 |
|---|---|
| 시산표 차대, 재무상태표 대차, 현금흐름=BS 현금 | `verify_close.py` · 워크북 검증리포트 수식 |
| 수식 개수(하드코딩 아님), 손익 항등식, 순이익=시산표 손익계정 합 | `verify_close.py` |
| 매출=원천 합계, 부가세 정합, 계정 부호 | 워크북 검증리포트 수식 |
| 시트·컬럼·숫자형·앞자리0, 날짜 범위, 구분과 차대 방향, 전표 유무 | `verify_upload.py` |
| 채권채무 거래처코드, 매입매출 사업자번호, 미등록 거래처 | `verify_upload.py` |
| 분개 건수 + 미분류 건수 = 통장 전체 | `run_close.py` |
| 원천 자료 자체의 정확성 | **자동 판정 없음.** 전문가가 본다 |
| 공제·불공제, 계정 분류, 기말재고 같은 판단 | **자동 판정 없음.** 확인사항으로 등재 |

## 미분류 가드레일 (100% 자동화 금지)

규칙이 모든 거래를 덮으면 어느 것이 규칙이고 어느 것이 추측인지 구분이 없어져 전문가가 검토할 수 없다.
- 전기에 같은 적요 모양이 있으면 그 방식을 승계한다.
- 전기에 없는 신규 거래는 적요가 성격을 설명할 때만 규칙으로 처리한다.
- 둘 다 아니면 **가계정**(가지급금·가수금)에 두고 `미분류목록_<기간>.xlsx` 로 낸다. 분개에서 빼지 않는다.
  빼면 현금 대사와 대차가 깨지고, 임의 계정을 주면 추측이 규칙으로 둔갑한다.
- 프로파일 `미분류_계정` 이 가계정을 정한다. 없으면 이 단계는 돌지 않는다.

## 판단 규율 & Red Flags
- 전기 동일 사례 있으면 그 방식 확정 + 「전기 승계」 표에 행. 없으면 추천안 잠정 + 5필드 등재. 금액 작아도 등재. **프로즈 속 "추정됩니다"는 등재가 아니다 — 표로 등재해야 등재.**
- **Red Flags**: 적요에 추정/가정인데 확인사항에 없음 / 확인사항 0건 / 선택지 없이 추천안만 / 재무영향 빈칸 / 더존 컬럼 임의변경 / 재무제표 하드코딩 / STEP8 없이 완료선언 / **사업자번호 없이 매입공제·여객운송 공제** / **반려를 임의값으로 통과** / **채권채무 계정 거래처코드·매입매출 11열 사업자번호를 선언 없이 빈칸으로 내보냄**(원천에 있는데 안 쓴 것인지, 한 거래처가 아니어서 빈 것인지 구분 안 됨) / **업로드 파일 컬럼·시트명을 손댐**(회사가 쓰던 양식 그대로여야 한다).

## CSV 폴더로 바로 (제일 간단한 길)

```
python "{skill}/scripts/close_folder.py" <CSV폴더> [기간] [회사프로파일] [산출폴더]
```

폴더에 CSV 열 개가 있으면 **원천 읽기 → 분개·재무제표·더존 업로드 → 확인사항 → 업로드 사전검증 → 검산**까지 한 번에 갑니다.
설치할 것이 없습니다. 산출폴더를 안 주면 **CSV폴더 안에 `결산_<기간>` 을 만듭니다.**
원본 CSV 는 읽기만 하고 건드리지 않습니다.

**기간을 안 주면 통장 거래일자에 있는 달 중 마지막 달을 잡습니다.** 두 달치가 들어 있는 자료가
많아서 무엇을 골랐는지 첫 화면에 찍습니다(`기간 2026-06 (통장에 있는 달 2026-05 · 2026-06 중 마지막)`).
다른 달을 돌리려면 기간을 직접 주면 됩니다.

필요한 CSV 열 개는 이것입니다.
`bank_transactions` · `card_approvals` · `tax_invoices` · `payroll` · `partners` ·
`accounts` · `opening_balance` · `journal_prior` · `platform_settlements` · `export_invoices`

사용자가 "이 폴더 자료로 결산해줘" 라고 하면 이 명령을 씁니다. 폴더에 CSV 가 없으면
어느 표가 빠졌는지 말하고 멈춥니다.

## 프로파일 메모

- **월 단위로 여러 번 돌리는 회사는 재고를 기간별로 줍니다.** `상품_기초재고`·`상품_기말재고_잠정` 에
  `{"2026-05": …, "2026-06": …}` 처럼 dict 를 두면 엔진이 그 기간 값을 씁니다(`Engine._by_period`).
- **카드 불공제 사유는 프로파일이 정합니다.** `카드불공제_사유 = {가맹점: 사유}` 를 두면 엔진이 적요에
  「매입세액 불공제 · 사유」로 적습니다. 안 두면 사유 없이 「매입세액 불공제」만 남습니다.
- 원천이 데이터베이스에 있으면 그 테이블을 위 열 개 표 모양으로 내보낸 뒤 `close_folder.py` 로 돌립니다.

## 커맨드 (슬래시 호출)
- `/결산자동화 <CSV폴더> [기간]` — `close_folder.py` 한 번으로 CSV 폴더에서 검산까지. 기간을 빼면 자료의 마지막 달.
- `/결산자동화 <raw_dir> <기간> [profile_모듈]` — run_close → build_docx → verify_close 순으로 4종 산출 후 앵커·검증 요약 보고.
- `/결산자동화 <raw_dir>` — 폴더를 스캔해 회사·기간을 식별(파일명·자료에서 추론)한 뒤 위 절차 실행.
- `/결산자동화` (인자 없음) — 처리할 raw 폴더 경로를 되묻고(STEP 0), 확인되면 실행.
- 산출물은 `<raw_dir>/output` (미지정 시)에 저장하고, 기간라벨은 `2026Q2`·`2026-05` 형식으로 정규화한다.
