> 결산자동화 스킬의 딸린 자료다. 원천 자료가 Gridie(MCP) DB 표일 때 읽는다.

#### Gridie(MCP) 표에서 받을 때
DB 표에는 여러 분기가 한 표에 있다. 표를 raw 엑셀로 내릴 때 이 순서를 지킨다(2026-10-16 마루키 2분기를 MCP 로 받아 돌려, Drive 원본으로 돌린 산출물과 셀 단위로 같음을 확인).
- **기간으로 거른다.** 통장 · 카드 · 세금계산서는 날짜, 급여대장은 귀속월, 기초재무상태표는 기준일(직전 분기말), 전기이월분개장은 일자(직전 분기말)로 거른다. 엔진도 결산 기간에 들지 않는 행을 빼고 `[주의]` 줄과 확인 항목으로 남기지만, 원천에서 거르는 것이 먼저다. 거르지 않으면 매출이 두 배로 잡혀도 `verify_close` 는 ALL PASS 를 낸다.
- **파일 이름 · 머리글 · 열 순서는 예시 폴더(`2분기_당기`)와 같게** 둔다. 엔진은 열을 위치로 읽는다. 금액 · 계정코드 · 사업자번호는 숫자형, 거래처코드는 텍스트('00101').
- **`run_sql` 은 UNION 을 쓰면 행을 돌려주지 않는다**(`affectedRows` 만 온다). 표마다 따로 읽거나 스칼라 하위 질의로 묶는다.
- **한 행을 문자열로 묶을 때 `concat_ws` 를 쓰지 않는다.** NULL 값이 사라져 입금 · 출금 열이 밀린다. `concat(a, '|', b, …)` 는 NULL 을 빈 문자열로 둔다.
- **내린 뒤 원천과 맞춘다.** 표마다 행 수와 금액 합계(또는 정렬한 행 문자열의 md5)를 `run_sql` 로 다시 세어 엑셀과 대조한다. 행을 옮겨 적다 생긴 오타는 대차가 맞아도 남는다.
