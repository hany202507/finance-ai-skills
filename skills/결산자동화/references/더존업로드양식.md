# 더존 SmartA 엑셀 업로드 양식 스펙 (authoritative)

> **이 문서가 더존 양식의 기준이다.** 폴더에 더존 매뉴얼·양식 파일이 없어도 이 스펙만으로 업로드 파일을 생성한다.
> 폴더에 더존 원본 양식이 **있고 이 문서와 다르면**(버전업 등) 그때만 원본을 우선하고, 차이를 확인사항에 등재한 뒤 이 문서를 갱신한다. (계정 선택·라우팅 판단은 [처리기준.md](처리기준.md)의 회사 프로파일·전기 방식 우선 — 이 규칙은 파일 형식에만 적용)

## 전표 라우팅 규칙

| 원천 | 업로드 파일 |
|---|---|
| 세금계산서·계산서·카드매출/매입 등 부가세 신고 대상 | 매입매출전표 업로드 |
| 그 외 모든 거래(급여·이체·차입/상환·자본·카드대금결제 등) | 일반전표 업로드 |
| 결산조정분개(감가·원가대체·부가세정리·미지급비용 등) | 일반전표 업로드 |

카드 매입 중 **매입세액 공제 대상**(가맹점 사업자번호 확인)은 매입매출전표(과세유형 57), **불공제·해외결제·간이·사업자번호 미확인**은 일반전표(전액비용) — 전기 라우팅 우선 확인.

## 1) 일반전표 업로드 (.xlsx, 시트명 「일반전표」)

이전 기간 파일과 동일한 컬럼 순서를 유지한다:

| 컬럼 | 형식 | 비고 |
|---|---|---|
| 월 / 일 | 숫자 | 필수 |
| 구분 | 숫자 | **3=차변, 4=대변** (1=출금, 2=입금, 5=결산차변, 6=결산대변) |
| 계정과목코드 | 숫자 | 더존 표준 계정코드 |
| 계정과목명 | 문자 | 코드와 일치 |
| 거래처코드 | 문자(5자리, 예 '00138') | 채권·채무 계정은 필수 기재 |
| 거래처 | 문자 | |
| 적요 | 문자 | |
| 차변 | 숫자 | 구분=3(또는 5)일 때만 |
| 대변 | 숫자 | 구분=4(또는 6)일 때만 |

- 한 전표(차대 세트)는 연속 행, 전표 내 차변합=대변합.
- 금액·**코드성 숫자(사업자번호·계정코드·과세유형)는 숫자형**(텍스트면 반려). 콤마·통화기호 금지.
- **거래처코드처럼 앞자리 0이 있는 값('00138')만 텍스트.**
- 재업로드 시 더존에서 기존 자동분개 삭제 후 올릴 것(중복 방지 — 안내 문구에 포함).

## 1-1) 거래처코드·사업자번호는 비워서 내보내지 않는다 (2026-09-13 추가)

세션2 실습 산출물에서 **일반전표 채권채무 35행 중 거래처코드가 1행만 채워지고, 매입매출전표
11열 사업자번호가 플랫폼 매출 6행에서 통째로 비어 있었다.** 원천(거래처마스터·정산서)에는 둘 다
있었는데 엔진이 쓰지 않았다. 대차는 맞으니 검산은 통과하고, 막히는 것은 더존에 올리는 순간이다.

원인은 **이름이 두 체계라서**다. 분개 적요의 거래처라벨은 짧은 통칭('네이버')이고 거래처마스터는
등기 상호('네이버파이낸셜(주)')다. 둘을 잇는 자리가 없으면 조회가 전부 빗나간다.

- 거래처마스터에는 **더존거래처코드**(5자리, 앞자리 0)와 **사업자번호**가 같이 있다. 라벨→상호가
  붙으면 두 값이 같이 따라온다. 따로 찾을 필요가 없다.
- **부분일치로 맡기면 안 된다.** '네이버'는 네이버파이낸셜(주)(플랫폼)과 네이버(주) 검색광고(광고)
  둘 다에 걸린다. 그래서 `close_engine.resolve_party` 는 좁은 것부터 찾고, 후보가 둘 이상이면
  빈칸으로 두고 미해소로 등재한다. 찍지 않는다.

| 계정·열 | 규칙 |
|---|---|
| 일반전표 거래처코드 | 채권채무 계정(108·120·131·133·232·251·253·254·259·260·262·293)은 필수 |
| 매입매출 11열 사업자번호 | 전 행 필수. 예외는 영세(12) 국외 거래처뿐 |
| 매입매출 11열, 유형 57·58·61 | **사업자번호 없으면 공제 대상이 아니다.** 일반전표로 보낸다 |
| 매입매출 7열 신용카드거래처코드 | 앞자리 0 텍스트 |

**한 거래처가 아닌 라벨은 빈칸이 정상이다.** 임직원(급여 집합)·공단/세무서·다수(매입처)·
해외바이어 같은 것이다. 이때는 프로파일 `집합거래처` 에 **선언**해야 한다. 선언하지 않은 빈칸과
선언한 빈칸을 구분하지 못하면 누락을 영영 못 잡는다.

→ 프로파일 두 맵: `거래처별칭 = {라벨: 등기상호}` · `집합거래처 = {라벨, ...}`
→ 집행: `scripts/verify_upload.py` (아래 §4)

## 4) 업로드 사전검증 (올리기 전에 반려 사유를 먼저 잡는다)

```
python scripts/verify_upload.py <산출폴더> <기간> [profile_모듈]
```

더존 반려 메시지는 거칠다. 사업자번호가 텍스트라서 막힌 것과 거래처가 미등록이라 막힌 것이
같은 문구로 나온다. 그래서 양식 쪽은 올리기 전에 전부 본다. **이 스크립트가 이 문서의 집행부다.**
`close_folder.py` 4/5 단계로 들어가 있고, FAIL 이면 파이프라인이 멈춘다.

보는 것: 시트명·컬럼 순서·명칭 완전일치 / 숫자형이어야 할 열이 숫자형 / 거래처코드·신용카드
거래처코드가 텍스트(앞자리 0) / 구분·과세유형·매입매출구분 유효값 / 차변합=대변합 /
불공(54)에 6열 불공제사유 有 / 채권채무 거래처코드 채움 / 11열 사업자번호 채움·10자리 /
엔진이 남긴 거래처 미해소(`_거래처미해소_<기간>.json`).

**엄격도는 프로파일이 정한다.** `거래처별칭`·`집합거래처` 를 **하나라도 선언한 프로파일**은 남은
빈칸을 FAIL 로 본다. 둘 다 없는 프로파일은 빈칸이 의도인지 누락인지 판단할 근거가 없으므로
`[미설정]` 로 알리고 FAIL 로 단정하지 않는다. 두 맵을 채우면 그때부터 엄격해진다.

> ⚠ 현재 `profile_glowbeam` 만 두 맵을 채웠다. `profile_maisonbloom`·`profile_sample` 은 미설정이다
> (원천 자료 없이 정리해 이 자리에서 검증하지 못했다). 해당 회사 결산을 돌릴 때 라벨·마스터를 보고 채운다.
