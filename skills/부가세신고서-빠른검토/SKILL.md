# 부가세 신고서 빠른 검토

`부가세신고서검토` 의 간단판이다. 입력 두 개, 실행 한 줄, 결과 표 하나.

## 입력

| 입력 | 꼴 |
|---|---|
| 분개장 | 위하고 · 더존 전표 엑셀 변환본(.xlsx). 머리글에 `전표일자` · `계정과목` · `차변` · `대변`, 계정코드는 `계정과목` 바로 앞 열 |
| 신고서 | 홈택스 · 위하고에서 출력한 PDF(본지 + 첨부서식). 텍스트를 고를 수 있는 PDF 여야 한다(스캔본 불가) |

`.101` 전자신고파일은 암호화돼 읽지 못한다. 받지 않는다.

## 실행

```
python -I -X utf8 scripts/quick_review.py <분개장.xlsx> <신고서.pdf> [--md 결과.md]
python -I -X utf8 scripts/quick_review.py <폴더>
```

폴더를 주면 그 아래 xlsx 1개 · pdf 1개를 찾는다. 여러 개면 목록을 찍고 멈춘다. 필요한 패키지는 `openpyxl` · `pymupdf`.

## 검토 15항목

| # | 항목 | 무엇을 맞추나 |
|---|---|---|
| 1 | 식별 · 기간 | 쪽마다 사업자번호 · 기간이 같은지, 분개장 전표일자가 신고기간 안이고 달마다 전표가 있는지 |
| 2 | 분개장 차대 | 차변 합 = 대변 합, 전표별 차대, 합계행 건수 |
| 3 | 본지 산식 | (9) · (16) · (18) · ㉰ · (30) · (35) · (52)=(15) · (56)=(17) |
| 4 | 세율 10% | (1)~(4) · (10) · (12) · (15) · (17) 세액이 금액의 10% 인지. 허용 1,000원 또는 건수×10원. (15) 가 벗어나면 카드 을 명세에서 해당 행을 찾는다 |
| 5 | 매출 세금계산서합계표 | 합계표 = (1)+(5). 세액 차이가 매수 이하이면 통과(단수) |
| 6 | 매입 세금계산서합계표 | 합계표 = (10)+(12) |
| 7 | 카드수령명세서 | ④ = (44)+(45), ⑤~⑧ 합 = ④, 을 명세 합 = ⑧ |
| 8 | 불공제명세서 | ⑨ = (53), (17) = (53)+(54)+(55). 공통매입세액 안분 (54)가 있으면 (17)이 ⑨보다 크다 |
| 9 | 계산서합계표 | 매출 = (89), 매입 = (90) |
| 10 | 영세율 | 영세율매출명세서 ⑬ = (5)+(6), 수출실적명세서 ⑨ ≤ (6) |
| 11 | 매출세액 ↔ 예수금 | ㉮ = 부가세예수금 발생액(정리전표 제외). 차이가 정리전표 잡손실 · 잡이익과 같으면 그 사실을 적는다 |
| 12 | 매입세액 ↔ 대급금 | ㉯ = 부가세대급금 발생액 |
| 13 | 과세표준 ↔ 매출계정 | (1)~(4) = 예수금 있는 전표의 매출계정 + 매출계정 없는 예수금×10, (5)+(6)+(85)+(86) = 예수금 없는 매출, (34) = 매출계정 없는 과세분 |
| 14 | 고정자산 | 유형자산 취득이 있는데 (12)·(45) 가 0, 매각 전표에 예수금이 없음. 토지 매각은 참고로만 |
| 15 | 정리분개 · 납부세액 | 정리전표가 있고, 예수금 · 대급금 발생액을 다 정리했고, 미지급세금 = (30) |

판정은 `통과` · `통과(단수)` · `확인필요` · `해당없음`(값도 서식도 없음) · `못읽음`(통과 아님) 다섯이다. 본지 1쪽을 못 찾으면 3~15번은 모두 `못읽음` 이다.

## AI 1차 검토

스크립트는 대조만 한다. 불공제 · 영세율 · 공통매입 · 차이 원인은 Claude 가 1차로 보고, 자료에 없는 사실만 회계사에게 남긴다. `--ai` 를 붙여 돌리면 표 아래에 「AI 1차 검토 자료」 A~D 가 나온다.

```
python -I -X utf8 scripts/quick_review.py <분개장.xlsx> <신고서.pdf> --ai
```

| 자료 | 스크립트가 모은 것 | Claude 가 판단할 것 |
|---|---|---|
| A. 불공제 후보 | 부가세대급금이 붙은 전표 중 계정(업무추진 · 차량 · 여비교통 · 기부 · 토지)이나 거래처 · 적요(택시 · 모빌리티 · 도로공사 · 대리운전 · 항공 · 철도 · 주차 · 골프 · 상품권)가 걸린 것, 신고서 불공제명세 | 거래처 · 적요로 거래 내용을 읽어 「문제 없음」 · 「불공제로 옮길 후보」 · 「회계사 확인」 중 하나로. 택시 등 여객운송 카드 매입, 비영업용 소형승용차 관련 비용(통행료 · 대리운전 · 주유 · 렌트), 접대 관련 매입이 공제로 들어갔으면 후보다. 차량 관련은 그 차가 영업용인지가 분개장에 없으니 회계사 확인으로 남긴다. 거꾸로 차량유지비 · 리스료가 대급금 없이 처리된 것은 불공제로 이미 처리된 것이니 건드리지 않는다 |
| B. 수출 | 수출실적명세서 행마다 외화 × 환율 재계산, 장부의 예수금 없는 매출 | 원화 차이가 있으면 선적 전 환가(받은 날 환율로 적음)인지, 선적일 기준환율과 맞는지를 회계사 질문으로. 장부 전표일과 선적일이 다르면 공급시기 확인. 본지 (5)(6) 공란이면 고칠 후보 |
| C. 공통매입세액 | 면세수입금액과 면세비율, 불공제명세서 3. 안분 칸이 비었는지 | 면세 매출이 있는데 안분 칸이 비었으면 「회계사 확인」. 면세 매출이 토지 매각처럼 한 번뿐인 거래면 안분 계산에 넣는지가 쟁점이니 그 사실을 적는다 |
| D. 확인필요 · 차이 | 15항목 중 확인필요 · 차이 남은 항목과 상세 | 항목마다 원인 가설 하나와 회사에 물을 것 한 줄. 단수 차이, 정리전표 잡손실, 불공제분이 대급금에 남음, 예정신고 누락분처럼 차이가 남아야 맞는 경우는 그 까닭을 적고 「문제 없음」 |

지킬 것

- 스크립트 숫자를 고치거나 다시 계산하지 않는다. 판단에 쓴 전표는 날짜 · 번호로 적는다.
- 조문 번호 · 세율 · 가산세율을 적어야 하면 `세법자문-회신` 규약(TaxDoctor · korean-law 원문)으로만 적는다. 근거를 열지 못했으면 조문 없이 「회계사 확인」으로 남긴다.
- 가산세 금액은 계산하지 않는다.

## 보고

1. 스크립트 15항목 표를 그대로 보인다.
2. 「AI 1차 검토」 표 하나: `구분 · 대상(전표나 서식) · 판단 · 근거 · 회계사에게 남길 질문`. 판단은 `문제 없음` · `고칠 후보` · `회계사 확인` 셋이다.
3. 마지막에 세 줄로 나눈다. 스크립트가 맞춘 것, AI 가 1차로 본 것, 회계사가 확인할 사실(자료에 없는 것: 차종 · 용도 · 계약 실질 · 서류 원본)과 서명.
4. 이 검토가 보지 않는 것(아래 표)을 한 줄로 적는다.

## 예외 기록

- 합계표의 금액은 PDF 에서 낱자로 나온다. x 간격이 가장 큰 곳에서 공급가액과 세액을 자르고, 세액이 공급가액의 5~15% 를 벗어나면 `못읽음` 으로 둔다.
- 본지 란 번호는 앞 글자에 붙어 나온다(`입(10)`, `액(15)`). 낱말 끝의 `(n)` 을 먼저 찾는다.
- 카드 갑 쪽 각주에 「수령명세서(을)」, 을 쪽 각주에 「(갑)」이 있다. 쪽 종류는 위 세 줄로만 판별한다.
- 본지 매출세액은 공급가액×10% 를 절사해 적고 장부는 건별 세액 합이라 몇십 원 차이가 난다. 회사가 정리전표 잡손실로 맞추면 11번은 `통과(단수)` 다.
- 분개장 마지막 `합계 (건수 : n )` 행은 자료에서 빼고 건수 대조에만 쓴다. `Code` 열이 둘이라 열 위치로 읽는다.
- 본지 2장 머리는 위하고가 「(2장앞쪽)」, 2026. 3. 20. 서식 원본이 「(6쪽(제2장중제4쪽)앞쪽)」 이다. 둘 다 본지2 로 읽는다(11-17).
- 서식 원본에 값을 얹은 PDF 는 금액이 칸 이름보다 1~2pt 위에서 시작해 윗변으로 줄을 묶으면 금액이 윗줄로 붙는다. 본지는 윗변 묶음으로 먼저 읽고, 못 읽은 란만 높이 가운데 묶음으로 한 번 더 채운다. 처음부터 가운데 묶음으로 바꾸면 위하고 출력물의 (31) · 합계표가 깨진다(11-17 실제 출력물로 확인).
- 합계표 「합 계」 가 두 낱말로 나오고 금액이 쉼표 숫자 둘로 나오는 서식도 읽는다(11-17).
- 서식 이름이 없는 이어지는 쪽(거래처 명세만 있는 쪽)에서는 사업자번호를 읽지 않는다. 첫 번호가 거래처 것이라 1번 식별이 틀린다(11-17).
