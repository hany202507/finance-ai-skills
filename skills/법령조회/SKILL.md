# 법령조회: 근거 조문을 두 곳에서 확인한다

법령을 조회하는 방법만 다룬다. 무엇을 검토할지(쟁점, 회신 양식)는 부르는 스킬이 정한다. 지금은 `양도소득세` 가 쓴다.

이 스킬이 막으려는 실패는 둘이다. 하나는 **다른 판·다른 법의 조문을 근거로 쓰는 것**이고, 다른 하나는 **조회하지 못한 것을 없는 것으로 적는 것**이다.

## 출처 순서

| 순서 | 출처 | 쓰는 곳 |
|---|---|---|
| 1 | TaxDoctor (`get_article`, `search_tax`, `list_upcoming`, `get_annex`, `search_interpretations`, `search_cases`) | 세법 90개의 조문 원문, 위임 하위법령 목록, 과거 시점 검증판(`as_of`), 해석례·판례 |
| 2 | korean-law (`get_law_text`, `scan_articles`, `get_addenda`, `trace_references`, `amendment_track`, `search_rulings`, `get_ruling`, `search_forms`) | 세법 조문 대조, 비세법 전부, 부칙, 내용 검색, 위임 추적, 개정 이력, 조세심판원 본문 |
| 3 | 법제처API (`mcp.gomdori.app/law`: `get_law_text`, `get_annexes`) | 별표 표(HTML), 행정규칙 첨부, 위 둘이 실패할 때 |
| 4 | 웹 | 고시·공고(관보 `gwanbo.go.kr`), 정부 개정안처럼 법령 DB 에 없는 것. 법령 원문을 웹으로 대신하지 않는다 |

시작할 때 살아 있는지 한 번씩 확인한다. TaxDoctor 는 `list_laws`, korean-law 는 `search_law("국세기본법")`. 둘 다 죽어 있으면 웹으로 잠정 조사하고 결과 첫 줄에 「법령 원문 미검증」을 적는다. TaxDoctor 가 없는 사용자는 korean-law 가 1차다.

도구 이름이 `mcp__<id>__get_article` 꼴이고 세션마다 id 가 다르다. 이름을 외우지 말고 ToolSearch 로 `get_article search_tax`, `korean-law` 를 찾는다.

## 질문별 도구

| 알고 싶은 것 | 먼저 | 이어서 | 주의 |
|---|---|---|---|
| 이 조문의 원문 | TaxDoctor `get_article` | korean-law `get_law_text` 같은 판 | 머리줄 법령명이 요청과 같은지 본다. TaxDoctor 는 삭제 조문을 다른 법령의 같은 번호로 답한 적이 있다 |
| 내용으로 조문 찾기 | korean-law `scan_articles` | TaxDoctor `search_tax` | `search_law` 는 법령명 전용이라 내용 키워드는 0건이다 |
| 언제부터 적용되나 | korean-law `get_addenda(keywords=["적용례","경과조치"])` | TaxDoctor `search_tax` 의 `as_of` | 조문에는 없다. 부칙에만 있다. 비어 와도 「부칙 없음」이 아니다 |
| 위임 받은 하위 조문 | TaxDoctor `get_article` 의 위임 목록 | korean-law `trace_references` | TaxDoctor 위임 목록은 빠질 때가 있다(제95조 → 시행령 제159조의4·제160조). 둘을 합친다 |
| 과거 시점 조문 | korean-law `get_law_text(effective_date)` | TaxDoctor `search_tax(as_of)` | 그 날 시행 중이던 판을 읽는다 |
| 시행예정 개정 | korean-law `amendment_track` → `get_law_text(mst, effective_date=시행일)` | TaxDoctor `list_upcoming` | TaxDoctor 시행예정 본문은 약 2,000자에서 잘리고 상태 표시가 낡을 때가 있다. 힌트로만 쓴다 |
| 세법이 아닌 법령 | korean-law `get_law_text` | 법제처API | TaxDoctor 에 없다(주택법, 민간임대주택법 등) |
| 별표·서식 | TaxDoctor `get_annex` | 법제처API `get_annexes`, korean-law `search_forms` | 서식 란 번호는 원본 PDF·HWP 로 확인한다 |
| 고시·공고 | 법제처 행정규칙 연혁 | 관보 검색 | 지역 목록은 첨부 PDF 에만 있다 |
| 해석·쟁점 | korean-law `search_rulings` → 조세심판원 `get_ruling` | TaxDoctor `search_interpretations`·`search_cases` | 심판례는 본문이 온다. 예규는 목록만 오므로 taxlaw 링크를 열어 본문을 읽은 것만 인용한다 |

## 대조 규칙과 등급

| 등급 | 조건 |
|---|---|
| ★★★ | 원문을 두 곳에서 읽었고 같다. 그중 하나가 law.go.kr URL 을 준 korean-law 또는 법제처API 다 |
| ★★☆ | 원문은 한 곳에서만 읽었다. 또는 2차 자료(보도자료, 해설)로만 확인했다 |
| ☆ | 확인하지 못했다 |

- 위 등급은 법령 조문에 붙인다. 심판례·해석례·예규는 본문을 읽고 출처 링크를 그대로 옮겼으면 ★★★, 목록·제목만 봤으면 ★★☆ 다
- 결론에 쓰는 조문은 ★★★ 이어야 한다. ★★☆ 나 ☆ 가 하나라도 있으면 결론 옆에 적는다
- 두 곳이 같은 판인지는 `MST@시행일` 로 본다. TaxDoctor 원천 스냅샷 `moleg-eflaw:<MST>@<시행일>` 이 korean-law 머리의 `MST`·`시행일` 과 같아야 한다
- 원문이 다르면 쓰지 않고 그 사실을 보고한다. 어느 쪽이 맞는지 추측하지 않는다
- URL 은 도구가 준 것을 그대로 옮긴다. 조립하지 않는다

## 절차

1. **생존 확인.** 위 「출처 순서」 끝 문단
2. **조문 특정.** 쟁점 키워드로 `scan_articles` 를 돌린다. 법 하나만 보지 않는다. 세목법과 그 시행령·시행규칙, 조세특례제한법을 늘 넣는다. 훑기 실패가 난 법령은 「검토하지 않음」으로 적는다
3. **원문 두 곳.** 잡힌 조문을 TaxDoctor 와 korean-law 로 같은 판을 읽는다. 항·호·목까지 좁혀 인용한다
4. **조문 끝까지 읽기.** 단서, 괄호, 「다만」, 「각 호의 어느 하나」, 표 안의 목을 빼지 않는다. 같은 조 안에서 놓치는 일이 가장 잦다
5. **부칙.** 개정이 걸린 조문이면 `get_addenda` 로 적용례·경과조치를 본다. 조문의 판정 기준일과 부칙의 적용 기준일은 다를 수 있다
6. **위임.** TaxDoctor 위임 목록과 `trace_references` 를 합쳐 하위 조문을 연다. `trace_references` 가 알려 주는 모호참조 건수만큼은 본문을 직접 읽는다
7. **세법이 아닌 근거.** 세법 본문이 「」 로 인용한 법령은 korean-law 로 연다. 옛 이름이면 부르는 스킬의 `법령별칭.json` 으로 현행 이름을 찾는다. 고시·공고는 행정규칙 연혁과 관보로 본다
8. **해석.** 조세심판원부터 본다. 예규는 과세관청 시각을 보강하는 데 쓰고, 조문과 어긋나면 `[불일치]` 로 남긴다
9. **인용 전수검증.** 결과에 쓴 조문번호를 전부 뽑아, 초안을 보지 않은 서브에이전트에게 조문번호와 「이 취지로 인용했다」 한 줄만 주고 원문과 맞는지 판정받는다. 판정은 `일치` / `불일치(무엇이)` / `존재하지 않음`. 존재하지 않는 조문은 지운다

## 반환 형식

조회 결과는 부르는 스킬에 이 형식으로 넘긴다.

```json
{
  "법령": "소득세법 시행령",
  "조항": "제155조 제1항 제1호",
  "시행일": "2026-10-01",
  "판": "290841@20261001",
  "발췌": "도구가 준 문장 그대로. 줄인 곳은 … 로 표시",
  "URL": "korean-law 가 준 law.go.kr 링크",
  "출처": ["TaxDoctor get_article", "korean-law get_law_text"],
  "등급": "★★★"
}
```

## 법령 목록과 누락 검사

주제마다 필요한 법령을 목록으로 고정하고, 그 목록의 법령이 모두 조회되는지 기계로 확인한다. 목록은 그 주제 스킬이 갖는다(`양도소득세/rules/법령목록.json`, `법령별칭.json`).

```bash
python scripts/coverage_check.py --목록 <주제스킬>/rules/법령목록.json --별칭 <주제스킬>/rules/법령별칭.json --출력 <주제스킬>/rules/누락검사.json
```

- 법령마다 이름이 정확히 같은 현행 판(MST·시행일)을 법제처에서 찾는다. 세법은 TaxDoctor 수록 여부도 적는다
- 옛 이름은 별칭의 현행 이름으로 찾는다. 법령이 아닌 것(협약 등)은 근거가 적혀 있으면 해소로 본다
- 고시 중 행정규칙ID 가 있는 것은 법제처 행정규칙에서 그 ID 를 찾는다. 부동산마다 따로 확인하는 사실은 확인처가 적혀 있어야 한다
- 해소되지 않은 항목이 하나라도 있으면 종료코드 1 이다. OC 는 환경변수 `LAW_OC` 또는 `claude mcp get korean-law` 에서 읽고 출력하지 않는다

## 빨간 신호

| 떠오른 생각 | 실제 |
|---|---|
| "TaxDoctor 에 나왔으니 됐다" | 한 곳이면 ★★☆ 다. korean-law 로 같은 판을 열어 대조한다 |
| "검색했더니 비슷한 법이 나왔다" | 이름이 정확히 같은지 본다. 「주택법」 조회에 민간임대주택법이 나온 적이 있다 |
| "날짜를 안 줬으니 현행이다" | 고치기 전 korean-law 는 시행 전 개정이 섞인 공포본을 줬다. 머리의 `시행일` 이 오늘 이전인지 본다 |
| "위임 목록에 없으니 하위 조문이 없다" | TaxDoctor 위임 목록은 빠진다. `trace_references` 를 같이 돌린다 |
| "부칙 조회가 비었으니 적용례가 없다" | 원문을 직접 열거나 「부칙 미확인」으로 남긴다 |
| "세법이 아니니 조회하지 않아도 된다" | 세법이 인용한 법령은 판정에 쓰인다. korean-law 로 연다 |
| "웹에 잘 정리돼 있다" | 법령 원문을 웹으로 대신하지 않는다. 웹은 ★★☆ 다 |
| "링크는 이렇게 생겼을 것" | 도구가 준 URL 만 쓴다 |

출처별 결함과 대응의 전체 목록은 `references/출처별결함.md` 에 있다.
