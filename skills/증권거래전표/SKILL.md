# 증권거래전표

증권사 거래내역 파일 → 표준거래표 → 원장 계산 → 전표 · 위하고 업로드.

양식은 증권사마다 달라도 한 거래에서 뽑을 것은 같다. 날짜, 무슨 거래인지, 종목, 수량, 금액, 비용, 통화, 잔액이다. 행마다 무슨 거래인지 보고 읽는다. 금액이 예상과 다른 칸에 들어 있거나(현지세를 비용 칸에), 시장을 「미국」 으로 적었거나, 대금이 그날 합계 한 행으로 오더라도 실제 거래대로 전표가 나와야 한다. 읽은 결과는 증권사 잔액(원화 · 외화 · 보유수량)과 줄마다 맞춰 보고, 안 맞으면 읽은 값부터 다시 본다(2026-11-08).

| 맡는 쪽 | 일 |
|---|---|
| 엔진(`scripts/`) | 파일 읽기, 머리글 맞추기, 이벤트 분류, 이동평균 원가, 외화 장부금액, 분개, 증권사 잔액 대사, 수식 워크북, 재계산 대조 |
| AI(이 세션) | 스캔 PDF 를 쪽 이미지로 읽어 표준거래표로 옮겨 적기, 새 머리글·적요를 사전에 넣기, 확인사항 정리 |
| 회계사 | 계정코드, 기초 장부금액, 기말 단가, 검토대기(타사 대체 입출고 · 돈이 오가는 기업행위), 기말 미수배당 · 결제일 자료의 연말 미결제 매매, 세무조정 |

대상은 법인이다. 개인(양도소득세)은 다루지 않는다. 세무조정 · 채권 · 펀드 · 해외직접투자는 다루지 않는다. 이 스킬은 국내 · 미국 주식, 예수금, 배당, 기말 평가를 맡는다.

## 설치와 시험해 보기

설치 스크립트로 받으면 `requirements.txt`(openpyxl · xlrd · pdfplumber)까지 깔린다. 스캔 PDF · 화면 캡처를 읽으려면 스킬 폴더에서 `pip install -r requirements-ocr.txt` 를 한 번 더 실행한다(수백 MB, 엑셀 · 글자 있는 PDF 만 쓰면 필요 없다).

1. 설치 확인: `python scripts/check_env.py`. 파이썬 패키지, Excel 또는 LibreOffice(수식 재계산 · 위하고 업로드 파일), Node.js(kordoc), OCR 패키지가 있는지 표로 나온다. 거래 자료는 읽지 않는다.
2. 시험해 보기: 회사 증권계좌 거래내역 한 달치(엑셀이나 PDF)로 시작한다. Claude 에게 이렇게 요청한다.

   > 「`<파일 경로>` 증권거래전표로 만들어줘. 회사는 ○○, 기간은 2026년 1월, 기초 잔고는 없는 것으로.」

   기초 잔고를 비우면 거래내역에서 역산하고 「기초 추정」 으로 표시한다. 실행보고의 검산 표가 모두 OK 인지, `[대사]` 가 0 인지 본다. 잔액이 안 맞으면 읽은 값부터 확인하고, 보고의 「못 맞춘 머리글」 · `[미분류]` 를 본다.

이 스킬에는 예시 파일과 시험 자료가 들어 있지 않다.

## 1. 받을 자료

| 자료 | 필수 | 비고 |
|---|---|---|
| 증권사 거래내역(기간 전체, 원화·외화 함께) | 필수 | 엑셀·CSV·xls(HTML 포함)·PDF. 한 줄 보기 · 외화 포함으로 받는다(KB 간편내역은 외화가 빠진다) |
| 전기말 잔고: 원화예수금, 외화예수금(외화·장부금액), 종목별 수량·장부금액 | 필수 | 전기 계정명세서 또는 이 스킬의 전기 워크북 `기초` 시트 |
| 기말 잔고증명서(종목별 단가) | 기말 평가 때 | 단가는 잔고증명서 값을 쓴다 |
| 회사 계정과목표 | 첫 회 | 기본값은 더존 3자리 초안(`engine.DEFAULT_ACCOUNTS`) |

증권사별 머리글 · 적요는 `references/머리글사전.json` · `references/적요사전.json` 에 있다. 받을 때 안내할 것: 키움은 영웅문 [0365]/[3110] 또는 홈페이지 CSV, 한국투자는 결제일 다음 날 이후에 받는다(그 전 원화 금액은 예상환율), 대신증권 HTS 의 .xls 는 내용이 `.files` 폴더에 따로 있어 그 폴더와 함께 받는다.

## 2. 실행 순서

```bash
# 1) 환율표: 첫 거래 직전부터 기말까지 ECOS 일별 매매기준율(키는 ECOS_API_KEY, 없으면 공개 sample 키로 나눠 받음)
python scripts/fetch_rates.py --start 2026-01-01 --end 2026-12-31 --ccy USD -o 환율표.csv

# 2) 설정 JSON(회사·분류·기초·기말·계정). 기초를 비워 두면 거래내역에서 역산하고 확인사항에 적는다
# 3) 실행
python scripts/run.py <거래내역 파일...> --out <산출폴더> --config 설정.json --rates 환율표.csv

# 암호 걸린 PDF(키움: 사업자번호, 미래에셋 거래내역증명서 등)는 비밀번호를 넘긴다. 파일·보고서에 남지 않는다
python scripts/run.py 거래내역증명서.pdf --password <비밀번호> --out <산출폴더> --config 설정.json --rates 환율표.csv
```

설정 예:

```json
{"회사": "가상상사", "증권사": "삼성증권", "분류": "단기매매",
 "기초": {"원화예수금": 13, "외화": {"USD": {"잔액": 352.55, "장부금액": 505874}},
          "종목": [{"종목": "가상 미국 ETF", "통화": "USD", "수량": 100, "장부금액": 70000000}]},
 "기말": {"일자": "2026-12-31", "환율": {"USD": 1480.0}, "단가": {"가상 미국 ETF": 520.5}, "단가출처": "잔고증명서 2026-12-31"},
 "계정": {"원화예수금": ["103", "보통예금"], "해외원천세": ["136", "선납세금"]},
 "거래처코드": {"삼성증권": "00101"},
 "계좌주체": "법인",
 "머리글": {"정산후금액": "정산금액"},
 "적요규칙": [{"pattern": "해외주식매수결제", "event": "매수", "통화": "외화"}]}
```

`머리글` · `적요규칙` 은 사전에 없는 양식을 코드 수정 없이 읽게 한다(사전보다 먼저 맞춘다). 표준열 이름은 `references/머리글사전.json` 의 `fields` 키, 이벤트 이름은 `references/적요사전.json` 의 `event` 값이다.

종료코드 0 은 검산 통과, 2 는 확인필요 남음, 3 은 중단 사유(환율 없음·보유보다 많은 매도·수식 오류)다. 3 이면 산출물을 넘기지 않는다.

### PDF · 스캔 · 화면 캡처(OCR)

`run.py` 에 PDF 나 이미지(png·jpg·tif·webp·gif)를 그대로 넣는다. PDF 는 읽는 방법 후보를 차례로 전표까지 돌려 보고, 중단 → 대사·미분류 → 종목명 빈 매매 순으로 가장 적은 결과를 쓴다(셋 다 0건이면 거기서 멈춘다). 실행보고 첫머리에 「PDF 읽기: ○○ 선택 (시도: …)」으로 후보별 결과가 남는다.

1. 글자가 들어 있는 PDF: kordoc → pdfplumber. 미래에셋 거래내역증명서 실물 127쪽에서 둘 다 전표 대사 0이었지만, kordoc 은 3줄 1건 표에서 종목명을 31건 빠뜨려 pdfplumber 가 뽑혔다. odl-pdf(2.5.10)는 숫자 칸을 27% 놓쳐 후보에서 뺐다.
2. 스캔 PDF·이미지: `scripts/ocr_table.py`(자체 OCR) → kordoc `--ocr`. 같은 실물을 이미지로만 만든 스캔본 127쪽에서 자체 OCR 은 전표 대사 0(위하고 1,155줄이 글자층 결과와 일자·계정·금액까지 같다), kordoc OCR 은 거래 수부터 틀리고(469건) 대사 410건이었다.
   - OCR 로 읽은 표는 금액을 두 번 바로잡는다(`normalize.repair_in_row` · `repair_by_balance`). 외화 금액·단가는 같은 행의 수량 × 단가, 금액 ± 비용 = 입출금액으로, 원화 금액은 증권사 잔액 변동으로 맞춘다. 10·100·1000 배 어긋난 값만 고치고, 고친 거래에는 「OCR 행 교정」·「OCR 잔액 교정」 메모가 붙는다. 127쪽 실물에서 틀린 칸 58개(1,000,000 → 1,00,000, 외화 소수점을 쉼표로 읽은 것)가 이것으로 다 잡혔다.
   - OCR 종목명 교정은 종목코드가 다르거나 이름 속 숫자가 다르면 합치지 않는다(같은 운용사의 레버리지 3X ETF 와 2X ETF).
   - 127쪽 자체 OCR 은 57분, kordoc OCR 은 41분 걸린다. 큰 스캔본은 백그라운드로 돌린다.
   - 엔진은 RapidOCR(PaddleOCR PP-OCRv5 한국어, CPU)이 기본이다. 없으면 `pip install rapidocr` 로 설치한다. Tesseract(kor) 는 RapidOCR 이 없을 때 쓴다.
   - 숫자 칸은 두 엔진이 함께 읽는다. RapidOCR 값을 기본으로 두고, 그 값이 같은 열의 숫자 꼴·소수 자릿수에 안 맞을 때만 Tesseract 값으로 바꾼다(두 값의 숫자 배열이 70% 이상 같을 때). 날짜와 글 열은 바꾸지 않는다.
   - 전처리: 잡음 제거, 폭 2,400px 까지 확대(최대 4배), 기울기 보정, 밝기 얼룩 보정.
   - 칸선이 다 있는 표는 칸을 잘라 칸 안 글자 줄마다 읽는다. 세로선은 행마다 따로 찾는다(셀 병합이 많은 양식은 표 전체를 잇는 세로선이 몇 개뿐이다). 바깥 테두리가 안 잡히면 가로선 양 끝으로 보충하고, 세로선 검출 길이는 줄 높이의 70% 로 잡아 한 줄 높이 칸막이도 지운다. HTS 화면처럼 가로선이 없는 표는 글자 상자를 찾아 줄·열로 묶는다.
   - 숫자 열 보정(쉼표·마침표, o→0), 날짜에 붙은 거래번호 떼기, 기호 줄 버리기, 머리글·적요·종목명 오타 교정(자모 유사도)을 한다. 바꾼 것은 확인사항에 남긴다.
   - 글자 높이가 6px 미만이거나, PDF 안 이미지의 실제 해상도가 150ppi 미만이면 품질 경고를 낸다. 다시 스캔(300dpi 이상)하거나 증권사에서 원본을 받는다. 89ppi 이미지로 된 한국투자 계산내역 견본은 두 엔진 모두 숫자를 거의 못 읽었다.
3. 그래도 머리글을 못 찾거나 잔액 열이 없는 표는 AI 가 쪽 이미지를 읽어 옮겨 적는다.
   - `python scripts/pdf_pages.py <PDF> <폴더>` 로 300dpi 쪽 이미지를 만든다(쪽마다 위·아래 반씩).
   - 이미지를 차례로 읽어 `templates/표준거래표_양식.csv` 꼴로 옮겨 적는다. 증권사 잔액 칸(현금잔액·외화예수금·잔고수량)을 꼭 함께 적는다.
   - `python scripts/run.py 표준거래표.csv --standard --out ... --config ... --rates ...`

OCR 로 읽은 자료는 잔액 대사로 최종 판정한다. 엔진이 줄마다 잔액을 다시 계산하므로 잘못 읽은 숫자는 `[대사]` 차이로 잡힌다. `[대사]` 가 0 이어도 실행보고의 의심 칸은 원본과 한 번 대조한다. 잔액 열이 없는 화면(매매일지 등)은 대사로 오판독을 못 잡으니 OCR 결과로 전표를 만들지 않는다.

측정치(2026-11-07, 숫자 정확도): 미래에셋 거래내역증명서 실물(127쪽, 거래 450건) 글자층 pdfplumber · kordoc 전표 대사 0. 같은 실물 스캔본 127쪽 자체 OCR 전표 대사 0(교정 전 잔액 불일치 291건). 한국투자 홈페이지 캡처 100%, 한국투자 HTS 견본 96.4%, 미래에셋 HTS 견본 82.1~92.9%, 가상 스캔 300dpi·기울기 100%, 200dpi 팩스 100%. 증권사가 낸 실제 PDF(결합 판독): IBKR Trades 100%, Schwab 거래 상세 86.8%(틀린 5건은 수량 괄호 부호라 전표 금액에 영향 없음), IBKR 체결확인서 66.7%(96ppi 경고), 한국투자 계산내역 4.7%(89ppi 경고). 영문 명세서(IBKR·Schwab)는 숫자는 읽지만 머리글·적요 사전이 없어 전표 단계에서 멈춘다.

표준거래표 열: 일자 · 결제일 · 원문거래종류 · 이벤트(비우면 적요사전으로 분류) · 시장 · 종목코드 · 종목명 · 통화 · 수량 · 단가 · 외화총액 · 외화비용 · 원화금액 · 원화비용 · 증권사원화잔액 · 증권사외화잔액 · 증권사잔고수량 · 상대방. 금액은 모두 양수로 적고 방향은 이벤트가 정한다. 외화총액은 체결금액(배당은 세전), 외화비용은 수수료·SEC fee·현지세다.

워크북에서 기초 장부금액·기말 단가·계정코드를 고치면 원장·전표가 다시 계산된다. 다만 위하고 업로드 파일은 다시 `run.py` 를 돌려야 바뀐다.

위하고 올릴 때: 변환옵션 기본값(계정코드 기준·거래처 기준) 유지, 다시 올릴 때는 자동분개 일괄검색 및 삭제로 먼저 지운다. 결산 평가 줄은 적요 앞에 `[결산]` 을 붙여 기말일로 낸다. 외화 금액은 업로드 열이 없어 워크북 거래원장으로 관리한다.

업로드 파일은 `scripts/wehago_upload.py` 가 쓰고 올리기 전에 검사한다. 결과는 실행보고 「위하고 업로드」 표에 있고, 반려가 하나라도 있으면 종료코드 3 이다.

## 4. 처리 기준

분개표와 판단 항목은 [references/분개규칙.md](references/분개규칙.md). 요점:

- 원가는 종목별 이동평균, 외화예수금은 통화별 이동평균 장부금액. 해외 매수·매도 원화 금액은 거래일 매매기준율(환율표), 환전은 실제 환율.
- 처분손익 = 비용을 뺀 처분대가 − 이동평균 원가. 매수 수수료는 지급수수료(비용)로 처리한다.
- 분류는 단기매매증권(일반기업회계기준) = 당기손익-공정가치측정 금융자산(K-IFRS 1109)만 처리한다. 두 기준은 회계처리가 같고 계정 이름만 달라서, IFRS 회사는 설정 `계정` 에서 이름을 바꾼다. 매도가능증권 · 기타포괄손익-공정가치측정 지분은 엔진에 처분 시 평가손익 누계를 처리하는 규칙이 없어 실행을 멈춘다(2026-11-08). 필요하면 업데이트를 요청한다.
- 해외 배당은 세전 총액을 배당금수익, 현지세를 법인세등(외국납부세액공제 대상, 법인세법 제57조①)으로 둔다.
- 증권사가 배당 입금과 현지세 출금을 두 행으로 내면 합친다. 사이에 같은 통화를 움직인 행이 끼어 있으면 합치지 않고 현지세를 따로 전표로 낸다(줄마다 잔액 대사가 맞도록).
- 미래에셋 매수입고+매수출금, 환전 원화 행·외화 행 짝, 키움 분할체결(마지막 행에만 정산금액), 키움 환전정산입금은 엔진이 자동으로 합치거나 조정한다.
- 무상증자 · 주식배당 · 액면분할 · 병합 · 감자 · 합병 · 교환처럼 수량만 바뀌는 기업행위는 전표 없이 수량만 바꾸고 장부금액은 그대로 둔다. 종목코드가 바뀌면 같은 날 출고 행의 장부금액을 입고 행으로 옮긴다. 합병은 공정가치로 다시 잡으라는 확인사항이 붙는다.
- 유상청약 · 단주대금처럼 돈이 오가는 기업행위와 규칙에 없는 입출금은 가수금 · 가지급금으로 기표하고 확인사항에 올린다. 타사 대체 입출고는 전표를 내지 않고 검토대기로 둔다.
- 인식일은 체결일이다(일반기업회계기준 6.4의2, 법인세법 시행령 제68조①5호). 파일에 체결일 · 매매일 칸이 있으면 그 칸을 일자로 쓴다.
- 국내 ETF · 투자신탁 분배금과 예탁금이용료(원화 · 외화)의 원천세는 선납세금, 해외 배당 현지세는 법인세등이다. 처리마다 회계기준 문단과 세법 조문을 붙인 검토 결과(2026-11-08)가 분개규칙.md 끝에 있다.
- 기말 미수배당, 결제일 자료의 연말 미결제 매매, 세무조정(평가손익 · 외화환산 · 수입배당금 익금불산입 · 의제배당)은 전표에 넣지 않고 확인사항에 고정으로 올린다.

## 5. 검증

### 자료 진단(검산 전에 보는 것)

`scripts/diagnose.py` 가 실행할 때마다 받은 자료로 무엇을 검증할 수 있고 무엇이 빠졌는지 판정해 실행보고 첫머리 「자료 진단」 과 워크북 `자료진단` 시트에 낸다. 「위험」 이 있으면 검산이 모두 OK 여도 결과를 그대로 쓰지 않는다(종료코드 2).

| 항목 | 위험 · 확인이 뜨는 경우 |
|---|---|
| 읽은 방법 | OCR 이면 확인. 교정 건수와 원본 대조 안내 |
| 잔액 열(대사 수단) | 원화 · 외화 잔액과 보유수량 열이 하나도 없으면 위험(잘못 읽은 숫자를 잡을 수단이 없다). 잔액이 없는 날이 10% 넘으면 확인 |
| 일자의 뜻 | 체결일 칸이 없으면 확인 |
| 기초 장부금액 | 기초 수량만 있고 장부금액이 0 이면 위험(처분이익이 부풀려진다) |
| 계좌 주체 | 법인 설정인데 상장주식 배당에 원천세가 찍혀 있으면 확인(개인 계좌 자료일 수 있다) |
| 못 읽은 것 | 미분류 · 검토대기, 못 맞춘 머리글 |
| 기간 · 통화 | 외화 거래에 환율표가 없으면 위험, 기말일이 없으면 확인 |

양식 · 읽는 방법에 따라 전표가 틀어지는 경우(OCR 자릿수 누락 · 소수점↔쉼표 · 숫자 닮은 글자, kordoc 종목명 누락, 묶음 대금행 등)와 스킬이 잡는 방법은 [references/자료차이.md](references/자료차이.md) 에 있다.

### 검산

워크북 `검산` 시트가 아래를 판정한다. 모두 OK 여야 넘긴다.

1. 전표 차변 − 대변 = 0, 거래별 차대 일치
2. 원화예수금 잔액 = 증권사 현금잔액(줄마다)
3. 외화예수금 잔액 = 증권사 외화예수금(줄마다)
4. 보유수량 = 증권사 잔고수량(매매 줄마다)
5. 엔진(`engine.py`, Decimal) 값 = 엑셀 수식 값(원장 12개 열, 행마다)
6. 환율 없는 외화 거래 0, 검토대기 0, 가계정 0, 장부금액 없는 기초 보유 종목 0, 기말 단가 미입력 0
7. 수식 오류(#REF!·#VALUE! 등) 0. `run.py` 가 Excel(없으면 LibreOffice)로 재계산해 확인한다

계산 엔진은 공개 전에 독립된 정답과 맞춰 봤다(2026-11-08). 엔진 코드를 열지 않은 에이전트가 `references/분개규칙.md` 만 보고 정답 계산기와 사례 16개(분할매도 · 같은 날 매수 · 매도 · 기초 보유분 매도 · 여러 환율 환전 뒤 매수 · 환율 급변 · 배당 현지세 환급 · 소수점 수량 · 기초 외화 · 평가 혼합 · 환산 · x.5원 반올림 등)를 만들었다. 결과는 계정 순액 16/16, 거래별 전표 줄 95묶음이 모두 같다. 이 대조는 엔진이 분개규칙.md 를 문서와 같게 해석하는지만 본다.

PASS 는 계산과 대사만 본다. 원천 자료가 맞는지, 계정 분류·기초 장부금액·기말 단가가 맞는지는 보지 않는다. 보고할 때 이 문장을 함께 적는다.

같은 가상 거래를 삼성 · 키움 · 미래에셋 · KB · 표준거래표 다섯 꼴로 넣어 계정별 순액이 같은지, 엔진 없이 손으로 푼 답과 같은지도 시험했다. 시험 코드와 시험 자료는 이 배포에 싣지 않는다.

## 6. 새 증권사 양식이 들어오면

1. 그대로 돌리고 실행보고 「자료 진단」 을 먼저 본다.
2. 「못 맞춘 머리글」 가운데 금액 · 잔액 · 날짜 열은 설정 `머리글` 에, `[미분류]` 적요는 설정 `적요규칙` 에 더하고 다시 돌린다. 코드와 사전 파일은 고치지 않아도 된다.
3. 같은 양식을 세 번째 받으면 설정에 둔 별칭 · 규칙을 `references/머리글사전.json` · `references/적요사전.json` 으로 옮기고 `_출처` 에 증권사를 적는다. 머리글은 괄호를 지우고 비교한다(`거래금액(외)` → `거래금액외`). 적요 규칙은 위에서부터 처음 맞는 것을 쓴다.
4. 표로 못 읽는 양식(그림, 칸이 표 꼴이 아닌 배치)은 AI 가 쪽 이미지를 읽어 `templates/표준거래표_양식.csv` 로 옮겨 적고 `--standard` 로 돌린다. 증권사 잔액 열도 함께 옮겨 적어야 대사로 검증된다.
5. 2행 1건(키움·KB·NH·신한) 꼴은 머리글 줄 수와 날짜 빈칸 비율로 자동 판정한다. 판정이 틀리면 보고의 `multiline/combined` 표시를 보고 고친다.
