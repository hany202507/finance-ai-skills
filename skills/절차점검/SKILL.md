# 절차점검

조서의 수행 결과 칸에 「예외 없음」 이라고 적혀 있어도 수행 시트에는 빈칸이 남아 있을 수 있다. 이 스킬은 절차 줄마다 수행 시트와 받은자료를 읽어 수행됐는지와 적절했는지를 판정한다.

- 판정은 Claude 가 한다. 조서 양식과 평가 방법이 건마다 달라 엔진 규칙으로 정하지 않는다.
- 엔진(`scripts/`)은 양식과 관계없이 되는 것만 검사한다. 판정이 줄마다 있는지, 근거 칸이 실제로 있는지, 점검 뒤에 조서나 근거 파일이 바뀌었는지다. 근거가 그 절차와 관계있는지는 엔진이 보지 못한다.
- 결과는 조서와 다른 파일이다. 조서 파일은 건드리지 않는다. 감사인이 점검표 「반영」 칸에 「예」 를 적은 줄만 검토의견 파일에 들어간다.
- 판정은 감사인이 확인하기 전이다. 감사증거가 충분한지의 결론은 감사인이 낸다(감사기준서 330 문단 26).
- 근거: 감사기준서 330 문단 18 · 21 · 26 · 28(실증절차와 증거 평가), 230 문단 8 · 9(감사문서에 남길 것).
- 예시 자료: `examples/모의자료/`(새론기공(가상)의 매출채권 조서와 받은자료). 쓰는 법은 아래 「시험해 보기」 에 있다.

## 넣을 것

| 넣을 것 | 무엇 | 없으면 |
|---|---|---|
| 조서 엑셀 파일(xlsx) | 절차 표(감사프로그램 · 표지)와 수행 시트가 든 계정별 조서 하나 | 점검할 수 없다 |
| 받은자료 폴더 | 회사가 준 명세 · 대장 · 약정서. 조서 폴더의 「00 받은자료」 를 먼저 찾는다 | 조서 안의 기록만으로 판정한다. 「해당 없음」 사유는 견줄 자료가 없으면 「판단 못 함」 이 된다 |
| 다른 조서 파일 | 이 조서가 수행 위치로 가리키는 다른 조서(외부조회 조서 등) | 그 절차는 「판단 못 함」 이 될 수 있다 |

## 돌리는 법

```bash
python scripts/run.py scan <조서.xlsx> [--sheet <시트>] [--rows 200] [--width 300]
python scripts/run.py rows <조서.xlsx> --layout <위치.json> --json
python scripts/run.py check <조서.xlsx> --layout <위치.json> --verdicts <판정.json> [--received <받은자료 폴더>] [--with <이름=다른 조서.xlsx>]
python scripts/run.py apply <조서.xlsx> --who <감사인 이름> [--pick 번호...]
python scripts/run.py status <조서.xlsx>
```

파일 경로는 절대 경로로 준다. 위치 파일과 판정 파일은 조서 폴더가 아닌 작업 폴더에 쓴다.

## 순서

1. **훑는다.** `scan <조서.xlsx>` 로 시트마다 칸 글과 절차 표 후보를 본다. 후보는 엔진의 추정이니 시트를 읽고 확인한다. 칸 글은 40자에서 잘린다. 수행 시트를 읽을 때는 `--sheet <시트> --rows 200 --width 300` 으로 전문을 본다.
2. **절차 표 위치를 적는다.**
   ```json
   {"area": "4000C",
    "tables": [{"sheet": "감사프로그램", "head_row": 4, "first_row": 5, "last_row": 13, "step": "B",
                "applies": "C", "ref": "D", "who": "E", "result": "F",
                "excluded": {"9": "소계 줄", "16": "결론 줄"}, "continued": [8]}]}
   ```
   - `area` 는 한공회 감사조서 서식의 4000 영역 번호다(매출채권 4000C, 매출 4000P, 재고자산 4000E, 유형자산 4000G …). 조서의 계정으로 정하고, 모르겠으면 감사인에게 묻는다.
   - `sheet` · `first_row` · `last_row` · `step`(절차 글 열)은 꼭 적는다. 해당 여부(`applies`) · 조서번호(`ref`) · 수행자(`who`) · 수행 결과(`result`) 열은 있는 것만 적는다.
   - 절차 표가 여러 시트나 여러 구역에 나뉘어 있으면 `tables` 에 모두 적는다. 범위를 좁게 잡지 않는다.
   - `head_row` 는 머리글 행(첫 절차 줄 바로 윗행)이다. 엔진은 범위 위아래 세 행 안의 절차 열에 글이 있으면 위치 파일을 받지 않는다. 절차가 아닌 줄(소계 · 구분 제목 · 결론)은 `excluded` 에 행 번호와 까닭을 적는다.
   - 절차 열이 비고 다른 칸에만 글이 있는 행은 윗줄의 수행 기록이 이어진 행일 때만 `continued` 에 적는다. 절차 칸을 병합한 양식은 적지 않아도 이어진다.
3. **절차 줄을 받는다.** `rows … --json`. 절차 줄(번호 n, key, 해당 여부, 수행 결과, 표시)과 그 영역의 확인 항목(`area_points`)이 나온다. `range_problems` 가 있으면 위치 파일을 고친다.
4. **읽고 판정한다.** 아래 「판정」 대로 절차 줄마다 하나씩. 수행 위치가 가리킨 시트를 `scan --sheet` 로 열어 읽고, 받은자료 파일도 연다.
5. **판정 파일을 쓴다.**
   ```json
   {"workpaper": "매출채권_조서.xlsx",
    "verdicts": [
      {"key": 3, "verdict": "수행 부족", "missing": "증거: 조회 3곳이 회신 없이 대체 절차도 없음", "cites": ["C30 조회!D11:H13"]},
      {"key": 1, "verdict": "수행됨", "cites": ["C10 총괄!A2:G3"]},
      {"part": "영역", "key": "C-8 특수관계자 채권", "verdict": "수행 기록 없음", "missing": "감사프로그램에 특수관계자 채권 절차 줄이 없음", "cites": ["C20 명세!D8"]}],
    "coverage": {"C-1": [1], "C-2": [2], "C-3": [3], "C-8": []}}
   ```
   - `key` 는 rows 가 보인 번호(n)나 key 다.
   - **대응표(coverage)**: rows 의 `defined` 가 true 인 영역은 `area_points` 의 절차 번호마다 그 절차를 다루는 절차 줄 번호를 적는다. 절차 표에 그 절차의 줄이 없으면(다른 시트에 흔적이 있어도) 빈 목록 `[]` 을 적고, 그 번호로 시작하고 판정이 「수행 기록 없음」 인 영역 줄(`"part": "영역", "key": "C-8 <절차 이름>"`)을 판정에 넣는다. 절차 줄 하나는 절차 번호 세 개까지 댄다. 관계없는 줄을 대지 않는다.
   - `defined` 가 false 인 영역은 coverage 를 쓰지 않는다. 조서에 적힌 절차 줄만 점검했고 조서에 없는 절차는 보지 못했다고 보고에 적는다. 절차 목록을 지어내지 않는다.
   - 근거(cites)는 `시트!칸`, 함께 준 다른 조서는 `<이름>:시트!칸`(`--with 이름=경로`), 받은자료는 `받은자료:<받은자료 폴더 아래 경로>#<쪽 · 표>`.
6. **판정 파일을 엔진에 넣는다.** `check …`. 조서 옆에 `절차점검_<파일 이름>.xlsx`(점검표)와 `절차점검_<파일 이름>.json`(기록)이 생긴다. 받지 않으면 까닭이 줄마다 나온다. 고쳐서 다시 넣는다. 통과시키려고 판정을 「판단 못 함」 으로 바꾸지 않는다.
7. **보고한다.** 이 순서로 적는다.
   1. 점검표 파일 경로.
   2. 「볼 것 n줄 · 문제없음 n줄」 과 볼 것 줄마다 한 줄(절차 · 판정 · 빠진 것). 절차는 조서에 적힌 번호와 절차 글로 부른다(rows 의 n 은 판정 파일에만 쓴다).
   3. 점검한 범위(시트와 행). 범위는 Claude 가 정했으니 감사인이 확인해 달라고 적는다.
   4. 확인 항목 정의가 없는 영역이면 그 사실.
   5. 다음 할 일. 「점검표 반영 칸에 예 를 적거나 번호를 알려 주시면 그 줄만 검토의견에 옮깁니다」 처럼 쓴다.
8. **고른 줄만 옮긴다.** 감사인이 「예」 를 적었다고 하거나 번호를 말하면 `apply <조서.xlsx> --who <감사인 이름> [--pick 번호...]`. 조서 옆 `검토의견_<파일 이름>.xlsx` 에 「열림」 으로 들어간다. 감사인이 고르지 않은 줄을 옮기지 않는다. 점검 뒤에 조서가 바뀌었으면 엔진이 옮기지 않으니 3번부터 다시 한다.

## 판정

「해당 없음」 줄은 사유가 맞는지 잔액 · 받은자료와 견준다. 수행 결과 칸의 글만 보고 판정하지 않는다.

| 판정 | 언제 |
|---|---|
| 수행됨 | 「해당」 줄. 수행 시트에 기록이 있고 아래 넷이 모자라지 않다 |
| 사유 맞음 | 「해당 없음」 줄. 사유가 자료와 맞다 |
| 일부 빠짐 | 절차 글에 든 세부 가운데 기록이 없는 것이 있다(기록이 수행 결과 칸에만 있는 세부도 이 판정이다) |
| 수행 부족 | 기록은 있는데 범위 · 증거 · 차이 처리 · 결론 가운데 하나가 모자라다 |
| 수행 기록 없음 | 「해당」 인데 그 절차의 기록이 수행 시트 어디에도 없다. 가리킨 시트가 있어도 그 절차의 기록이 없으면 이 판정이다. 해당 여부가 빈칸인 줄도 같다 |
| 사유 어긋남 | 「해당 없음」 사유가 자료와 맞지 않는다 |
| 판단 못 함 | 견줄 자료가 없다. 무엇이 없는지 적는다 |

적절한지는 넷으로 본다.

- **범위**: 모집단이 잔액과 맞는지, 표본 · 조회 대상이 계획한 만큼인지, 본 기간에 결산일 앞뒤가 들어가는지.
- **증거**: 어느 자료를 봤는지 적혀 있는지, 회사 설명만으로 끝내지 않았는지.
- **차이 처리**: 대사 차이 · 회신 차이 · 미회신 건마다 원인이나 대체 절차가 적혀 있는지.
- **결론**: 남은 차이가 있는데 문제없다고 결론 내지 않았는지, 계획에 적힌 경영진 주장을 다뤘는지.

「수행 부족」 의 빠진 것은 `범위:` · `증거:` · `차이 처리:` · `결론:` 가운데 하나로 시작한다. 모자란 것이 여럿이면 이 순서에서 앞선 것 하나를 머리말로 쓰고 나머지는 뒤에 잇는다.

근거는 그 절차의 기록이 실제로 적힌 칸이다. 확인 항목이 있는 절차는 항목마다 어느 칸에서 확인했는지 대응시켜 고른다. 시트 제목이나 잔액 칸 하나를 여러 줄의 근거로 되풀이해 쓰지 않는다(엔진은 「수행됨」 세 줄까지만 같은 근거를 받는다).

| 판정 | 근거 |
|---|---|
| 수행됨 | 절차 표 범위와 겹치지 않는 수행 칸이 하나 이상이고 비어 있지 않다. 같은 근거를 네 줄 이상에 쓰면 전체가 거부된다 |
| 사유 맞음 | 비어 있지 않은 조서 칸이 하나 이상(사유를 뒷받침하는 잔액 칸이나 사유 칸) |
| 일부 빠짐 · 수행 부족 · 수행 기록 없음 | 조서 칸이 하나 이상. 채워져 있어야 할 칸이 비어 있다면 그 빈칸을 가리켜도 된다 |
| 사유 어긋남 | 조서 칸이나 받은자료 파일이 하나 이상(받은자료만 근거로 써도 된다) |
| 판단 못 함 | 없어도 된다. 빠진 것에 무엇이 없는지 적는다 |

- 문제없는 줄(수행됨 · 사유 맞음)에는 빠진 것을 쓰지 않는다.
- 빠진 것은 한 줄 80자. 금액을 쓰지 않는다(근거 칸으로 가리킨다). 건수는 직접 센 것만 쓴다.
- 일반 조언(「추가 검토 필요」)과 칭찬을 쓰지 않는다.
- rows 출력의 표시(flags)만으로 판정하지 않는다.
- 수행 시트끼리 기록이 어긋나 보이면 판정을 억지로 바꾸지 않고 보고에 「감사인이 볼 것」 으로 따로 적는다.
- 조서가 봤다고 적은 자료가 받은자료에 없으면 조서 기록으로 판정하고, 원본과 견주지 못한 자료를 보고에 따로 적는다.
- 「수행됨」 줄에도 받은자료 근거를 더할 수 있다. 엑셀 받은자료는 `받은자료:조회_발송회신대장.xlsx#발송회신 C11:D13` 처럼 쓴다. `#` 뒤는 사람이 볼 위치이고 엔진은 그 파일이 있는지만 본다.

## 쓰는 중인 조서

감사인이 「이 조서 뭐가 더 남았어」 라고 물으면 쓰는 중인 조서에도 돌린다. 남은 일은 「볼 것」 목록으로 본다. 이때는 검토의견에 옮기지 않고 볼 것을 절차 순서로 보고한다. 남은 절차를 Claude 가 스스로 수행하지 않는다.

## 하지 않는 것

- 조서 파일을 고치지 않는다.
- 해당 여부가 옳은지 정하지 않는다. 사유가 자료와 맞는지까지만 본다.
- 감사인이 고르지 않은 줄을 검토의견에 옮기지 않는다.
- 확인 항목 정의가 없는 영역의 절차 목록을 지어내지 않는다.
- 감사의견이나 감사증거가 충분하다는 결론을 쓰지 않는다.

`examples/모의자료/매출채권_조서.xlsx` 는 가상 회사의 매출채권 조서다. 회계사가 손수 만든 양식이고 결함 넷을 일부러 넣었다. 받은자료는 같은 폴더의 `00 받은자료/` 에 있다. 감사인이 「절차점검 예시 조서 점검해 줘」 라고 하면 이 파일을 작업 폴더로 복사한 뒤 위 순서대로 한다. 예시 폴더 안에 점검표를 쓰지 않는다.
