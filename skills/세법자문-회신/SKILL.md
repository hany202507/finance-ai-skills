# 세법자문-회신 — 근거 조문이 달린 세무 회신 초안

세무 쟁점을 받아 **법령 원문 조사 → 누락 스윕 → 교차검증 → 회신 초안** 까지 자율 수행한다.
모든 결론에 근거 조문(법령명·조문번호·시행일)이 붙고, 못 찾은 것은 "확인 불가"로 남긴다.
**최종 판단·서명은 세무사·회계사.**

## 이 스킬의 실패 방식은 "틀린 답"이 아니라 "빠진 답"이다

부가세 서식 미작성 건을 검토하면서 주요 가산세를 통째로 놓친 적이 있다.
원인은 판단력이 아니라 검색이었다.

- `search_law` 는 **법령명만** 찾는다. 조문 본문은 검색하지 못한다.
  `search_law("부가세 서식미작성 가산세")` → **0건**.
- 0건이 나오면 모델은 자기 기억으로 메운다. 기억은 조문 단위로 정확하지 않다.
- 세목 하나만 보면 다른 법에 있는 같은 쟁점의 가산세를 못 본다.
  부가세 가산세인데 **조세특례제한법**에 있는 조문이 9개다.

그래서 이 스킬의 중심은 회신 문장이 아니라 **2단계 스윕**이다.

## 도구 사실관계 (틀리면 조용히 0건이 된다)

법령 조회는 전부 **`korean-law` MCP** 로 한다. 웹·기억으로 조문번호를 단정하지 않는다.

`korean-law` 는 이 저장소의 `mcp/korean-law` 다. 법제처 OPEN API 를 직접 부르는 로컬 서버라
**본인 OC 키 하나**만 있으면 된다(open.law.go.kr 회원가입 → OPEN API 활용신청, 승인 1~2일).
설치 스크립트가 `~/.claude/mcp/korean-law` 에 넣어 주고, 등록은 한 번만 한다.

```
claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "~/.claude/mcp/korean-law/index.js"
```

등록이 안 돼 있으면 아래 도구가 전부 없다. 0단계의 생존 확인에서 바로 드러난다.

| 하려는 것 | 쓸 도구 | 주의 |
|---|---|---|
| 법령명 → MST·시행일 | `search_law` | **법령명 전용.** 내용 키워드는 0건 |
| 법 구조 파악 | `get_law_outline` | 편·장·절 + 조문 목차. 조특법 전문은 1MB라 통째로 못 읽는다 |
| 내용으로 조문 찾기 | **`scan_articles`** | 여러 법을 한 번에. 항·호 본문까지 훑는다 |
| 조문 원문 | `get_law_text` | `article` 은 `"60"`·`"75의8"` 형식 |
| **언제부터 적용되나** | **`get_addenda`** | **부칙의 적용례·경과조치.** 조문에는 없다 |
| 개정 이력 | `amendment_track` | `legal_research` 라는 도구는 **없다** |
| 조문 간 연계(법-령-칙·타법) | **`trace_references`** | §60⑩ → 법인세법 §75의6 을 눈으로 안 쫓는다 |
| 판례·법령해석례·헌재결정례 | `search_decisions` | domain 은 `prec`·`expc`·`detc` **3개뿐** |
| **국세청 예규·조세심판원 결정** | **`search_rulings`** → `get_ruling` | `search_decisions` 로는 안 나온다. 이걸 써라 |
| 별표·서식(세율표·신고서식) | `search_forms` | 본문은 PDF다. **이름·링크만 쓰고 내용 추측 금지** |

**국세청 예규는 목록만 열린다. 본문 API 는 존재하지 않는다**(법제처가 국세청 법령해석 본문을
제공하지 않는다. 국세청 OpenAPI 는 사업자등록 확인용뿐이다). 신청으로 풀리는 문제가 아니다.

> **회신에 예규를 근거로 쓰려면 그 예규의 본문을 봤어야 한다.**
> 목록이 주는 `taxlaw.nts.go.kr` 링크를 브라우저로 열면 요지·회신·상세내용·관련법령이 다 보인다.
> 열었으면 **★★★**, 못 열었으면 **안건명·안건번호·일자까지만 적고 ★★☆**.

- 브라우저를 못 쓰는 환경(예약 실행 등)이면 ★★☆ 로 남기고 **그 사실을 적는다.** 추측 금지.
- 인용할 예규는 보통 2~3건이다. 목록으로 좁힌 뒤 그것만 열면 된다.
- **안건명만 보고 요지를 지어내는 것이 최악이다.** 제목과 결론이 반대인 예규가 흔하다.

### 예규보다 **조세심판원부터** 본다

둘을 동급으로 두지 마라. 본문을 읽을 수 있는지가 다르고, 그것이 근거등급을 가른다.

| | 본문 | 등급 |
|---|---|---|
| **조세심판원** `get_ruling(source:"tribunal")` | ✅ 재결요지·이유·주문·관련법령 | **★★★ 가능** |
| 국세청 예규 `search_rulings` 목록 | ❌ API 없음 | ★★☆ (링크를 열면 ★★★) |

심판례는 **실제로 다툰 사안**이라 실무 위험을 가늠하는 데 예규보다 낫고, 본문이 오므로 검증도 된다.
먼저 심판례로 쟁점을 잡고, 예규는 과세관청 시각을 보강하는 데 쓴다.

모든 조회 응답 끝에 `출처: https://www.law.go.kr/법령/...` 가 붙는다. **회신에는 그 링크를 그대로 옮긴다.**
링크를 직접 조립하지 마라. 조문 링크를 지어내는 것이 가장 잦은 환각이다.

## 법령 위계 — 어긋나면 위가 이긴다

```
헌법 > 법률(부가가치세법·국세기본법…) > 시행령(대통령령) > 시행규칙(부령)
      ─────────── 여기까지가 법원(法源) ───────────
      ▽ 아래는 법원이 아니다. 과세관청 내부 기준일 뿐이다
   기본통칙 · 고시 · 국세청 예규(서면질의·질의회신)
```

**국세청 예규는 근거가 아니라 정황이다.** 예규만 대고 결론 내리지 마라. 조문을 먼저 찾고,
예규는 "과세관청이 이렇게 본다"는 실무 위험 신호로 쓴다. 예규와 조문이 어긋나면 `[불일치]`로 남긴다.

**특별법 우선** — 같은 사안에 조세특례제한법 규정이 있으면 세목법보다 조특법이 먼저다.
그래서 스윕에 조특법을 항상 넣는다.

## 검토 순서 — 5축을 순서대로, 하나도 건너뛰지 않는다

쟁점을 받으면 실체 판단에서 멈추고 싶어진다. 거기서 멈춘 것이 누락이 나는 자리다.

```
1축 실체    과세 대상인가 / 세율·과세표준은 / 면세·영세율인가
2축 절차    신고·납부 기한, 제출해야 할 서식·명세서·합계표는 무엇인가   ← 대개 시행령에 있다
3축 가산세  1·2축에서 어긋난 것마다 어느 법 몇 조의 가산세가 붙는가      ← 전 법령 스윕
4축 감면    국기법 §48 감면, §49 한도, 세목법의 중복적용 배제
5축 기간    적용 시행일, 부과제척기간, 경정청구·기한후신고 가능 여부
```

**1·2·5축은 항상 돈다. 3·4축은 조건부다.**

세법 자문의 대부분은 해석 질문이고, 거기엔 가산세가 없다. 없는 걸 억지로 채우면
회신이 산만해지고 "해당 없음" 표만 늘어난다. 그래서 게이트를 둔다.

```
3·4축을 돌린다        이미 어긋난 사실이 있을 때
                      · 미제출·지연·누락·오류·기한 도과가 사실관계에 있다
                      · 수정신고·경정청구·기한후신고가 쟁점이다
                      · 질문이 불이익을 묻는다("가산세 붙나요", "얼마나 물어야")

3·4축을 건너뛴다      순수 해석·사전 계획 질문
                      · "이게 면세인가요" "손금인가요" "세율이 몇 %인가요"
                      · 아직 하지 않은 일을 어떻게 할지 묻는 경우
```

**건너뛰었으면 건너뛰었다고 한 줄 남긴다.** 검토 범위에 `가산세 축: 해당 없음 — 미이행 사실 없음`.
**"판단해서 뺀 것"과 "안 봐서 없는 것"은 다르다.** 그 구별이 안 되면 이 스킬의 핵심이 무너진다.

사전 계획 질문이라도 **"이렇게 하면 어떤 의무가 생기는지"는 2축에서 다룬다.** 그 의무를 어기면
어떻게 되는지가 궁금하면 실무 유의에 한 줄이면 족하다. 표까지 갈 일이 아니다.

**3축을 돌렸다면 4축은 반드시 짝으로 돈다.** 가산세만 세고 감면·한도·중복배제를 빼면 금액이 틀린다.
부가법 §60⑨⑩ 은 항끼리 중복적용을 배제하고, ⑩ 은 **법인세법·소득세법** 가산세를 끌어와 배제한다.

**3축에서 지방소득세를 빼먹으면 금액이 10% 적게 나온다.** 법인세·소득세 가산세에는
지방소득세 가산세가 자동으로 따라붙는다(지방세법 §103의30 법인, 법인세법 §75의2~§75의9 의 10%,
§99 개인, 소득세법 §81의2~§81의14 의 10%). 별도 쟁점이 아니라 본세 가산세의 부속물이다.
인용 범위에 해당 조문번호가 들어가는지 **번호 단위로 대조**한다. 상세는 `references/가산세-스윕.md`.

**5축은 조문이 아니라 부칙에서 나온다.** "이 개정규정은 이 법 시행 후 신고하는 분부터 적용한다" 같은
적용례·경과조치는 부칙에만 있다. 개정이 걸린 쟁점에서 조문만 읽고 과세기간을 판단하면 틀린다.
`get_addenda(keywords=["적용례","경과조치"])` 로 확인한다.

**조문의 판정 기준일과 부칙의 적용 기준일은 다를 수 있다.** 본문이 "사업연도 종료일 현재"인데
부칙 적용례는 "사업연도 개시일부터"인 식이다. 실체규정만 보고 유추하면 결론이 뒤집힌다.
**설립 초년도**나 **개정 시행일에 걸친 사업연도**가 쟁점이면 부칙을 먼저 편다.
그리고 `get_addenda` 가 비어 있어도 "부칙 없음"이 아니다. 원문을 직접 확인하고,
그래도 못 찾으면 **"부칙 미확인"**으로 남긴다.

## 세법 해석 원칙 (근거: 국세기본법)

조문을 찾은 뒤 **어떻게 읽을 것인가**의 규율. 이걸 빼면 조문 나열에 그친다.

| 원칙 | 근거 | 실무에서 뜻하는 것 |
|---|---|---|
| 문리해석 우선·엄격해석 | 조세법률주의 | 조문에 없는 과세요건을 유추로 만들지 않는다. **없으면 과세 안 되는 쪽** |
| 세법 해석의 기준 | 국기법 **§18①** | 과세형평과 합목적성. 납세자 재산권을 부당히 침해하지 않게 |
| 소급과세 금지 | 국기법 **§18②③** | 성립된 납세의무에 새 해석·관행을 소급 적용하지 않는다 |
| 실질과세 | 국기법 **§14** | 명의가 아니라 사실상 귀속·거래의 실질로 판단 |
| 신의·성실 | 국기법 **§15** | 과세관청 공적 견해를 믿고 한 행위를 뒤집는 데는 제약이 있다 |
| 기업회계 존중 | 국기법 **§20** | 세법에 특별규정이 없으면 계속 적용한 기업회계 기준·관행을 존중 |

**§14(실질)와 문리해석은 자주 부딪힌다.** 형식이 유리한 결론을 낼 때는 실질과세로 뒤집힐 위험을
실무 유의에 반드시 적는다. 양쪽을 다 적고 위험을 명시하는 것이, 한쪽만 적고 단정하는 것보다 낫다.

## 절차

### 0단계 — 쟁점 정규화 + 비식별 + **MCP 생존 확인**
쟁점을 한 문장으로 적고 세목을 특정한다. 주민번호·사업자번호·계좌번호는 비식별화한다.
**과세기간(연·반기)을 반드시 명시한다.** 이게 있어야 5축에서 적용 버전을 고정할 수 있다.

그리고 **조사 시작 전에 `korean-law` MCP 가 살아 있는지 한 번 확인한다**(`search_law("국세기본법")` 한 방).
죽어 있으면 웹으로 잠정 검토하되 **회신 첫 줄에 "법령 원문 미검증"** 을 적는다.
MCP 가 응답하지 않는데 그걸 확인하지 않고 웹으로 답한 회신은 근거가 없는 회신이다.

### 1단계 — 실체·절차 조사 (1·2축)
낯선 법이면 `get_law_outline` 으로 구조를 먼저 본다(어느 장에 무엇이 있는지).
그다음 `scan_articles` 로 해당 세목법 **및 그 시행령**을 쟁점 키워드로 훑고, 잡힌 조문을 `get_law_text` 로 편다.
서식·명세서 의무는 대개 시행령에 있다. 법만 훑으면 2축이 통째로 빈다.

인용은 **항 단위까지** 좁힌다. 조문 전체를 통째로 붙이면 근거가 흐려진다.
"부가법 §60" 이 아니라 "부가법 §60⑧(현금매출명세서·부동산임대공급가액명세서 미제출, 1%)".

### 2단계 — 누락 스윕 (3·4축) — **해당하면 생략 불가**

먼저 위 게이트로 판정한다. **어긋난 사실이 없으면 이 단계를 건너뛰고 3단계로 간다**
(건너뛴 사실은 검토 범위에 남긴다). 해당하면 아래를 **하나도 빼지 않고** 돈다.
여기가 누락이 나는 자리다.

`references/가산세-스윕.md` 의 법령 세트·키워드 세트를 그대로 쓴다.

```
scan_articles(
  law_names = A세트(국세기본법·조세특례제한법·국세징수법) + B세트(해당 세목법·시행령·시행규칙),
  keywords  = 축별로 나눠 여러 번 (가산세 / 명세서·합계표·제출 / 감면·한도 / 과태료 / 배제·추징)
)
```

- **쟁점이 어느 세목이든 조세특례제한법을 반드시 넣는다.**
- 이전 과세기간이면 `effective_date` 를 넣어 **그때 시행 중이던 버전**을 훑는다.
- 스윕 결과에 `훑기 실패` 가 있으면 그 법령은 검토된 게 아니다. 검토 범위 표에 **미확인**으로 적는다.

### 3단계 — 적용시점·교차검증 (5축)
1. **`get_addenda(keywords=["적용례","경과조치"])`** — 이 쟁점의 조문이 개정된 적 있으면
   **어느 과세기간부터 적용되는지는 부칙에만 있다.** 여기를 안 보면 5축이 통째로 추측이 된다.
2. `amendment_track` 으로 시행일별 이력·시행예정 확인. 이전 과세기간이면 `effective_date` 로 그때 버전을 다시 읽는다.
3. **`search_rulings`** 로 훑는다. **조세심판원부터** `get_ruling` 으로 본문을 펴고(★★★ 가능),
   국세청 예규는 인용할 2~3건만 taxlaw 링크를 열어 본문을 확인한다. 못 열면 ★★☆.
   (웹 검색은 여기서 못 찾을 때의 보조다. 먼저 도구를 써라.)
   예규·결정례는 법원(法源)이 아니라 **과세관청·심판기관의 판단**이다.
   조문과 어긋나면 `[불일치]` 로 남기고 원문을 따른다.
4. 쟁점 조문이 다른 법·시행령과 얽혀 보이면 **`trace_references`** 로 연계를 확인한다.
   이 도구는 명시 인용만 잇는다. **못 푼 모호참조 건수를 함께 돌려주니, 그 숫자만큼은 본문을 읽어라.**

### 4단계 — 산출물을 만든다 (내부검토용 / 발송용)

**근거등급·검토 범위·부담액 산정은 내부 관리 정보다. 고객에게 그대로 나가면 안 된다.**
감사에서 조서를 의뢰인에게 주지 않는 것과 같다. 다만 **범위 제한은 의견에 남기듯**,
확인하지 못한 것은 발송용에도 문장으로 옮긴다.

| | 내부검토용 | 발송용 |
|---|---|---|
| 파일 | `세법자문_{주제}_내부.md` | `세법자문_{주제}_회신.md` (+ 메일·리포트) |
| 가산세·부담액 **표**(금액 산정) | ○ | ✕ (율·근거 조문만 본문에 서술) |
| 근거등급 ★★★/★★☆/☆ | ○ | ✕ |
| 검토 범위 표(훑은 법령·키워드) | ○ | ✕ |
| 도구 출처 URL | ○ 전부 | 필요한 것만(법제처 조문 링크) |
| **확인 못 한 사항** | 표에 `미확인` | **「확인이 필요한 사항」에 문장으로** |

발송용은 받는 사람과 쓰임에 따라 **형태가 셋**이다. 내용은 같고 껍데기만 다르다.

| 형태 | 파일 | 언제 |
|---|---|---|
| 회신 문서 | `세법자문_{주제}_회신.md` | 기본. 문서로 전달하거나 첨부한다 |
| **메일 본문** | `세법자문_{주제}_메일.md` | "메일로 보내야", "답장 써줘" 일 때. 제목·수신·본문까지 |
| **리포트** | `세법자문_{주제}_리포트.html` | 인쇄·PDF·격식 있는 제출이 필요할 때 |

양식 원문은 `references/산출물-양식.md` 에 있다. 그대로 채운다.

### 둘 다 만드나? — 내부용은 항상, 발송용은 보낼 데가 있을 때

파일이 둘이면 **잘못해서 내부용을 보낼 위험**이 생긴다. 그래서 필요할 때만 만든다.

```
내부용만          본인 확인·판단용
                  · "이거 어떻게 되지" "확인 좀" "맞나?"
                  · 강의·교육 자료로 쓰려는 경우

둘 다             받는 사람이 있을 때
                  · 입력이 고객 메일·질의서 원문이다(누가 물었다)
                  · "회신", "답변드려야", "보내야", "고객이 물어봤는데"
                  · 명시적으로 회신 초안을 요청받았다
```

**애매하면 내부용만 만들고, 보고 끝에 "발송용이 필요하면 말씀해 주세요" 한 줄을 붙인다.**
안 만들어서 한 번 더 요청받는 비용이, 잘못 나가는 비용보다 훨씬 싸다.

**내부용은 예외 없이 만든다.** 발송용만 만들고 끝내면 나중에 무엇을 근거로 썼는지 되짚을 수 없다.

**철칙 — 발송용은 내부용에서 덜어내는 것이지, 더 단정하는 게 아니다.**
내부용에 ☆(확인 불가)가 하나라도 있으면 발송용에 반드시 그 취지가 남아야 한다.
등급 표시를 지우면서 불확실성까지 지우면, 검증이 덜 된 문서가 더 확신에 찬 얼굴로 나간다.

**메일은 초안까지다. 자동 발송하지 않는다.** 메일 도구가 붙어 있어도 초안(draft)에서 멈추고
사람에게 확인받는다. 발송 버튼은 사람이 누른다.

### 4-1단계 — 인용 전수검증 (초안이 나온 뒤, 저장하기 전)

**초안에 쓴 조문번호를 전부 다시 확인한다.** 조사할 때 본 것과 회신에 적은 것이 어긋나는 일이
가장 흔한 환각이다. 스윕에서 §75의6 을 봤는데 초안에 §75의8 로 적히는 식이다.

1. 초안에서 조문번호를 전부 뽑는다(`「법령명」 제○조`, `§○`).
2. **인용 건별로 서브에이전트를 병렬로 띄운다**(Claude Code 면 `Agent`/`Task` 도구).
   각 에이전트에 주는 것은 **조문번호와 "이 취지로 인용했다"는 한 줄뿐이다.**
   초안 전문이나 결론은 주지 마라. 아래 이유가 이 단계의 핵심이다.
3. 각 에이전트가 하는 일: `get_law_text(law_name, article)` 로 원문을 펴고,
   **조문제목·본문이 그 취지와 맞는지만** 판정해 `{조문번호, 조문제목, 시행일, 출처URL, 판정, 근거등급}`
   을 돌려준다. 판정은 `일치` / `불일치(무엇이 다른가)` / `존재하지 않음` 셋 중 하나다.
4. 돌아온 것으로 초안을 고친다. **존재하지 않는 조문이면 삭제한다.**
   근처 번호로 "고쳐 짐작"하지 않는다.
5. 판례·심판례를 인용했으면 사건번호로 다시 조회해 **변경·폐기되지 않았는지** 확인한다.
   확인 못 하면 근거등급을 ★★☆ 로 낮추고 그 사실을 적는다.

**왜 서브에이전트인가 — 빨라서가 아니라 오염되지 않아서다.** 같은 컨텍스트 안에서 자기 초안을
검증하면, 이미 "§75의8 이 맞다"고 써 둔 문장이 판정을 끌어당긴다. 조문을 펴 보고도
"취지상 맞다"고 합리화하게 된다. **초안을 못 본 검증자는 합리화할 것이 없다.**
그래서 초안 전문을 주지 않는 것이 이 설계의 요점이지, 병렬이 요점이 아니다.

서브에이전트를 못 쓰는 환경이면 순차로 하되 **조문마다 원문을 실제로 펴라.**
인용 조문은 보통 5~10건이라 몇 분이면 끝난다.
**검증 안 한 조문번호가 회신에 들어가는 것이 이 스킬이 낼 수 있는 가장 큰 사고다.**

**★★★ 은 도구가 준 law.go.kr 출처 URL 이 있을 때만 붙인다.** URL 은 MCP 를 부르지 않으면 나오지 않으므로,
이 칸이 곧 "원문을 실제로 봤는가"의 증거다. 기억으로 쓴 조문에 ★★★ 을 붙이면 그게 환각이다.
☆ 가 하나라도 있으면 **결론 옆에** 그 사실을 적는다. 표 안에만 묻어두지 마라.

### 4-2단계 — 누락 비평 (저장 직전, 서브에이전트 1개) — **조건부**

**이 스킬의 실패는 "빠진 답"인데, 그 판정을 자기가 자기한테 하면 안 된다.**
검토 범위 표를 스스로 채우고 스스로 "보지 않은 것: 없음"이라고 적는 구조이기 때문이다.
**같은 컨텍스트 안에서는 자기가 안 떠올린 논점을 떠올릴 수 없다.** 그래서 시각을 하나 더 붙인다.

**다만 매번 돌리지는 않는다.** 한 번에 10만 토큰 안팎, 수 분이 든다.
"이거 면세인가요" 한 줄에 그 비용을 쓰면 스킬 자체를 안 쓰게 된다. 그게 이 장치가 죽는 방식이다.
3·4축 게이트와 같은 원리로 문턱을 둔다.

```
4-2 를 돈다        하나라도 해당하면
                   · 3축(가산세)을 돌렸다        ← 금액이 나온다. 빠지면 액수가 틀린다
                   · 발송용을 만든다             ← 받는 사람이 있다. 틀리면 밖으로 나간다
                   · 세목이 둘 이상 얽힌다       ← 다른 법에 같은 쟁점이 있는 전형적 자리

건너뛴다           위 셋에 다 해당하지 않는 순수 해석 질문(내부용만, 단일 세목)
```

**건너뛰었으면 검토 범위에 `누락 비평: 미실시 — <사유>` 를 남긴다.**
그리고 **건너뛰더라도 「보지 않은 것」 칸은 직접 채운다.** 비평을 안 돌린 것이
안 본 것을 안 적어도 된다는 뜻은 아니다.

서브에이전트 하나를 띄우고 **초안과 검토 범위 표만** 준다. 물을 것은 하나다.

> 이 쟁점에서 **안 본 것**이 무엇인가. 세목·과세기간·논점·절차 중 빠진 축을 짚어라.
> 결론이 맞는지는 묻지 않는다. **빠진 것만** 찾아라.
> 지적마다 `[지적 N] 요약 / 근거(조문·도구 결과, 확인 못 했으면 "미확인") /
> 반영 권고: 필수·권장·참고` 를 붙여 돌려라. **지적이 없으면 "지적 없음"이라고 명확히 적어라.
> 없는 것을 지어내지 마라.**

**반환 형식을 못박는 이유는 4-1 과 같다.** 4-1 은 `{조문번호, 조문제목, 시행일, 출처URL, 판정, 근거등급}`
을 고정한다. 4-2 도 등급(`필수/권장/참고`)이 없으면 **매번 다른 체계가 나와서** 아래 반영 표를 채울 수 없다.

특히 이 넷을 짚게 한다. 실제로 놓쳤던 자리들이다.

```
· 다른 세목에 같은 쟁점이 있는가        (부가세 가산세가 조특법에 9개 있었다)
· 지방세가 따라붙는가                   (법인세·소득세 가산세에 10%)
· 적용시점을 부칙으로 확인했는가        (조문 기준일 ≠ 부칙 기준일)
· 검토 범위의 "미확인"이 결론에 드러났는가
```

돌아온 지적은 **하나씩 판정한다.** 반영하거나, 반영하지 않는다면 **왜 안 하는지를 검토 범위에 적는다.**
"판단해서 뺀 것"과 "안 봐서 없는 것"의 구별이 여기서도 그대로다.

비평이 아무것도 못 찾으면 그것도 결과다. 검토 범위에 `누락 비평: 지적 없음` 한 줄.
**서브에이전트를 못 쓰면 이 단계를 건너뛰되, 건너뛰었다고 적는다.** 조용히 빼지 마라.

**돌렸다면 지적을 반영한 표도 남긴다.** `필수/권장/참고` 별 반영 여부와, 반영하지 않은 것의 사유.

### 5단계 — 산출·자가점검

**어디에 저장하나.** 사용자가 위치를 지정했으면 거기. 아니면 **현재 작업 폴더**에 쓰되,
그 폴더가 산출물을 둘 자리가 아니면(예: 남의 코드 저장소 한복판) 어디에 쓸지 먼저 물어본다.
**자문 산출물이 엉뚱한 저장소에 떨어져 그대로 커밋되는 사고**를 막기 위한 것이다.
어느 경로에 썼는지는 보고에 반드시 적는다.

- `세법자문_{주제}_내부.md` — **항상.**
- `세법자문_{주제}_회신.md` — **받는 사람이 있을 때만**(위 판정). 안 만들었으면 보고 끝에
  "발송용이 필요하면 말씀해 주세요" 한 줄. 발송용만 만들고 끝내는 경우는 없다.
- `세법자문_{주제}_메일.md` — 메일로 나갈 때. **초안까지. 자동 발송 금지.**
- `세법자문_{주제}_리포트.html` — 인쇄·PDF 가 필요할 때. `templates/리포트.html` 을 채운다.
- 자가점검:
  · 모든 결론에 조문·시행일이 붙었는가
  · 근거 미확보가 내부용에 "확인 불가"로 표기됐는가
  · **그 항목이 발송용 「확인이 필요한 사항」에 문장으로 옮겨졌는가**
  · (발송용을 만들었다면) 근거등급·검토범위표·도구 흔적이 남아 있지 않은가
  · A세트 3법을 실제로 훑었는가

## 가드레일
- 근거 없으면 단정하지 않고 **"확인 불가"**. 조문번호·링크 지어내기 금지.
- 식별정보 비식별화. **메일 자동 발송 금지**(초안까지).
- 막히면 멈추지 말고 대안 통로로 전환하되, **무엇을 못 봤는지 검토 범위 표에 적는다.**
- 법령 MCP 자체가 죽어 있으면 웹으로 잠정 검토하되 회신 상단에 **"법령 원문 미검증"** 을 명시한다.
- 이 스킬의 산출물은 **초안**이다. 최종 판단과 서명은 자격 있는 세무사·회계사가 한다.
