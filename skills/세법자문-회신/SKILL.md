# 세법자문-회신: 근거 조문과 등급이 달린 세무 답변

세무 쟁점을 받아 조사, 가산세 조문 훑기(해당할 때), 적용 시점 확인, 답변 작성, 인용 확인까지 한다.
결과물은 답변 md 파일 하나(`세법자문_{주제}.md`)다. 고객에게 보낼 때만 발송용을 따로 만든다.
판단과 서명은 회계사가 한다.

이 스킬이 막으려는 실수는 셋이다. 빠진 논점(다른 법에 있는 가산세, 부칙의 적용 시점), 조회하지 않은 조문번호를 답변에 적는 것, 결론과 상관없는 법령과 미확인 사항을 답변에 늘어놓는 것.

## 준비 (처음 한 번)

근거 출처 두 곳과 훅 하나를 쓴다. 0단계 확인에서 빠진 것이 드러나면 이 절로 돌아와 사용자에게 안내한다.

### 1. TaxDoctor 커넥터

세법령 90종의 조문, 예규 · 해석례, 판례 · 조세심판원 결정을 조회하는 외부 커넥터다.

1. `taxdoctorai.com` 에서 무료 가입한다.
2. 클로드 설정 → 커넥터 → 커스텀 커넥터 추가. 이름 `TaxDoctor`, 주소 `https://mcp.taxdoctorai.com/mcp`. 설정 화면에서 사람이 한다.
   터미널에서 Claude Code 를 쓰면 `claude mcp add --transport http taxdoctor https://mcp.taxdoctorai.com/mcp`.
3. 확인: 「TaxDoctor 의 list_laws 로 수록 법령 수를 알려줘」. 90건 안팎이 나온다.

### 2. korean-law 법령 서버

법제처 OPEN API 를 직접 부르는 로컬 서버다. 이 저장소의 `mcp/korean-law` 이고 Node.js 18 이상이 필요하다.

1. OC 를 받는다. OC 는 법제처 OPEN API 이용자 아이디다. `open.law.go.kr` 회원가입 → OPEN API 활용신청(승인까지 하루 이틀). OC 값은 가입 이메일의 아이디 부분이다(`hong@gmail.com` 이면 `hong`). 신청 화면에서 법령 본문 · 부칙, 판례 · 법령해석례 · 헌재결정례, 별표 · 서식, 조세심판원 결정례를 모두 체크한다. 좁게 신청하면 오류 없이 0건으로 나온다.
2. 설치 스크립트(`install.ps1`, `install.sh`)가 서버를 `~/.claude/mcp/korean-law` 에 넣는다. 그 폴더에 `node_modules` 가 없으면 거기서 `npm install` 을 실행한다.
3. 등록한다. 경로는 절대경로로 적는다. `~` 를 쓰면 연결이 안 된다.

   ```bash
   claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "<홈 폴더 절대경로>/.claude/mcp/korean-law/index.js"
   ```

   데스크톱 앱만 써서 `claude` 명령이 없으면 홈 폴더의 `.claude.json` 파일 `mcpServers` 에 넣는다.

   ```json
   "korean-law": {
     "type": "stdio",
     "command": "node",
     "args": ["<홈 폴더 절대경로>/.claude/mcp/korean-law/index.js"],
     "env": { "LAW_OC": "<본인OC>" }
   }
   ```

4. 앱을 껐다 켠 뒤 확인한다. 「korean-law 로 국세기본법을 찾아줘」에 법령 이름 · 시행일 · `law.go.kr` 링크가 나온다.

### 3. 훅

세법 낱말이 든 질문에 근거 규약(범위와 등급)을 끼워 넣는다. 스킬은 모델이 고르지만 훅은 매번 들어가므로, 스킬이 안 뜬 질문에도 규약이 적용된다.

설치 스크립트가 `~/.claude/hooks/tax-source-guard.mjs` 에 넣는다. `~/.claude/settings.json` 에 등록한다. 이미 `hooks` 가 있으면 `UserPromptSubmit` 배열에 한 항목을 더한다.

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "command": "node \"<홈 폴더 절대경로>/.claude/hooks/tax-source-guard.mjs\"" } ] }
    ]
  }
}
```

확인: `node "<홈 폴더 절대경로>/.claude/hooks/tax-source-guard.mjs" --selftest` 가 `PASS` 를 낸다. 등록한 뒤 앱을 껐다 켠다.

## 근거 범위와 등급

근거로 적는 출처는 둘뿐이다. 웹 검색과 기억은 찾는 데만 쓰고 근거로 적지 않는다.

| 출처 | 맡는 것 |
|---|---|
| TaxDoctor | 세법 조문 조사, 예규 · 해석례, 판례 · 조세심판원 결정, 고시 · 훈령, 조세조약, 별표 |
| korean-law | 세법이 아닌 법령(법률 · 시행령 · 시행규칙), 부칙의 적용례 · 경과조치, 지난 과세기간에 시행 중이던 조문, 여러 법을 내용으로 훑기, 조세심판원 결정 본문, 근거 조문 대조 |

근거 줄마다 등급을 붙인다.

| 등급 | 조건 |
|---|---|
| ★★★ | 원문을 확인했다. 현행 세법 조문은 TaxDoctor 와 korean-law 에서 시행일이 같은 판을 열어 인용한 항 · 호의 문언이 같다. TaxDoctor 에 없는 법령, 부칙, 지난 과세기간 조문은 korean-law 원문과 `law.go.kr` 링크가 있다. 예규 · 판례 · 심판례는 회신이나 판단 본문을 읽었다 |
| ★★☆ | 현행 세법 조문을 한 곳에서만 읽었다. 예규 · 판례는 요지나 목록, 앞부분만 봤다 |
| ☆ | 두 곳에서 다 열지 못했다 |

- 근거에 적은 조문은 ★★★ 이어야 한다. 아니면 결론 바로 아래에 그 조문과 등급, 이유를 한 줄로 적는다.
- TaxDoctor 가 「미검증」 표시를 붙인 조문이라도 korean-law 와 시행일 · 문언이 같으면 ★★★ 이다.
- 링크는 도구가 준 것만 옮긴다. TaxDoctor 는 조문의 `law.go.kr` 링크를 주지 않는다. 조문 링크는 korean-law 에서 받는다. 판례 · 예규 링크는 TaxDoctor 가 준 것을 쓴다.
- 고시 · 훈령은 korean-law 로 열리지 않는다. TaxDoctor 로 못 열면 「확인 필요」나 「보내주실 자료」로 돌린다.
- 한 곳이 응답하지 않으면 남은 곳으로 조사하되 현행 세법 조문 등급은 ★★☆ 까지다. korean-law 가 없으면 세법이 아닌 법령, 부칙, 지난 과세기간 조문에 걸린 결론은 내지 않는다. 둘 다 없으면 웹으로 잠정 검토하고 답변 첫 줄에 「법령 원문 미검증」을 적는다.
- 사용자가 TaxDoctor 만 쓰라고 했으면 그 지시를 따르고, 조문 등급은 ★★☆ 로 적는다.

## 도구

도구 이름은 `mcp__<서버 id>__<도구>` 꼴이고 세션마다 id 가 다르다. 지연 로딩이면 ToolSearch 로 `search_tax get_article get_evidence verify_citations`, `korean-law` 를 찾아 한 번에 불러온다.

| 하려는 것 | TaxDoctor | korean-law | 주의 |
|---|---|---|---|
| 쟁점으로 조문 찾기 | `search_tax` | `scan_articles(law_names, keywords)` | 조문번호를 알면 `get_article` 로 바로 연다. `search_tax` 는 응답이 길다. `search_intents` 를 하나만 넣고 `limit` 를 5 이하로 둔다. korean-law `search_law` 는 법령명만 찾는다 |
| 조문 원문 | `get_article` | `get_law_text` (`article` 은 `"60"`, `"75의8"`) | TaxDoctor 는 현행 판만 준다. 응답 머리줄의 법령명이 요청과 같은지 본다 |
| 적용 시점 | `list_upcoming` (시행 예정) | `amendment_track`, `get_addenda` | 아래 3단계 |
| 지난 과세기간 조문 | `search_tax` 의 `as_of` (참고) | `get_law_text(effective_date)`, `scan_articles(effective_date)` | 날짜는 쟁점 사실이 일어난 날을 넣는다 |
| 위임 · 다른 법 인용 | `get_article` 의 위임 목록 | `trace_references` | 조문번호를 명시한 인용만 따라간다 |
| 예규 · 해석례 | `search_interpretations` → 본문은 `get_evidence` (`source_field="content"`) | `search_rulings` (목록만) | `search_tax` 의 `ruling` 은 고시 · 훈령을 먼저 준다. 예규는 `search_interpretations` 로 찾는다 |
| 판례 · 심판례 | `search_cases` | `search_rulings` → `get_ruling(source="tribunal")` | 조세심판원 결정부터 본다. 실제로 다툰 사안이다 |
| 별표 · 서식 | `get_annex` | `search_forms` (이름과 링크) | 서식 란 번호는 원본 파일로 확인한다 |
| 인용 확인 | `verify_citations` | `get_law_text` | `verify_citations` 는 세법만, 현행 판만, 조 단위 존재와 제목만 본다. 판례는 사건번호(`2020누50234`) 꼴로 넣는다 |

`법령검토` 스킬이 설치돼 있으면 출처별 결함과 대응은 그 스킬의 `references/출처별결함.md` 를 본다.

## 검토 순서

쟁점을 받으면 실체 판단에서 멈추기 쉽다. 다섯 가지를 차례로 본다.

```
1 실체    과세 대상인가, 세율 · 과세표준, 면세 · 영세율
2 절차    신고 · 납부 기한, 제출할 서식 · 명세서 · 합계표     (대개 시행령에 있다)
3 가산세  1 · 2에서 어긋난 것마다 어느 법 몇 조의 가산세가 붙는가
4 감면    가산세 감면 · 한도, 세목법의 중복적용 배제
5 기간    적용 시점, 부과제척기간, 경정청구 · 기한후신고
```

1 · 2 · 5는 항상 본다. 3 · 4는 셋 중 하나일 때만 본다.

- 미제출 · 지연 · 누락 · 기한 도과 같은 의무 위반이 사실관계에 있다.
- 수정신고 · 경정청구 · 기한후신고가 쟁점이다.
- 질문이 가산세나 불이익을 묻는다.

위반 여부를 아직 모르면 3 · 4는 보지 않는다. 대신 그 의무를 어겼을 때 붙는 가산세 조문 하나를 「실무 유의」에 한 줄로 적는다. 건너뛰었으면 「조회 기록」에 「가산세 조문 훑기: 안 함(사유)」를 남긴다. 3을 봤으면 4도 같이 본다. 가산세만 세고 감면 · 한도 · 중복배제를 빼면 금액이 틀린다.

법과 법 사이는 넷을 따라간다. 인용은 요건 · 금액 · 시기를 정하는 것만 따라간다.

- 위임: 법 → 시행령 → 시행규칙 → 별표.
- 특별법: 조세특례제한법에 같은 대상의 특례가 있는지 한 번 검색한다. 있으면 세목법보다 먼저 적용한다.
- 세법이 인용한 다른 법령: 상법 · 민법 · 건축법 · 주택법 등은 korean-law 로 조문 원문까지 본다. 그 법 안에서 해석이 갈리는 지점은 「확인 필요」에 적고 더 파지 않는다.
- 부칙: 3단계.

해석은 국세기본법의 원칙을 따른다.

| 원칙 | 근거 | 뜻 |
|---|---|---|
| 엄격해석 | 조세법률주의 | 조문에 없는 과세요건을 유추로 만들지 않는다 |
| 해석의 기준 · 소급과세 금지 | 국세기본법 제18조 | 과세형평과 합목적성. 성립한 납세의무에 새 해석을 소급하지 않는다 |
| 실질과세 | 국세기본법 제14조 | 사실상 귀속과 거래의 실질로 본다 |
| 신의성실 | 국세기본법 제15조 | 과세관청의 공적 견해를 믿고 한 행위를 뒤집는 데는 제약이 있다 |
| 기업회계 존중 | 국세기본법 제20조 | 세법에 특별한 규정이 없으면 계속 적용한 기업회계 기준을 존중한다 |

형식이 유리한 결론을 낼 때는 실질과세로 뒤집힐 위험을 「실무 유의」에 적는다.
예규는 과세관청의 입장이다. 조문을 먼저 적고 예규는 참고로 둔다. 조문과 어긋나면 `[불일치]` 로 적고 조문을 따른다.

## 절차

### 0단계. 정리와 확인

- 쟁점을 한 문장으로 적고 세목, 과세기간, 검토 기준일(오늘)을 정한다. 질문이 여러 개면 ①, ② 로 번호를 붙인다.
- 조회할 때 고객 이름 · 사업자번호 · 주민번호 · 계좌번호를 넣지 않는다. 파일에도 적지 않는다. 메일 양식의 「받는 사람」은 자리만 두고 사람이 채운다.
- 두 출처가 응답하는지 한 번씩 본다. TaxDoctor 는 `list_laws`, korean-law 는 `search_law("국세기본법")`. 빠진 곳이 있으면 「준비」 절을 안내하고, 남은 곳으로 계속할지 사용자에게 묻는다.

### 1단계. 조사 (1 · 2)

TaxDoctor 로 조문을 찾아 `get_article` 로 연다. 이 단계에서 세법 조문을 korean-law 로 또 열지 않는다. 대조는 5단계에서 한 번에 하고 등급도 그때 확정한다. 서식 · 명세서 의무는 시행령에 있으니 법만 보고 끝내지 않는다. 결론의 행위(지급, 양도, 신고)에 바로 따르는 신고 · 납부 · 제출 의무는 질문이 묻지 않았어도 조사한다. 예규와 심판례는 결론이 조문만으로 정해지지 않을 때 찾는다. 세법이 아닌 법령이 걸리면 korean-law `get_law_text` 로 연다.

옆 쟁점은 질문이 묻지 않은 다른 세목이나 다른 사람의 세금이다(소득처분을 받는 사람의 소득세, 부가가치세 등). 따로 조사하지 않고 「실무 유의」에 한 줄로 적는다. 결론이나 금액을 바꾸는 것이면 조사한다.

### 2단계. 가산세 조문 훑기 (3 · 4, 해당할 때만)

korean-law `scan_articles` 로 훑는다. 법령과 키워드는 `references/가산세-스윕.md` 에 있다.

- 먼저 가산세 본체 키워드로 A세트(국세기본법 · 조세특례제한법 · 국세징수법)와 B세트(해당 세목의 법 · 시행령 · 시행규칙)를 훑는다. A세트는 세목과 상관없이 넣는다. 부가가치세 가산세가 조세특례제한법에 있는 식이다.
- 서식 · 제출 키워드는 B세트에만, 감면 · 한도 · 중복배제 키워드는 국세기본법과 B세트에만 넣는다. 조세특례제한법에 넣으면 100건 넘게 나온다.
- 지난 과세기간이면 `effective_date` 에 의무 위반일(신고기한)을 넣어 그때 시행 중이던 판을 훑는다.
- 법인세법 · 소득세법에 따른 가산세가 있으면 그 가산세액의 10% 를 지방소득세 가산세로 같이 적는다(법인은 지방세법 제103조의30, 개인은 제99조). 국세기본법에 따른 가산세는 이 10% 대상이 아니다.
- 결과에 「훑기 실패」가 있으면 그 법령은 본 것이 아니다. 다시 훑는다.

### 3단계. 적용 시점 (5)

1. korean-law `amendment_track` 으로 그 법령이 과세기간 시작일 뒤에 개정됐는지 본다. 진행 중인 과세기간도, 결론을 정하는 세법이 아닌 법령도 같다. 이 도구는 법령 단위 이력만 준다.
2. 개정이 없었으면 조회 기록에 「개정 없음」으로 적는다. 개정이 있었으면 `get_law_text(effective_date=과세기간 시작일)` 로 그때 판을 열어 인용한 항 · 호를 현행과 견준다. 그대로이거나 부처 이름 · 자구만 바뀌었으면 「개정 있음, 인용한 항 변동 없음」으로 적는다.
3. 인용한 항 · 호가 바뀌었으면 `get_addenda(keywords=["적용례","경과조치"])` 로 부칙을 연다. 조문의 판정 기준일(예: 사업연도 종료일)과 부칙의 적용 기준일(예: 사업연도 개시일)은 다를 수 있다.
4. `get_addenda(law_name)` 결과에 그 개정의 부칙이 없으면 `amendment_track` 이 준 그 판의 MST 로 `get_addenda(mst=…)` 를 부른다. 그래도 못 찾고 결론이 그 조문으로 갈리면 「확인 필요」에 적는다.

### 4단계. 답변 작성

`references/산출물-양식.md` 1절 양식으로 `세법자문_{주제}.md` 를 쓴다. `{주제}` 는 한글 15자 이내로 짓고 띄어쓰기 대신 밑줄을 쓴다. 싣는 기준과 분량은 아래 두 절을 따른다.

### 5단계. 인용 확인

답변에 적은 번호를 전부 확인하고 등급을 확정한다.

1. 세법 조문번호와 예규 · 판례 문서번호는 TaxDoctor `verify_citations` 로 실제로 있는지 확인한다. 「실무 유의」에 괄호로 적은 조문번호도 넣는다. 건수는 조 단위로 센다.
2. 세법이 아닌 법령과 지난 과세기간 조문은 korean-law `get_law_text` 로 연 것으로 확인을 대신한다.
3. 「근거」 절에 등급을 붙여 적은 조문(부칙 포함)은 korean-law 에서 원문을 한 번 더 열어 인용한 취지와 맞는지 대조한다. 초안을 보지 않은 서브에이전트 하나에 조문마다 법령명 · 조항, 「이 취지로 인용했다」 한 줄, 쓸 도구(`get_law_text(law_name, article)`)만 주고 `일치` / `불일치(무엇이)` / `존재하지 않음` 으로 판정받는다. 초안을 쓴 쪽이 직접 대조하면 이미 쓴 문장에 맞춰 읽게 된다. 서브에이전트를 못 쓰면 조문마다 원문을 다시 열어 직접 본다.
4. 존재하지 않는 번호는 지운다. 가까운 번호로 고쳐 짐작하지 않는다. 확인하지 못한 번호는 근거에 싣지 않는다.

### 6단계. 빠진 쟁점 재검토 (해당할 때만)

2단계를 돌렸거나, 질문이 둘 이상의 세목에 대해 각각 결론을 묻는 경우에만 한다. 본세에 딸려 오는 원천징수와 지방소득세는 세목 수로 세지 않는다.

서브에이전트 하나에 초안과 조회 기록을 주고 넷만 묻는다. 다른 세목에 같은 쟁점이 있는가, 지방세가 따라붙는가, 적용 시점을 부칙으로 확인했는가, 결론의 날짜와 기간 요건이 검토 기준일과 맞는가. 지적 가운데 결론이나 금액을 바꾸는 것만 반영하고, 나머지는 조회 기록에 건수만 적는다. 반영하면서 근거에 조문이 늘었으면 늘어난 조문만 5단계를 다시 한다.

### 7단계. 저장과 보고

- 사용자가 위치를 정했으면 거기에, 아니면 현재 작업 폴더에 쓴다. 그 폴더가 남의 코드 저장소 한복판처럼 산출물을 둘 곳이 아니면 먼저 묻는다.
- 보고에는 결론 한두 문장, 파일 경로, ★★★ 이 아닌 근거와 「확인 필요」 건수를 적는다.

## 답변에 싣는 기준

1. 조회는 넓게 하고, 「근거」에는 결론 문장의 요건 · 금액(율) · 기한을 직접 정하는 조문만 적는다. 아래는 근거에 싣지 않는다.
   - 정의만 하는 조문, 위임만 하는 조문. 위임은 「위임 경로」 한 줄로 적는다.
   - 기한이 주말 · 공휴일일 때 다음 날로 미루는 조문. 날짜만 보정해 적는다.
   - 결론을 바꾸지 않는 옆 쟁점의 조문. 「실무 유의」에 한 줄로 쓰고 조문번호만 괄호로 적는다. 이 줄에는 율 · 금액 · 날짜를 적지 않는다. 적으려면 그 조문 원문을 연다.
   - 신고 · 납부 기한을 정하는 조문. 질문이 기한을 물었을 때만 근거에 싣는다.
   - 훑었지만 해당이 없던 법령. 「조회 기록」에 이름만 적는다.
2. 근거 조문은 항 · 호까지 좁혀 적는다.
3. 예규는 회신 본문을 읽은 것만 내용을 인용한다. 요지나 앞부분만 봤으면 문서번호 · 일자만 적고 ★★☆ 로 둔다.
4. 확정하지 못한 것은 먼저 다시 조회한다. TaxDoctor 에서 못 열면 korean-law 로 연다. 그래도 남으면 이렇게 나눈다. 여기서 금액은 질문받은 세목의 세액과, 같은 사실에서 바로 따라오는 원천징수 · 지방소득세다.
   - 결론도 금액도 바꾸지 않는 것은 답변에 쓰지 않는다.
   - 결론이나 금액을 바꾸는 것 중 사실관계가 없어 정하지 못한 것은 「보내주실 자료」에 자료 이름으로 적는다. 사실관계와 원문이 둘 다 없거나 사실관계에 따라 해석이 갈리는 것도 여기에 적는다.
   - 사실관계는 있는데 해석이 갈리거나 결론에 필요한 원문을 두 곳에서 다 못 연 것은 「확인 필요」에 적는다. 건마다 무엇을 확인하면 결론이 어떻게 달라지는지 적는다.
5. 결론에 날짜나 기한을 적었으면 검토 기준일과 대조한다. 이미 지난 기한을 앞으로 할 일로 쓰지 않는다. 결론이 「사업연도 내내」, 「○일 이내」 같은 기간 요건에 걸리면 그 기간이 검토 기준일 전에 이미 시작됐거나 지났는지도 본다. 지났으면 결론에 적는다.

## 분량

회계사가 몇 분 안에 읽고 판단할 수 있어야 한다. 넘치면 덜어낸다. 조사한 것을 다 싣지 않는다.

| 절 | 기준 |
|---|---|
| 결론 | 질문 하나에 한 문단, 다섯 문장 이내. 경우가 갈리면 경우별 금액 표 하나를 붙인다 |
| 근거 | 질문 하나에 다섯 줄 이내, 답변 전체 열 줄 이내. 한 줄에 조 하나(같은 조의 항 · 호는 한 줄에 묶는다). 「위임 경로」 줄은 세지 않는다. 넘치면 결론의 가부와 금액을 정하는 조문을 남기고, 계산 방법과 예외를 정하는 조문은 「실무 유의」로 내린다 |
| 실무 유의 | 다섯 줄 이내 |
| 보내주실 자료 | 결론을 가르는 것만, 다섯 개 이내 |
| 확인 필요 | 세 건까지 풀어 쓴다. 넘으면 영향이 큰 세 건만 풀어 쓰고 나머지는 제목만 한 줄씩 적는다 |
| 조회 기록 | 항목마다 한 줄 |
| 발송용 회신 | 질문 하나에 A4 한 장(공백 포함 1,500자 안팎) |

| `세법자문_{주제}_회신.md` | 받는 사람이 있을 때 | 고객 발송용. 등급과 조회 기록을 뺀다 |
| `세법자문_{주제}_메일.md` | 메일로 보내 달라고 했을 때 | 회신을 메일 문장으로. 초안까지만 |
| `세법자문_{주제}_리포트.html` | 인쇄 · PDF 를 요청했을 때 | `templates/리포트.html` 을 채운다 |

- 받는 사람이 있다는 것은 입력이 고객 메일 · 질의서이거나 「회신」, 「답변드려야」, 「보내야」 같은 요청일 때다. 애매하면 답변만 만들고 보고 끝에 「발송용이 필요하면 말씀해 주세요」를 붙인다.
- 발송용은 답변에서 덜어낸 것이다. 더 단정하게 쓰지 않는다. 근거 조문이 ★★★ 이 아니었으면 그 사실을, 「확인 필요」가 있었으면 그 내용을 문장으로 남긴다.
- 「회신 초안」 요청에는 회신 문서만 만든다. 메일 파일과 리포트는 그것을 따로 요청했을 때만 만든다.
- 메일은 초안까지만 만든다. 보내는 것은 사람이 한다.

## 가드레일

- 근거가 없으면 단정하지 않는다. 조문번호와 링크를 지어내지 않는다.
- 식별정보를 조회어와 파일에 넣지 않는다.
- 메일은 초안까지만 만든다.
- 도구가 막히면 다른 출처로 바꾸되, 열지 못한 것을 조회 기록에 적는다.
