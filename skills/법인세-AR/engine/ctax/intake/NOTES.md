# ctax read (입력) 메모

`python -m ctax read <신고 건 폴더>` 는 `00 받은자료/` 를 머리줄로 가려 읽고 `_색인/장부.json` · `_색인/전표.csv` 를 쓴다.
계약은 `../CONTRACT.md` 3 · 5절과 13절의 입력 줄. 고객 자료는 이 문서에 적지 않는다.

## 파일

| 파일 | 하는 일 |
|---|---|
| `cli.py` | 명령. 파일 판별 → 분개장(꼴별, 분기 파일 이어 붙이기) · 재무제표(계정별판 고르기) · 거래처 파일 · 시산표 읽기 → `build` → JSON · CSV · 신고건.json |
| `sniff.py` | 머리줄로 종류와 꼴 판별(journal · bs · is · partner_ledger · account_detail · trial_balance · prior_pdf · unknown). 파일 이름의 `_10100_` 은 계정코드 힌트로만 쓴다 |
| `xlsxread.py` | xlsx 행 읽기(스타일 `count` 깨짐 복구), xls 행 읽기(xlrd), 금액 읽기(쉼표 문자열 · `△` · 괄호 음수 · `'0'`), 이름 정리 |
| `journal.py` | 위하고 분개장 11열. 합계 줄 분리, 마감 전표 · 원가 대체 줄 표시(`mark`) |
| `douzone.py` | 더존 ERP 분개장 10열(7자 코드 → 계정 단위 코드, 원래 코드는 `sub_account`), 계정명세서 블록(BIFF xls), 합계잔액시산표 |
| `fs.py` | 재무상태표 · 손익계산서 5열. 줄 종류, 손실 줄 부호, 총액 · 차감 짝, 계산 줄(memo), 구역 이름 변형 맞춤 |
| `partners.py` | A 꼴 거래처원장 잔액 6열, B 꼴 계정명세서 7열(계정마다 나눔) |
| `build.py` | 코드 잇기, 부호, 계정 · 거래처 목록, 세분류, 합계, 대사 다섯(시산표가 있으면 여섯) |

corptax-impl 에서 옮긴 것: 더존 분개장 읽기(`engine/intake/journal_parser.py`), 계정명세서 블록 읽기
(`tools/oracle_account_detail.py`)를 `douzone.py` 로 옮겨 고쳤다. 재무제표는 1회차 `fs.py` 가 같은 5열이라 그대로 쓰고
`fs_parser.py` 의 결함(△, 손실 표기 변형, 차감 계정 목록, 같은 이름 줄)은 1회차에서 이미 고쳤다. `loader.py` 의 파일 이름 글롭은
머리줄 판별로 바꿨다. corptax 를 import 하지 않는다.

## 계약과 다르게 한 곳

1. **코드 범위 class.** 계약 표는 901~950 수익, 951~997 비용이다. 실제 위하고 자료에서 931 이자비용 · 933 기부금 · 949 보상비 ·
   950 유형자산처분손실 · 960 잡손실은 비용이고 962 임차보증금 · 964 기타보증금 · 980 출자금은 자산, 981 · 982 매도가능증권평가손익은
   자본(기타포괄손익)이다. 그래서 기본값을 901~930 수익, 931~960 비용, 961~997 자산으로 두고, **재무제표 줄에 이어진 계정은 재무제표
   구역(자산 · 부채 · 자본, 손익계산서 구역)으로 class 를 정한다.** 961~997 은 재무상태표 줄을 고를 때 어느 구역에도 붙을 수 있게 했다.
2. **500~799 원가 계정의 debit · credit 은 마감 전표에 더해 원가 대체 줄도 뺐다.** 원가 대체 줄 = 재고(146~175) 또는
   매출원가(451~470) 계정이 차변에 있는 전표 안의 500~799 대변 줄(역분개의 음수 줄 포함). 뺀 금액은 `transfer`.
   이 계정들은 손익계산서에 명세가 없어 전기 금액을 모르므로 `prior_amount` 0 과 `prior_known: false` 를 붙였다.
3. **손익(400) 계정의 debit · credit 은 전체 값이다.** `closing` 이 손익 잔액이고 `closing_residual` 이 이것을 본다.
4. **더존 ERP 7자 코드는 계정 단위로 묶는다.** 7자 = 계정 3자 + 세분류 4자. 재무제표 · 시산표 · 계정명세서가 모두 계정 단위라
   장부 계정 code 를 `앞 3자 + 0000`(7자 그대로)으로 하고 세분류는 `subaccounts`, 전표.csv `sub_account` 에 둔다. class 는 앞 3자로
   위 표를 그대로 쓴다. 위하고 세목 5자(국고보조금 세목처럼 세목이 다른 재무제표 줄인 경우가 있다)는 묶지 않는다.
5. **손익 → 미처분이익잉여금 대체 전표가 없는 꼴(더존 ERP).** 손익(400) 잔액이 당기순손익과 같으면 그 전표만 없는
   것으로 본다(마감은 됐다). 이익잉여금 대사에 그 금액을 더하고 closing_residual 의 `손익 400 잔액` 은 그 금액을 뺀 값(0)이다. 같지 않으면 실패.
6. **덧붙인 키**(읽는 쪽은 무시해도 된다): accounts 의 `subsection` · `transfer` · `prior_known` · `subaccounts`, fs 줄의 `section` ·
   `contra` · `net_cur` · `net_prior`, totals 의 매출원가 · 영업이익 등과 `totals.prior`, files 의 `form` · `account` · `account_how` ·
   `accounts` · `parts` · `duplicate_of` · `ignored` · `notes`, partners 의 `estimated_opening` · `in_file`, checks 의 `tb_match`,
   전표.csv 의 `sub_account` 열.

## 판단 규칙

- **마감 전표** = 손익(400, 세목 회사 40000, 더존 4000000) 계정이 든 전표. 구분 결차 · 결대로 정하지 않는다.
- **재무상태표 줄 → 코드.** 1차: 같은 이름 · 같은 구역 코드 중 (전기 + 분개장 증감 = 당기)가 맞는 것. 2차: 이름만 맞는 코드,
  분개장에 거래가 없는 줄은 거래처원장 · 명세서 파일의 기초 · 기말 금액이 같은 것. 0 줄은 코드를 비워 둔다.
  퇴직연금운용자산처럼 투자자산 줄과 부채 차감 줄로 나뉜 계정은 두 줄을 합쳐 하나로 본다.
  더존 계정 단위 코드는 계정 단위 줄(뒤 4자 0000)의 이름으로, 그 줄이 없으면 세분류 이름으로 잇는다.
- **손익계산서 줄 → 코드.** 손익계산서 구역(매출 · 매출원가 · 판관비 · 영업외 · 법인세등)의 코드 범위 안에서 이름으로 고른다.
  판관비 급여(802)와 제조 급여(503) 같은 이름 겹침을 이것으로 가른다. 이름이 맞는 코드가 없으면 같은 구역에서 계정 단위 이름이 없고
  (세분류만 쓰인 더존 계정) 금액이 같은 코드가 하나뿐일 때 잇는다(예 국내 · 해외 매출 세분류 → 상품매출).
- **이익잉여금(375~378).** 재무상태표에는 한 줄(미처분이익잉여금 또는 미처리결손금)이다. 375~378 을 묶어 대사한다.
  기초는 A 꼴 거래처원장 전기이월이 있으면 그 배분을, 없으면 결손이면 376, 이익이면 375(코드 길이에 맞춰 37500 · 3750000)에 둔다.
- **A 꼴 잔액 성격.** 행마다 잔액 = 이월 + 차 − 대 이면 차변 성격, 이월 + 대 − 차 이면 대변 성격. 가려지지 않으면(거래 없음) 장부 잔액
  부호로 정한다. `partners` 는 차변 양수로 바꿔 넣는다.
- **A 꼴 계정.** 파일 이름 코드가 분개장 그 계정의 차변 · 대변 합계와 맞는지 본다. 다르면 합계가 같은 계정을 분개장에서 찾는다.
  현금(101)은 원장이 출금 · 입금 전표의 현금 줄을 빼고 잡아 원래 맞지 않으므로 이름 코드를 그대로 쓰고 대사에서 뺀다.
- **B 꼴 계정.** 파일 안 첫 코드 열(코드가 빈 줄은 앞 계정에 붙임). 한 파일에 계정이 여럿이면 계정마다 나눈다. 같은 계정 · 같은 내용
  파일은 하나로 센다(`_2` · 접미사 중복).
- **더존 계정명세서 블록 계정.** 계정과목 블록은 줄의 7자 코드로, 거래처 블록은 블록 제목을 분개장 계정 이름(계정 단위 이름, 없으면
  세분류 이름)에 잇는다. 이름이 같은 계정이 없으면 한 글자만 다른 이름이 하나뿐일 때 잇는다(제목 오타). 같은 이름 계정이 여럿이면
  명세 합계와 분개장 순증감 크기가 같은 것, 그래도 못 정하면 계정을 비우고 partner_match 를 실패로 둔다.
- **B 꼴 잔액 부호와 기초.** 명세 합계가 장부 기말과 같은 쪽으로 부호를 맞추고, 못 맞추면 계정 class 로 정한다. 거래처별 기초 =
  기말 − 분개장 거래처별 증감(`estimated_opening: true`). 분개장에 거래가 있는데 명세에 없는 거래처(기말 0)는 기말 0 줄로 더한다
  (`in_file: false`). 계정마다 첫 B 파일만 더하고 그 파일은 추정 기초 합계 = 장부 기초도 대사한다. 거래처코드가 모두 빈 명세는 계정 단위
  한 줄이고 계정 전체 증감으로 기초를 추정한다.
- **closing_residual.** 손익 400 잔액이 0 이면 통과. 마감 뒤에도 잔액이 남은 손익 계정이 있으면(계정 사이 마감 금액이 엇갈린 경우)
  detail 과 amounts 에 계정별 잔여를 적고, 합계가 0 이라 400 이 0 이면 통과로 둔다. 400 잔액이 당기순손익과 같으면 위 5번.
- **bs_rollforward** 는 계정 줄마다 대사에 더해 계정 줄 합계 = 자산 · 부채 · 자본총계(읽기 검산)와 자산 = 부채 + 자본도 본다.
- **pl_match** 는 계정 줄마다 대사에 더해 손익계산서에 없는 손익 계정의 잔액과 당기순이익(분개장 마감 전 합계)도 본다.
- **tb_match**(합계잔액시산표가 있을 때). 시산표 계정 줄을 이름으로 장부 계정에 잇는다(같은 이름 여러 줄은 합침). 손익 구역은 차변 ·
  대변 합계(손익대체 포함) = 분개장, 재무상태표 구역은 잔액 = 장부 기말(분개장에 없는 무변동 줄은 재무상태표 금액). 분기 분개장이
  빠지거나 겹치면 여기서 드러난다.
- **분개장 여러 파일.** 이어 붙인 뒤 마감 표시를 다시 한다. 꼴이 섞이면 끝 코드 2. 파일마다 합계 줄과 줄 합계를 대조해 다르면 그 파일
  `note` 에 적고, 모든 파일에 합계 줄이 있으면 그 합을 balanced 가 본다.
- **같은 종류 재무제표 여럿.** 금액 줄이 많은 파일(계정별판)을 쓴다. 나머지는 같은 내용이면 `duplicate_of`, 다르면 `ignored`(표시과목판
  · 빈 파일). 머리 두 줄만 있는 빈 표는 종류를 정하지 못해 unknown 이다.

## 확인한 범위

- 2회차(10-09 저녁): 시험 폴더 열 곳 모두 읽음. 아홉 곳 끝 코드 0, 한 곳 끝 코드 1(마감 뒤 입력한 전표가 손익대체에 빠진 실제 자료
  문제, closing_residual). 더존 ERP 한 곳(분기 분개장 넷 · 계정명세서 xls 블록 22개 · 시산표)은 대사 여섯 모두 통과.
  B 꼴 네 곳과 더존 한 곳은 계정마다 거래처 기초 합계 = 장부 기초, 기말 합계 = 장부 기말.
- 합성 시험: `ctax/tests/test_intake.py` 11개, `test_intake_bform.py` 3개, `test_intake_douzone.py` 7개(xls 시험은 xlwt 가 없으면 건너뜀).

## 얕게 둔 곳

- **B 꼴 · 더존 거래처별 기초는 추정값이다.** 계정 합계만 장부 기초와 맞는다. 거래처별 값은 전기 기말 계정명세서가 와야 확정된다.
  추정 기초가 계정 잔액과 반대 방향인 거래처 수만 partner_match detail 에 적고 이슈로 올리지 않는다.
- **명세 파일이 없는 계정의 거래처 줄은 만들지 않는다.** 가지급금 · 가수금처럼 기말 0 이라 명세가 오지 않은 계정은 partners 에 없다.
  거래처별 기중 잔액이 필요하면 전표.csv 의 거래처 줄로 계산해야 한다(인정이자 조서 몫).
- **손익계산서에서 코드를 못 찾은 줄**(당기 0, 전기에만 금액이 있는 줄)은 `accounts` 에 넣지 않았다. `fs.is` 에 `code: null` 로 남는다.
  표준 계정코드표로 코드를 채우지 않았다(회사마다 퇴직급여 806 · 808 처럼 다르다).
- 재무상태표 0 줄과 분개장에 거래가 없는 무변동 줄 중 거래처 파일로도 못 이은 것은 `code: null`(더존 시험 폴더의 무형 계정 하나).
- 재무제표 머리의 기간과 신고 건 연도를 대조하지 않는다.
- 월중 가결산 역분개 짝은 지우지 않는다. 연 합계는 맞다. 더존 분개장의 작성일 열과 취소 짝(corptax `_pair_cancels`)은 옮기지 않았다.
- 합계잔액시산표는 대사에만 쓴다. 시산표 이름이 장부 계정 이름과 다르면(세분류만 있는 계정에 재무제표 이름이 없을 때) 맞지 않을 수 있다.
- 자본의 차변 계정(자기주식 등)은 1차 연결에서 부호를 뒤집어 맞춰 보는 정도만 한다.
