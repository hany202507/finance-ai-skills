# 1-(1)부터 2-(2)까지: 한 단계씩

가이드는 위에서부터 차례로 하라는 안내다. 앞 단계에서 정한 것이 다음 단계의 출발점이라 이 여섯 단계는 순서를 바꾸지 않는다. 엔진(AR.json)이 이미 사실과 이슈를 찾아 두었으니, 단계마다 할 일은 **엔진이 찾은 것을 회계사 눈으로 확인하고, 엔진이 못 본 것을 더하고, 다음 단계에 넘길 결론을 정하는 것**이다.

| 순서 | ID | 하는 일 | 넘기는 것 |
|---|---|---|---|
| 1-(1) | P1 | 전기 신고서의 기업 구분 확인 | 구분 · 소기업 · 업종 · 유예 |
| 1-(2) | P2 | 주식 변동, 부동산임대업 주업 | 주식등변동상황명세서 예상, 임대업 주업 여부 |
| 1-(3) | P3 | 전기 15호 · 50호(을) 줄마다 당기 예측 | 예측 f1, f2 … (확인할 이슈 번호) |
| 1-(4) | P4 | 전기 공제 · 감면 줄마다 당기 예측 | 예측 c1, c2 … |
| 2-(1) | F1 | 재무제표로 볼 계정 고르기 | 계정 a1, a2 … (엔진 이슈 번호, 없으면 AI 추가 이슈) |
| 2-(2) | F2 | 당기 중소기업 여부 다시 판정 | 메모 · 제안이 쓸 기업 구분 전제 하나 |

## 진행

```bash
python scripts/ar.py step next "<신고건>"          # 지금 할 단계, 가이드 원문, 엔진 사실(engine), 앞 단계 결론(premise)
# _색인/AR_단계/<ID>.json 을 쓴다
python scripts/ar.py step done "<신고건>" <ID>     # 검사를 통과하면 끝난 단계로 적고 다음 단계가 열린다
```

- `next` 의 `engine` 은 출발점이다. 이 단계의 자료(전기 신고서 PDF 쪽, 분개장 `_색인/전표.csv`, 장부.json)를 직접 열어 확인한다. 전기 PDF 는 `00 받은자료/전기/` 에 있다.
- `done` 은 순서를 건너뛴 단계, 정해진 값이 아닌 칸, 엔진 결과와 안 맞는 칸, 엔진 결과에 없는 금액, 줄표 · 물음표를 거절한다.
- 끝난 단계를 고치면 `done <ID> --redo`. 그 뒤 단계는 모두 다시 한다.
- 서브에이전트에 맡기면 한 단계에 한 에이전트씩, 앞 단계가 `done` 된 뒤에 다음을 부른다.

## 단계 파일 꼴

```json
{"id": "P3", "step": "1-(3)",
 "finding": "확인한 사실 2~4문장. 자료에서 본 것은 「자료상」, 짐작은 「추정:」",
 "note": "다음 단계로 넘기는 한두 문장",
 "carry": { 단계별 칸 },
 "ask": ["받을 자료 …주십시오"]}
```

금액은 엔진 결과(장부.json · 전기.json · AR.json · 조정.json · 전표.csv)에 있는 값만 쓴다. 「전표 N줄」 의 N 은 `_색인/전표.csv` 머리줄 다음부터 1로 센 번호다(파일의 줄 번호보다 하나 작다). 원 단위 그대로(6,000,000원) 쓴다. 엔진에 없는 숫자를 계산해 쓰지 않는다. 전표를 가리킬 때 「전표 10234줄」, 「37쪽」, 날짜는 금액으로 보지 않는다.

엔진에 없는 숫자가 필요하면 두 명령으로 먼저 적는다. 적은 숫자는 단계 파일 · 공제 제안 글에 쓸 수 있다. 글에 금액 대신 「합계 s2」 처럼 id 를 써도 된다(보고서가 「무엇 금액원」 으로 풀어 쓴다). 이슈 메모 글에는 쓰지 못하니 메모는 `facts` 로 가리킨다(memo.md).

```bash
python scripts/ar.py sum "<신고건>" --what "영업비 중 접대 거래처" --account 813 --memo "카드|식대"   # 엔진이 합계를 센다(s1)
python scripts/ar.py sum "<신고건>" --what "법인세 환급 줄" --lines 1204,1310                          # 줄을 골라 센다
python scripts/ar.py pdf "<신고건>" --page 37 --form 29 --what "업무외사용금액" --amount 5930000      # 엔진이 못 읽은 전기 PDF 값(p1, 확인 전)
python scripts/ar.py facts "<신고건>"                                                                  # 적은 것 보기
```

여러 줄을 더한 금액을 머릿속으로 계산해 쓰면 거절된다. `sum` 으로 세게 한다. `pdf` 는 쪽과 서식을 적은 사람 판독이라 화면에 「확인 전」 으로 나온다.

## P1 회사 종류 구분 (전기)

볼 것: 전기 별지 제1호 종류별 구분, 제51호 중소기업등 기준검토표, `next` 의 `prior_company`.

```json
"carry": {"class": "중소기업", "small": "소기업", "industry": "도매 및 소매업 / 기계장비 도매",
          "grace": "유예기간 아님", "effects": ["기업업무추진비 기본한도와 최저한세율은 중소기업 기준"]}
```

- `class`: 중소기업 · 중견기업 · 상호출자제한기업 · 그 외 · 미확인. `small`: 소기업 · 중기업 · 해당 없음 · 미확인.
- 전기.json `company.sme` · `small` 과 다르게 적으면 `differs_reason` 에 까닭(예: 엔진이 51호를 못 읽음, 신고서 원문은 중견기업)을 쓴다.
- 전기 51호 안에서 칸끼리 어긋나면(소기업 칸 (22) 은 해당인데 (27) 적정 여부는 「부」 등) `small` 은 신고서가 감면율에 실제로 쓴 쪽((27))을 적고, 어긋남은 `effects` 에 적는다. 당기 판단은 F2 가 다시 한다.
- 요건 뜻은 `references/sme.md`.

## P2 주식변동, 부동산임대업 주업

볼 것: 전기 54호(`next` 의 `prior_54`), 당기 자본금 · 주식발행초과금 증감, 임대료수입.

```json
"carry": {"stock_change": "미확인", "stock_form": "미확인", "rental_main": "해당 아님",
          "effects": ["주주명부를 받기 전에는 2-(2) 독립성을 확인 필요로 둔다"]}
```

- `stock_change`: 있음 · 없음 · 미확인. `stock_form`: 제출 예상 · 제출 대상 아님 · 미확인. `rental_main`: 해당 · 해당 아님 · 미확인.
- 주식등변동상황명세서(54호)는 사업연도 중에 주식등의 변동사항이 있는 법인이 낸다(법인세법 제119조 제1항, korean-law 2025-12-31 시행판 원문 ★★☆, https://www.law.go.kr/법령/법인세법/제119조 ). 변동이 없으면 `stock_form` 은 「제출 대상 아님」, 모르면 「미확인」.
- 자본금이 그대로여도 주주 사이 양도는 장부로 알 수 없다. 「미확인」 이 정상이고 `ask` 에 주주명부를 적는다.

## P3 전기 조정 · 유보로 당기 예측

`next` 의 `prior_lines` 가 전기.json 이 읽은 15호 · 50호(을) 줄이고 줄마다 `src`(adj:0, res:0 …)가 붙어 있다. **줄마다 예측 하나**를 쓴다. 빠지거나 겹치면 `done` 이 거절한다.

```json
"carry": {"forecast": [
  {"id": "f1", "src": "adj:0", "item": "접대비(기업업무추진비) 한도초과", "kind": "반복", "outlook": "다시 생길 듯",
   "why": "당기 지출 48,200,000원이 전기 41,500,000원보다 늘었고 한도 구조는 같다", "issues": [4]},
  {"id": "f2", "src": "adj:1", "item": "법인세등", "kind": "반복", "outlook": "안 생길 듯",
   "why": "당기 법인세등이 0원이다(결손)", "issues": [7]}]}
```

- `kind`: 반복 · 유보 추인 · 일회성. `outlook`: 다시 생길 듯 · 추인될 듯 · 안 생길 듯 · 미확인.
- `issues`: 당기에 이 예측의 결론을 낼 AR.json 이슈 번호. 엔진은 전기 15호 줄을 같은 조정 종류의 이슈에 붙이거나(전기 처리) 「전기 연속」 이슈로 따로 낸다. `next` 의 `issues_with_prior` 를 본다. 맞는 이슈가 없고 당기에 안 생기면 `issues: []`, `outlook: "안 생길 듯"` 과 까닭.
- 전기 15호 · 50호(을)가 비면 `forecast` 는 빈 목록이고, `finding` 에 빈 서식이 이월액 0원의 근거는 아니라는 점을 적는다. 엔진이 줄을 못 읽었다고 보이면(전기.json `problems`) PDF 쪽을 보고 `finding` 과 `ask` 에 적는다.

## P4 전기 공제 · 감면으로 당기 예측

`next` 의 `prior_lines` 는 전기.json `credits`(8호 갑 · 을, 이월액). 줄마다 예측 하나.

```json
"carry": {"forecast": [
  {"id": "c1", "src": "credit:0", "name": "중소기업에 대한 특별세액감면", "outlook": "미확인",
   "why": "당기 결손이라 감면할 세액이 없을 수 있다", "issues": []}]}
```

- `outlook`: 계속 · 사후관리 · 종료 · 미확인.
- `issues` 는 엔진의 공제감면 이슈 번호(`credit_issues`). 없으면 비워 두고 나중에 공제 제안(`ar.py credits`)의 `answers` 로 받는다.
- 2025 사업연도에 기한으로 갈리는 제도는 `references/credits.md`.

## F1 재무제표로 볼 계정 고르기

두 가지를 한다.
1. P3 예측을 당기 재무제표에 대 본다: `forecast_check` 에 예측마다 계정 있음 · 크게 변함 · 계정 없음. 「크게 변함」 은 그 계정의 당기 금액이 전기의 두 배 이상이거나 절반 이하인 것, 또는 계정의 성격이 바뀐 것(새 거래처 · 새 적요)이다.
2. 엔진 이슈 목록(`all_issues`)을 보고, 세무 차이가 날 계정을 고른다. 엔진 이슈가 있는 계정은 `issues` 에 번호. **엔진 이슈가 없는데 봐야 할 계정**(비용으로 처리한 장비, 이름과 실질이 다른 거래, 엔진 규칙에 없는 계정)은 `issues: []` 로 두고 `finding` · `risk` 를 쓴다. 이것이 「AI 추가 이슈」 가 되어 요약과 화면에 나온다.

```json
"carry": {
  "forecast_check": [{"forecast": "f1", "status": "크게 변함"}],
  "accounts": [
    {"id": "a1", "account": "단기대여금", "why": "대여금 300,000,000원, 엔진이 인정이자 점검 이슈를 냄", "issues": [1]},
    {"id": "a2", "account": "용역비", "current": 120000000, "prior": 15000000, "issues": [],
     "finding": "자료상 4월 장비구매 적요 전표가 용역비로 처리됨(전표 1234줄)", "why": "자산 취득이면 감가상각 · 투자세액공제 대상",
     "risk": "중", "judgment": "판단 필요", "ask": ["장비 구매 계약서를 보내 주십시오"]}]}
```

3. **엔진 규칙에 안 걸린 계정을 모두 훑는다.** 금액이 있는데 엔진 계정 묶음 · 엔진 이슈 · 위 `accounts` 어디에도 안 걸린 계정(매출원가, 외주비, 지급수수료, 소모품비, 선수금, 보증금 같은 것)을 `others_reviewed` 에 빠짐없이 적는다. 비슷한 계정은 한 줄에 묶어도 된다. 하나라도 빠지면 `done` 이 빠진 계정 이름을 대며 거절한다. 훑다가 조정 단서가 보이면 그 계정은 `accounts` 로 올려 AI 추가 이슈로 만든다.

`others_reviewed` 는 `carry` 안에 둔다(`forecast_check` · `accounts` 옆). 밖에 두면 명령이 읽지 못해 모든 계정이 빠졌다고 거절한다.

```json
"carry": {
  "forecast_check": [...],
  "accounts": [...],
  "others_reviewed": [
    {"accounts": ["상품매출원가", "외상매입금"], "note": "매입 세금계산서 합계와 맞고 기말 상품은 재고 실사로 봄(AI 추가 a3)"},
    {"accounts": ["통신비", "여비교통비", "사무용품비"], "note": "일반 경비. 적요에 업무 무관 · 가산세 단서 없음"}]}
```

`accounts` 에는 `step outside` 가 보여 주는 장부.json 계정 이름을 그대로 쓴다(전표.csv 의 세목 이름이 달라도 장부 이름으로). 계정 목록과 금액은 `python scripts/ar.py step outside "<신고건>"` 로 언제든 본다(F1 을 끝낸 뒤 `--redo` 할 때도). F1 차례일 때는 `step next` 의 `engine.outside_accounts` 에도 나온다.

훑다가 조정 단서가 보이면 원칙은 그 계정을 `accounts` 로 올려 AI 추가 이슈로 만드는 것이다. 바로 올리기 어려우면(이미 끝난 F1 을 크게 바꾸지 않을 때) 그 줄에 `"clue": "단서 한 문장"` 을 적는다. 보고서에 단서로 따로 나온다.

- AI 추가 이슈(`issues: []`)에는 `title`(선택, 60자 안의 짧은 제목)을 적는다. 없으면 `why` 첫 문장을 60자로 잘라 제목으로 쓴다.
- AI 추가 이슈의 근거 조문 · 질문지 · 세액 영향(`tax_effect`) · 숫자(`facts`) · 받은 앞 단계 항목(`answers`)은 F1 이 아니라 이슈 메모 파일의 `added` 줄에 단다(memo.md 「AI 추가 이슈」). F1 을 다시 하지 않아도 된다.
- P3 예측의 결론이 AI 추가 이슈에서 날 때는 P3 의 `issues` 를 `[]` 로 두고(이유는 why 에), 메모 `added` 줄의 `answers` 에 그 예측(f*)을 적는다.
- 엔진 이슈가 있는 계정을 모두 `accounts` 에 넣을 필요는 없다. 앞 단계 예측과 잇거나 엔진 이슈에 덧붙일 판단이 있는 계정만 넣는다.
- 단계 글은 줄표 · 물음표와 함께, 앞을 부정하고 뒤를 말하는 문장(「…이 아니라 …」)도 거절한다. 뒤의 말만 쓴다.
- `accounts` 는 재무상태표 위에서부터, 그다음 손익계산서 순서로 적는다.
- 계정이 있다는 것만으로 넣지 않는다. 엔진 이슈와 같은 내용을 되풀이하지 않는다.

## F2 당기 중소기업 여부

볼 것: 당기 매출과 구성, 자산총계, 유가증권, P1 · P2 결론, `references/sme.md`.

```json
"carry": {"verdict": "중소기업 (소기업)", "status": "확인 필요", "premise": "중소기업(소기업)", "compare_p1": "같음",
          "point": "업종 · 규모 · 자산은 충족, 독립성만 주주명부로 확인", "effects": "독립성이 미충족이면 기업업무추진비 기본한도와 공제율이 바뀐다",
          "tests": [{"name": "업종", "result": "충족", "fact": "…"}]},
"ask": ["2025년 말 주주명부를 보내 주십시오"]
```

- `status`: 확정 · 확인 필요 · 판단 불가. `compare_p1`: 같음 · 달라짐 · 미확인. `tests` 는 업종 · 규모 · 자산총액 · 독립성 · 유예기간 · 소기업 모두, `result` 는 충족 · 미충족 · 미확인 · 해당 없음.
- 판정이 확인 필요여도 `premise` 는 하나로 정한다. 메모와 제안은 이 전제를 쓴다.
- `premise` 는 조서에도 넘어간다. `step done F2` 가 끝나면 조서 「기준」 시트 중소기업 여부(중소기업이면 여, 중견 · 일반이면 부)와 공제감면 조서 소기업 여부(전제의 소기업 · 중기업, 없으면 tests 「소기업」 충족 · 미충족)를 맞추고 조서를 다시 계산한다. 회계사가 엑셀에서 고친 칸은 두고 알린다. 조서의 소기업 여부 기본값은 전기 51호를 옮긴 것이라 전제와 다를 수 있다(당기 매출로 다시 본 것이 전제다).
- 기업 구분 말고도 조서 계산에 넘길 전제가 있으면(건설용장비 내용연수 같은 것) `carry.sets` 에 적는다. 꼴은 질문지 `sets`(`references/memo.md`)와 같고 줄마다 `why` 를 단다.

```json
"sets": [{"paper": "depreciation", "key": "내용연수/기계장치", "value": 5, "why": "2-(2) 업종 판단에 따른 기준내용연수(근거 조문과 등급을 함께 적는다)"}]
```
