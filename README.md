# finance-ai-skills

재무·회계·세무 실무에 쓰는 Claude Code 스킬입니다. 하나씩 추가합니다.

실무에서 매달 쓰는 것을 공개합니다. 공통 원칙은 세 가지입니다. 계산은 결정적인 코드가 하고, 판단 근거는 원문으로 남기고, 결과는 AI 와 무관한 방법으로 한 번 더 검산합니다.

| 이름 | 분야 | 하는 일 |
|---|---|---|
| [현금흐름표](skills/현금흐름표/) | 회계 | 전기 재무상태표와 당기 분개장(또는 계정별원장)으로 현금흐름표 직접법·간접법을 만들고 서로 맞춰 본다 |
| [세법자문-회신](skills/세법자문-회신/) | 세무 | 세무 쟁점을 법령 원문으로 검토해 조문·시행일이 달린 회신 초안을 만든다. 가산세·감면·적용시점까지 빠짐없이 훑는다 |
| [회계기준검토](skills/회계기준검토/) | 회계 | 회계기준 쟁점을 기준서 원문 문단으로 검토하고, 감리지적사례·IFRIC 같은 권위 사례로 결론을 반증한 뒤 자문을 쓴다 |

## 현금흐름표

분개장의 현금 전표를 전부 보고 상대계정으로 영업·투자·재무를 정합니다. 미지급금·가지급금·가수금처럼 상대계정만으로 모르는 것은 원천 전표, 은행 상세 내역, 적요로 따라가 발라냅니다. 그 결과로 직접법을 만들고, 감사인 정산표(WTB) 방식의 간접법과 맞춰 봅니다.

- **계산은 엔진, 워크북은 수식.** 분개장 줄마다 활동·항목이 붙고 직접법·정산표·간접법은 전부 그 열을 SUMIFS 합니다. 분개장 한 줄의 분류를 고치면 현금흐름표가 따라 바뀝니다.
- **직접법과 간접법이 맞는 것은 분류가 맞다는 증거가 아닙니다.** 둘이 같은 분류를 쓰기 때문입니다. 그래서 분류와 무관한 사실로 분류를 확인하는 독립 검산을 따로 둡니다.
- **읽는 입력.** 한 줄 한 계정 분개장, 차변·대변 계정이 다른 열인 분개장, 더존 계정별원장, 합계잔액시산표, 공시 양식 재무상태표·손익계산서, 은행 상세 내역, 계정명세서.
- **기준.** 일반기업회계기준(중소기업 포함)과 K-IFRS.

실제 장부 네 벌로 돌려 내부 대사와 독립 검산을 통과했고, 그중 하나는 감사인 정산표와 대조했습니다. 다만 더존·이카운트류 양식에서만 검증했고, 연결 현금흐름표와 여러 해 비교 표시는 다루지 않습니다.

### 설치

스킬만 설치합니다(플러그인 아님). 한 줄을 붙여 넣으면 스킬 폴더에 들어가고 파이썬 패키지까지 설치합니다.

윈도우 PowerShell

```powershell
irm https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.ps1 | iex
```

맥 · 리눅스 터미널

```bash
curl -fsSL https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.sh | sh
```

`~/.claude/skills/` 아래에 스킬 폴더가 들어가고, 법령 조회 서버는 `~/.claude/mcp/korean-law` 에 들어갑니다. Claude Code 를 다시 열면 잡힙니다. 현금흐름표는 파이썬 3.10 이상, 법령 서버는 Node.js 18 이상이 필요합니다. 새 판이 나오면 같은 줄을 다시 실행하면 덮어씁니다.

세법자문-회신을 쓰려면 법령 서버를 한 번 등록합니다. OC 는 [open.law.go.kr](https://open.law.go.kr) 에서 OPEN API 활용신청을 하면 받습니다(승인 1~2일).

```bash
claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "<홈>/.claude/mcp/korean-law/index.js"
```

플러그인으로 설치하려면 `/plugin marketplace add hany202507/finance-ai-skills` 후 `/plugin install finance-ai-skills@finance-ai-skills`.

## 세법자문-회신

세무 자문에서 잘 나는 사고는 틀린 결론보다 빠진 논점입니다. 부가세 서식 미제출 건에서 조세특례제한법에 있는 가산세를 통째로 놓친 일이 이 스킬의 출발점입니다. 그래서 결론 문장보다 검토 순서와 누락 점검에 무게를 뒀습니다.

- **5축을 순서대로.** 실체 · 절차 · 가산세 · 감면 · 적용시점. 가산세와 감면은 미이행 사실이 있을 때만 돌고, 건너뛰면 건너뛴 사유를 남깁니다.
- **조문 본문을 훑는다.** 법령명 검색으로는 조문 내용을 못 찾습니다. 국세기본법·조세특례제한법·국세징수법은 세목과 상관없이 항상 훑고, 법인세·소득세 가산세에는 지방소득세 10% 를 붙입니다.
- **적용시점은 부칙에서.** 개정이 걸린 쟁점은 부칙의 적용례·경과조치를 원문으로 확인합니다.
- **초안을 못 본 검증자.** 회신에 적은 조문번호는 초안을 보지 않은 서브에이전트가 하나씩 원문과 대조합니다. 빠진 논점은 별도 서브에이전트가 따로 짚습니다.
- **내부용과 발송용을 나눈다.** 근거등급과 검토 범위는 내부용에만 두고, 확인하지 못한 것은 발송용에도 문장으로 남깁니다. 메일은 초안까지만 만듭니다.

법령 조회는 이 저장소의 [`mcp/korean-law`](mcp/korean-law/) 로 합니다. 법제처 OPEN API 를 직접 부르는 로컬 서버라 본인 OC 키 하나만 있으면 됩니다. 국세청 예규는 법제처가 본문 API 를 주지 않아 목록과 링크까지만 받고, 본문은 브라우저로 열어 확인합니다. 조세심판원 결정은 본문까지 받습니다.

## 회계기준검토

기준서 원문을 문단 번호까지 읽고, 질의회신과 웹으로 최신성을 확인한 뒤, 금감원 감리지적사례 · 회계기준원 질의회신 · IFRIC Agenda Decision · Big4 간행물 · 상장사 공시로 결론을 반증합니다. 반례가 나오면 원문으로 돌아가 결론을 고칩니다.

- **기준.** K-IFRS, 일반기업회계기준, 중소기업회계기준. 적용 대상부터 판별합니다.
- **원문은 각자 받아 둡니다.** 기준서는 저작권 때문에 이 저장소에 넣지 않았습니다. 한국회계기준원 「시행중 회계기준」에서 PDF 를 받아 한 폴더에 두고 `ACCOUNTING_STANDARDS_DIR` 로 알려 주면 그 폴더를 읽습니다. 폴더가 없으면 웹으로 잠정 검토하고 "기준서 원문 미검증"을 첫 줄에 적습니다.
- **결과.** 핵심쟁점 · 결론 · 회계처리(분개) · 상세설명 · 권위 사례 대조 순서의 자문 문서.

## 고지

결과는 전문가 검토 전 초안입니다. 회계 처리와 세무 판단의 최종 확정은 사용자에게 있습니다. 예시와 테스트의 회사·금액은 합성하거나 바꾼 값입니다.
