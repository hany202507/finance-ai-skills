## 결산자동화

**결산 스킬을 만들 때 참고하는 예시입니다. 그대로 쓰지 말고 회사 업무처리에 맞게 고쳐 쓰십시오.** 계정체계, 거래처코드, 전표 기준, 부가세 판단, 회계 프로그램 양식은 회사와 사무소마다 다릅니다. 강의에서는 수강생이 결산 스킬을 처음부터 직접 만든 뒤, 같은 자료로 이 스킬을 돌려 결과를 비교하고 빠뜨린 처리를 찾는 데 씁니다.

- **원천 열 개.** 통장 · 카드 승인 · 세금계산서 · 급여대장 · 거래처 · 계정과목 · 기초 재무상태표 · 전기 분개장 · 플랫폼 정산서 · 수출 인보이스.
- **산출 네 가지.** 결산확정 워크북(분개장 · 시산표 · 재무제표 · 현금흐름표, 전부 수식), 더존 일반전표 · 매입매출전표 업로드 파일, 전문가 확인사항(.docx).
- **규칙 밖 거래는 분개하지 않습니다.** 가계정에 두고 미분류 목록으로 냅니다. 공제 · 불공제, 계정 분류, 기말재고 같은 판단은 확인사항으로 남기고 전문가가 확정합니다.
- **검증.** 더존 업로드 사전검증(양식 · 거래처코드 · 사업자번호 · 차대)과 워크북 재계산 검산(대차 · 현금 · 순이익 연결)을 통과해야 끝납니다.

```bash
python ~/.claude/skills/결산자동화/scripts/close_folder.py <원천자료폴더> 2026-06 profile_glowbeam
```

프로파일(`scripts/profile_glowbeam.py` · `profile_maisonbloom.py`)은 가상 실습 회사에 맞춘 예시입니다. 자기 회사에 쓰려면 `profile_sample.py` 를 복사해 계정 · 거래처 · 판단 기준을 바꿉니다. 더존 SmartA 양식에서만 확인했고, 위하고 · 이카운트 등 다른 프로그램 양식은 다루지 않습니다.

## 현금흐름표

분개장의 현금 전표를 전부 보고 상대계정으로 영업·투자·재무를 정합니다. 미지급금·가지급금·가수금처럼 상대계정만으로 모르는 것은 원천 전표, 은행 상세 내역, 적요로 따라가 발라냅니다. 그 결과로 직접법을 만들고, 감사인 정산표(WTB) 방식의 간접법과 맞춰 봅니다.

- **계산은 엔진, 워크북은 수식.** 분개장 줄마다 활동·항목이 붙고 직접법·정산표·간접법은 전부 그 열을 SUMIFS 합니다. 분개장 한 줄의 분류를 고치면 현금흐름표가 따라 바뀝니다.
- **직접법과 간접법이 맞는 것은 분류가 맞다는 증거가 아닙니다.** 둘이 같은 분류를 쓰기 때문입니다. 그래서 분류와 무관한 사실로 분류를 확인하는 독립 검산을 따로 둡니다.
- **읽는 입력.** 한 줄 한 계정 분개장, 차변·대변 계정이 다른 열인 분개장, 더존 계정별원장, 합계잔액시산표, 공시 양식 재무상태표·손익계산서, 은행 상세 내역, 계정명세서.
- **기준.** 일반기업회계기준(중소기업 포함)과 K-IFRS.

실제 장부 네 벌로 돌려 내부 대사와 독립 검산을 통과했고, 그중 하나는 감사인 정산표와 대조했습니다. 다만 더존·이카운트류 양식에서만 검증했고, 연결 현금흐름표와 여러 해 비교 표시는 다루지 않습니다.

### 설치

스킬만 설치합니다(플러그인 아님). 한 줄을 붙여 넣으면 스킬 폴더에 들어가고 파이썬 패키지까지 설치합니다.

윈도우 PowerShell

```powershell
irm https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.ps1 | iex
```

맥 · 리눅스 터미널

```bash
curl -fsSL https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.sh | sh
```

`~/.claude/skills/` 아래에 스킬 폴더가 들어가고, 법령 조회 서버는 `~/.claude/mcp/korean-law` 에 들어갑니다. Claude Code 를 다시 열면 잡힙니다. 회계·세무 스킬은 파이썬 3.10 이상, 법령 서버는 Node.js 18 이상이 필요합니다. 새 판이 나오면 같은 줄을 다시 실행하면 덮어씁니다.

세법자문-회신·법령조회 스킬을 쓰려면 법령 서버를 한 번 등록합니다. OC 는 [open.law.go.kr](https://open.law.go.kr) 에서 OPEN API 활용신청을 하면 받습니다(승인 1~2일).

```bash
claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "<홈>/.claude/mcp/korean-law/index.js"
```

플러그인으로 설치하려면 `/plugin marketplace add hany202507/finance-ai-skills` 후 `/plugin install finance-ai-skills@finance-ai-skills`.

## 세법자문-회신

세무 자문에서 잘 나는 사고는 틀린 결론보다 빠진 논점입니다. 부가세 서식 미제출 건에서 조세특례제한법에 있는 가산세를 통째로 놓친 일이 이 스킬의 출발점입니다. 그래서 결론 문장보다 검토 순서와 누락 점검에 무게를 뒀습니다.

- **5축을 순서대로.** 실체 · 절차 · 가산세 · 감면 · 적용시점. 가산세와 감면은 미이행 사실이 있을 때만 돌고, 건너뛰면 건너뛴 사유를 남깁니다.
- **조문 본문을 훑는다.** 법령명 검색으로는 조문 내용을 못 찾습니다. 국세기본법·조세특례제한법·국세징수법은 세목과 상관없이 항상 훑고, 법인세·소득세 가산세에는 지방소득세 10% 를 붙입니다.
- **적용시점은 부칙에서.** 개정이 걸린 쟁점은 부칙의 적용례·경과조치를 원문으로 확인합니다.
- **초안을 못 본 검증자.** 회신에 적은 조문번호는 초안을 보지 않은 서브에이전트가 하나씩 원문과 대조합니다. 빠진 논점은 별도 서브에이전트가 따로 짚습니다.
- **내부용과 발송용을 나눈다.** 근거등급과 검토 범위는 내부용에만 두고, 확인하지 못한 것은 발송용에도 문장으로 남깁니다. 메일은 초안까지만 만듭니다.

법령 조회는 이 저장소의 [`mcp/korean-law`](mcp/korean-law/) 로 합니다. 법제처 OPEN API 를 직접 부르는 로컬 서버라 본인 OC 키 하나만 있으면 됩니다. 국세청 예규는 법제처가 본문 API 를 주지 않아 목록과 링크까지만 받고, 본문은 브라우저로 열어 확인합니다. 조세심판원 결정은 본문까지 받습니다.

## 회계기준검토

기준서 원문을 문단 번호까지 읽고, 질의회신과 웹으로 최신성을 확인한 뒤, 금감원 감리지적사례 · 회계기준원 질의회신 · IFRIC Agenda Decision · Big4 간행물 · 상장사 공시로 결론을 반증합니다. 반례가 나오면 원문으로 돌아가 결론을 고칩니다.

- **기준.** K-IFRS, 일반기업회계기준, 중소기업회계기준. 적용 대상부터 판별합니다.
- **원문은 각자 받아 둡니다.** 기준서는 저작권 때문에 이 저장소에 넣지 않았습니다. 한국회계기준원 「시행중 회계기준」에서 PDF 를 받아 한 폴더에 두고 `ACCOUNTING_STANDARDS_DIR` 로 알려 주면 그 폴더를 읽습니다. 폴더가 없으면 웹으로 잠정 검토하고 "기준서 원문 미검증"을 첫 줄에 적습니다.
- **결과.** 핵심쟁점 · 결론 · 회계처리(분개) · 상세설명 · 권위 사례 대조 순서의 자문 문서.

## 리스회계

계약서에서 개시일·기간·리스료·지급시점·보증금·할인율을 뽑아 조건 파일로 고정하고, 계산은 파이썬 엔진이 합니다. 현재가치, 유효이자율 상각, 정액 감가상각, 월별 전표를 만들고 엑셀 네 시트를 전부 셀 참조 수식으로 잇습니다. 입력가정의 할인율을 바꾸면 상각표와 전표가 따라 바뀝니다.

- **검산.** 엔진 값을 연금 현재가치 닫힌 식과 맞추고, 엑셀 수식을 `formulas` 로 독립 재계산해 엔진과 맞춥니다. 차대 일치, 리스부채·사용권자산 기말잔액 0, 총리스료 − 리스부채 = 총이자를 확인합니다.
- **판단은 회계사.** 내재이자율이 없으면 증분차입이자율 5% 를 자리값으로 두고 가정으로 표시합니다. 회사의 IBR 로 바꾼 뒤 확정합니다. 갱신·매수선택권, 단기·소액 면제도 회계사가 정합니다.
- **다루지 않는 것.** 변동리스료, 리스변경 재측정, 복구충당부채 전입액, 다통화.

## 매입매출장검토

완성된 장부를 원천자료(매출집계·주문·정산·세금계산서·카드·현금영수증·은행) 옆에 놓고 검토항목 32개로 봅니다. 10개는 스크립트가 자동으로 대조하고, 나머지 22개는 항목마다 적힌 검토 방법대로 회계사가 봅니다.

- **누락은 원천에서 보입니다.** 장부 안에서만 보면 빠진 매출(F1)과 일반전표로 간 세금계산서(F2)가 안 잡힙니다.
- **수정분개는 더존 양식으로.** 원건을 음수로 지우고 정건을 양수로 넣습니다. 원장에는 적용하지 않고, 반영한 사본으로 다시 검토해 정지가 0건인지 봅니다.
- **규칙은 CSV.** 채널의 총액·순액, 불공제 가맹점, 고정자산 계정을 고객사마다 CSV 로 적습니다. 들어 있는 규칙은 합성 예시입니다.

## 부가세신고서검토

장부가 맞아도 신고서는 틀릴 수 있습니다. 매입매출장검토로 장부를 닫은 뒤, 같은 장부에서 별지 제21호서식 본지를 다시 계산해 직원 작성본과 란별로 대조합니다. 검토항목은 40개이고 18개가 자동입니다.

- **부속명세 8종.** 매출처별·매입처별 세금계산서합계표, 신용카드 수령명세서·발행금액집계표, 공제받지 못할 매입세액 명세서, 감가상각자산 취득명세서, 영세율 매출명세서, 계산서합계표를 장부에서 만들고 본지와 공급가액·세액 둘 다 0원으로 맞춥니다.
- **놓치기 쉬운 것.** 전자신고세액공제 금액과 세무대리인 신고 여부, 법인의 신용카드 발행공제, 영세율 첨부서류(시행령 제101조) 누락을 따로 봅니다.
- **PDF.** 국가법령정보센터의 서식 원본 PDF 에 값만 얹어 신고서를 뽑습니다. 제출용이 아니라 검토·보관용입니다.

## 자금일보

계좌 거래내역 CSV 와 분류규칙 표 하나로 자금일보를 만듭니다. 은행 엑셀이든 데이터 플랫폼(예: Gridie)의 은행 연동 표든 열 이름만 맞추면 됩니다.

- **1원 검산이 먼저.** 계좌마다 거래 한 줄씩 잔액이 이어지는지, 날마다 전일 잔액 + 입금 - 출금 = 계좌 잔액 합계인지 봅니다. 하나라도 어긋나면 파일을 쓰지 않고 날짜와 차이를 내고 멈춥니다. 계좌 간 이체는 입출금에서 양쪽 다 빼므로 이체의 한쪽만 놓쳐도 여기서 걸립니다.
- **분류는 표로만.** 적요·거래처에 든 말로 자금코드를 붙입니다. 표에 안 걸린 거래는 비슷한 코드에 넣지 않고 「확인 필요」로 모읍니다. 규칙을 바꾸려면 표에 한 줄을 더하고 다시 돌립니다.
- **결과.** 대시보드 HTML 한 파일(기준일 달력, 마감 잔액 추이, 자금코드별 유입·유출, 앞으로 2주 일자별 예측, 계좌별 잔액, 확인 필요 거래, PDF 인쇄)과 자금일보 md.
- **예측.** 입출금 예정표는 그대로 쓰고, 판매 정산·매입처럼 반복되는 흐름은 최근 영업일 평균으로 채워 근거를 같이 적습니다. 평균이라 정산 주기와 계절성은 반영하지 않습니다.

예시는 지어낸 회사의 계좌 4개, 거래 688건입니다. 원화 계좌만 다루고, 은행 잔액 자체가 맞는지는 잔액증명과 따로 대조해야 합니다.
