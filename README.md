## AI면접점검

재무·회계 면접에서 AI 활용을 어떻게 말할지 준비하는 스킬입니다. 면접관 역할로 질문하고, 답을 네 항목의 1~4점 기준으로 채점하고, 비어 있는 것을 채우게 돕습니다. 네 항목은 맥락 설정력, 분해력, 검증력, 지속력이고 Anthropic의 AI Fluency 4D를 재무에 맞게 옮긴 것입니다.

- **스킬 없이도 됩니다.** [AI대화가이드](skills/AI면접점검/references/AI대화가이드.md)에 일반 대화창에 붙여 넣을 문장이 있습니다.
- **문서 셋.** [대비체크리스트](skills/AI면접점검/references/대비체크리스트.md)는 항목별 질문과 준비 목록, [채점기준](skills/AI면접점검/references/채점기준.md)은 1~4점 기준입니다.
- **회사 내부 자료는 넣지 않습니다.** 전 직장 자료는 숫자와 이름을 지우고 방식만 설명합니다.

## 결산자동화

**결산 스킬을 만들 때 참고하는 예시입니다. 그대로 쓰지 말고 회사 업무처리에 맞게 고쳐 쓰십시오.** 계정체계, 거래처코드, 전표 기준, 부가세 판단, 회계 프로그램 양식은 회사와 사무소마다 다릅니다. 강의에서는 수강생이 결산 스킬을 처음부터 직접 만든 뒤, 같은 자료로 이 스킬을 돌려 결과를 비교하고 빠뜨린 처리를 찾는 데 씁니다.

- **원천 열 개.** 통장 · 카드 승인 · 세금계산서 · 급여대장 · 거래처 · 계정과목 · 기초 재무상태표 · 전기 분개장 · 플랫폼 정산서 · 수출 인보이스.
- **산출 네 가지.** 결산확정 워크북(분개장 · 시산표 · 재무제표 · 현금흐름표, 전부 수식), 더존 일반전표 · 매입매출전표 업로드 파일, 전문가 확인사항(.docx).
- **규칙에 안 맞는 거래는 분개하지 않습니다.** 가계정에 두고 미분류 목록으로 냅니다. 공제 · 불공제, 계정 분류, 기말재고 같은 판단은 확인사항으로 남기고 전문가가 확정합니다.
- **검증.** 더존 업로드 사전검증(양식 · 거래처코드 · 사업자번호 · 차대)과 워크북 재계산 검산(대차 · 현금 · 순이익 연결)을 통과해야 끝납니다.

```bash
python ~/.claude/skills/결산자동화/scripts/run_close.py <원천폴더> <산출폴더> 2026Q2 profile_sample
```

프로파일 예시는 `scripts/profile_sample.py` 입니다. 자기 회사에 쓰려면 그 파일을 복사해 계정 · 거래처 · 판단 기준을 바꿉니다. 더존 SmartA 양식에서만 확인했고, 위하고 · 이카운트 등 다른 프로그램 양식은 다루지 않습니다.

## 현금흐름표

분개장의 현금 전표를 전부 보고 상대계정으로 영업·투자·재무를 정합니다. 미지급금·가지급금·가수금처럼 상대계정만으로 모르는 것은 원천 전표, 은행 상세 내역, 적요로 따라가 발라냅니다. 그 결과로 직접법을 만들고, 감사인 정산표(WTB) 방식의 간접법과 맞춰 봅니다.

- **계산은 엔진, 워크북은 수식.** 분개장 줄마다 활동·항목이 붙고 직접법·정산표·간접법은 전부 그 열을 SUMIFS 합니다. 분개장 한 줄의 분류를 고치면 현금흐름표가 따라 바뀝니다.
- **직접법과 간접법이 맞는 것은 분류가 맞다는 증거가 아닙니다.** 둘이 같은 분류를 쓰기 때문입니다. 그래서 분류와 무관한 사실로 분류를 확인하는 독립 검산을 따로 둡니다.
- **읽는 입력.** 한 줄 한 계정 분개장, 차변·대변 계정이 다른 열인 분개장, 더존 계정별원장, 합계잔액시산표, 공시 양식 재무상태표·손익계산서, 은행 상세 내역, 계정명세서.
- **기준.** 일반기업회계기준(중소기업 포함)과 K-IFRS.

실제 장부 네 벌로 돌려 내부 대사와 독립 검산을 통과했고, 그중 하나는 감사인 정산표와 대조했습니다. 다만 더존·이카운트류 양식에서만 검증했고, 연결 현금흐름표와 여러 해 비교 표시는 다루지 않습니다.

### 설치

스킬만 설치합니다(플러그인 아님). 한 줄을 붙여 넣으면 스킬 폴더에 들어가고 파이썬 패키지까지 설치합니다.

윈도우 PowerShell

```powershell
irm https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.ps1 | iex
```

맥 · 리눅스 터미널

```bash
curl -fsSL https://raw.githubusercontent.com/hany202507/finance-ai-skills/main/install.sh | sh
```

`~/.claude/skills/` 아래에 스킬 폴더가 들어가고, 법령 조회 서버는 `~/.claude/mcp/korean-law` 에, 세법 훅은 `~/.claude/hooks/tax-source-guard.mjs` 에 들어갑니다. Claude Code 를 다시 열면 잡힙니다. 회계·세무 스킬은 파이썬 3.10 이상, 법령 서버는 Node.js 18 이상이 필요합니다. 새 판이 나오면 같은 줄을 다시 실행하면 덮어씁니다.

양도소득세 · 세법자문-회신 · 법령검토 스킬은 korean-law 법령 서버, 법제처 OC(OPEN API 인증값), TaxDoctor 커넥터, 법제처 통합검색 커넥터로 법령 원문을 읽습니다. 설치 스크립트는 끝에 「법령 서버 점검」을 띄워, 없는 것만 설치 경로와 주소를 붙여 알려 줍니다. TaxDoctor 와 법제처 통합검색은 Claude 앱 커넥터라 스크립트가 볼 수 없어서, 터미널로 등록한 경우가 아니면 늘 `[확인]` 으로 나옵니다.

Claude 앱에 「hany202507/finance-ai-skills 의 스킬을 설치해 줘」라고 보내 설치해도 됩니다(스킬 하나만 골라도 됩니다). 설치를 마치면 Claude 가 이 대화에서 korean-law(`get_law_text`) · TaxDoctor(`search_tax`) · 법제처 통합검색(`legal_research`) 도구가 보이는지 확인하고, 없는 것만 아래 순서로 안내합니다. 같은 내용을 양도소득세 SKILL.md 「설치 뒤 점검」 절과 세법자문-회신 · 법령검토 SKILL.md 「준비」 절에도 적었습니다.

법령 서버는 한 번만 등록합니다.

1. 법제처 OPEN API 인증값(OC)을 받습니다. [open.law.go.kr](https://open.law.go.kr) 에 회원가입하고 「OPEN API 신청」에서 활용신청을 합니다(승인 1~2일). OC 는 가입 아이디입니다(이메일이 `hong@gmail.com` 이면 `hong`).
2. 신청 화면에서 법령 본문·부칙, 행정규칙, 판례·법령해석례·헌재결정례, 별표·서식, 조세심판원 결정례를 모두 체크합니다. 좁게 신청하면 오류 없이 0건이 나옵니다.
3. IP 칸이 있으면 쓰는 PC 의 공인 IP 를 넣습니다. 2026-07 법제처 답변으로는 아이디로 호출한다고 하니 신청 화면 안내를 따릅니다. 문의는 02-2109-6446 입니다.
4. 아래 명령으로 등록합니다.

```bash
claude mcp add -s user korean-law -e LAW_OC=<본인OC> -- node "<홈 폴더 절대경로>/.claude/mcp/korean-law/index.js"
```

경로는 절대경로로 적습니다. `~` 를 쓰면 연결이 안 됩니다. 데스크톱 앱만 써서 `claude` 명령이 없으면 홈 폴더의 `.claude.json` 파일 `mcpServers` 에 같은 내용을 넣습니다. 적는 꼴은 [세법자문-회신 스킬의 「준비」 절](skills/세법자문-회신/SKILL.md)에 있습니다.

세법자문-회신 스킬은 세법 조사를 [TaxDoctor](https://taxdoctorai.com) 커넥터로 합니다. 법령검토 스킬도 세법 조문은 TaxDoctor 와 한 번 더 대조합니다(민법·상법 같은 법은 korean-law 만으로 됩니다). 무료 가입 뒤 클로드 설정 → 커넥터 → 커스텀 커넥터 추가에 `https://mcp.taxdoctorai.com/mcp` 를 넣습니다.

법령검토 스킬로 노무·상법을 볼 때는 고용노동부 행정해석과 판례 본문 검색을 법제처 통합검색 커넥터로 합니다. 커스텀 커넥터 추가에 `https://mcp.gomdori.app/law?oc=<본인OC>` 를 넣습니다(korean-law-mcp, korean-law 서버와 같은 OC). `?oc=` 를 빼면 키 없는 사용자가 함께 쓰는 한도에 걸려 요청이 자주 막힙니다.

등록한 뒤 앱을 다시 열고 「민법 제162조 원문 찾아줘」를 물어 법령명·시행일·`law.go.kr` 링크가 나오면 됩니다.

#### 세법 훅 (tax hook)

세법 낱말이 든 질문에 근거 규약(출처 범위와 등급)을 끼워 넣는 훅입니다. 스킬이 뜨지 않은 질문에도 규약이 적용됩니다. `~/.claude/settings.json` 에 한 번 등록합니다.

```json
{
  "hooks": {
    "UserPromptSubmit": [
      { "hooks": [ { "type": "command", "command": "node \"<홈 폴더 절대경로>/.claude/hooks/tax-source-guard.mjs\"" } ] }
    ]
  }
}
```

`node "<홈 폴더 절대경로>/.claude/hooks/tax-source-guard.mjs" --selftest` 가 `PASS` 를 내면 정상입니다.

플러그인으로 설치하려면 `/plugin marketplace add hany202507/finance-ai-skills` 후 `/plugin install finance-ai-skills@finance-ai-skills`.

## 세법자문-회신

세무 쟁점 하나를 받아 답변 md 파일(`세법자문_{주제}.md`)을 만듭니다. 세무 자문에서 잘 나는 사고는 틀린 결론보다 빠진 논점입니다. 부가세 서식 미제출 건에서 조세특례제한법에 있는 가산세를 통째로 놓친 일이 이 스킬의 출발점입니다.

- **근거 출처는 둘.** 세법은 TaxDoctor 로 조사하고, 세법이 아닌 법령(상법 · 민법 · 건축법 등), 부칙의 적용 시점, 지난 과세기간 조문은 법제처 korean-law 로 엽니다. 웹과 기억은 근거로 적지 않습니다.
- **근거마다 등급.** ★★★ 은 원문을 확인한 것입니다. 현행 세법 조문은 두 곳에서 시행일이 같은 판을 대조합니다. 한 곳에서만 읽었으면 ★★☆ 입니다.
- **검토 순서.** 실체 · 절차 · 가산세 · 감면 · 기간. 가산세와 감면은 의무 위반이 있거나 가산세를 물을 때만 훑습니다. 훑을 때는 국세기본법 · 조세특례제한법 · 국세징수법을 세목과 상관없이 넣고, 법인세법 · 소득세법에 따른 가산세에는 지방소득세 가산세를 같이 적습니다.
- **적용 시점은 부칙에서.** 과세기간 중 인용한 항 · 호가 바뀌었으면 부칙의 적용례 · 경과조치를 원문으로 확인합니다.
- **답변 목차는 넷.** 결론 · 쟁점분석 · 실무해설 · 근거규정 순서이고, 대화창 완료 보고도 같은 순서입니다. 근거규정에는 결론을 직접 정하는 조문만 한 줄씩 싣습니다(질문 하나에 세 줄, 전체 다섯 줄 이내). 결론이나 금액을 바꿀 수 있는데 정하지 못한 것만 「확인할 사항」으로 따로 적습니다.
- **저장 전 인용 확인.** 답변에 적은 번호는 실제로 있는지 확인하고, 근거 조문은 초안을 보지 않은 서브에이전트가 원문과 대조합니다.
- **발송용은 따로.** 고객에게 보낼 때만 등급과 검토 기록을 뺀 같은 목차의 회신 문서를 만듭니다. 메일은 초안까지만 만듭니다.

준비물은 셋입니다. TaxDoctor 커넥터, 이 저장소의 [`mcp/korean-law`](mcp/korean-law/) 법령 서버(본인 OC 필요), 세법 훅. 붙이는 방법은 [스킬의 「준비」 절](skills/세법자문-회신/SKILL.md)에 있습니다. 2026-10-12 에 해석 질의, 상법이 걸린 배당 질의, 가산세 질의 세 건으로 시험했습니다. 2026-10-20 에 답변 목차를 바꾸고 회식비 매입세액, 업무용승용차 리스 두 건으로 다시 시험했습니다.

## 양도소득세

사용자에게는 계약일·잔금일·등기접수일과 읍면동 주소, 세대가 가진 주택 목록을 묻고, 조정대상지역 여부·보유햇수·세율은 엔진이 판정합니다. 조정대상지역·투기과열지구·투기지역은 2017-08-03 부터의 지정·해제 공고 35건을 기준일마다 다시 적용해 정합니다.

세율·공제율·기준금액·처분기한·한시배제 양도기한은 판정·계산 코드가 규칙세트에서 읽습니다. 코드에 남은 고정 날짜와 햇수 몇 개는 근거와 함께 `skills/양도소득세/references/규칙세트_스키마.md` 의 「코드에 남은 고정값」에 적었습니다. `rules/추출규칙.json` 에는 사람이 확인한 값을 적습니다. `scripts/build_ruleset.py` 는 그 값의 원문 발췌를 2025-01-01 이후 시행된 법제처 조문 버전마다 본문과 글자 그대로 대조해 규칙세트를 만듭니다. 현행 버전은 TaxDoctor 와 한 번 더 대조합니다.

- **코드값.** 결과의 세율구분·자산종류·과세구분·취득가액종류는 국세청 양도소득세 파일설명서 V5.17 의 코드입니다. 신고서에는 서식 표기로 바꿔 적습니다.
- **합산.** 같은 해 둘 이상 양도하면 산출세액은 같은 세율 자산 합산 세액과 합산 비교세액 중 큰 값입니다(소득세법 제104조⑤). 계산근거 엑셀에 두 금액이 모두 나옵니다.
- **검산.** 장특공률과 고가주택 안분은 조문 식으로 직접 계산하고, 세율은 과세표준을 늘려 본 세액 증가분으로, 워크북은 수식 재계산으로 엔진 값과 대조합니다. 하나라도 어긋나면 종료코드 1 로 끝납니다.
- **기준정보 확인일.** 규칙세트는 확인일 시점의 법령 기준입니다. 7일이 지나면 모든 결과에 갱신하라는 경고가 붙습니다. 지금은 `scripts/refresh/fetch_articles.py` 로 다시 받습니다.
- **형식이 틀린 값과 반영하지 못하는 사실.** 예/아니오 문항에 글자를 넣는 것처럼 형식이 틀린 값은 그 문항을 다시 묻습니다. 엔진이 반영하지 못하는 사실(같은 날 주택 여러 채 양도, 매수인이 부담한 양도소득세, 특수관계인에게 시가보다 낮게 양도 등)이 있으면 다루지않음으로 알립니다.
- **중과 한시배제.** 보유 2년 이상 주택이면 가목(2026-05-09 까지 양도)과 함께 2026-04-23 신설된 나목(토지거래허가 대상)·다목(2026-05-09 까지 계약·계약금 수령)도 판정합니다. 양도 기한이 계약일부터 4개월인지 6개월(서울 21개 구·경기 12곳)인지는 규칙세트의 지역표로 정합니다. 토지거래허가 대상인지·허가일·계약일을 모르면 중과로 계산하고 확인사항을 남깁니다.
- **증빙 자동 채움.** 매매계약서, 취득세 영수증, 공사 세금계산서 같은 파일을 주면 Claude 가 값을 읽어 적고, 엔진이 원문 발췌와 대조해 맞는 값만 사실관계에 넣습니다. 그 뒤 남은 문항만 묻습니다. 스캔본·사진에서 읽은 값과 원문과 맞지 않는 값은 `증빙_확인표.md` 로 사용자에게 확인받습니다. 경비 영수증은 서류마다 따로 받아 이어 붙이고, 지급일·금액은 같고 나머지 값이 다른 줄이 두 서류에서 오면 넣지 않고 확인받습니다.
- **신고서 PDF.** 예정신고 정기분과 예정신고를 한 번도 하지 않은 확정신고 정기분은 신고인 정보를 따로 받아 별지 제84호서식(본지·부표1·부표3)과 지방소득세 별지 제40호의11서식을 법령 서식 원본 위에 채웁니다. 만들기 전에 서식 검산이 란 사이 산식과 엔진 값을 다시 대조합니다.
- **확정신고 가산세.** 예정신고를 한 번도 하지 않은 확정신고에는 예정신고 무신고가산세와 납부지연가산세를 국세와 지방소득세에 계산해 넣습니다. 무신고가산세는 감면 없이 100분의 20 으로 적고, 예정신고분을 기한 후 신고로 내서 감면이 적용될 때의 금액을 함께 보여 줍니다. 지방소득세 가산세는 예정신고기한과 원 미만 처리 방법을 가정한 값이라 위택스 화면의 가산세와 다르면 위택스 값을 따릅니다.
- **전액 비과세 자산.** 과세 자산과 섞여 있으면 신고서에서 빼고 과세 자산만 신고합니다. 전액 비과세 자산뿐이면 신고서를 만들지 않습니다.
- **신고기한.** 기한이 토요일, 일요일, 공휴일, 대체공휴일, 노동절이면 그 다음의 첫 평일로 옮깁니다. 공휴일 표에는 2025년부터 2027년까지 있습니다. 표에 없는 해의 연휴와, 표를 확인한 뒤에 지정된 임시공휴일은 반영하지 못합니다.
- **출력 파일.** 출력 폴더에는 신고서 PDF 두 벌(`양도소득세_신고서.pdf`, `지방소득세_신고서.pdf`)과 `양도소득세_계산근거.xlsx` 만 남습니다. 상태, 합계, 확인사항, 경고, 질문, 사람이 할 일은 화면 출력과 MCP 응답으로 나옵니다.
- **신고는 사람이.** 홈택스·위택스 로그인과 제출은 사람이 합니다. 지방소득세는 위택스에서 따로 신고합니다.
- **인적사항.** 성명, 주민등록번호, 주소는 사실관계와 따로 `신고인.json` 으로 받습니다. 신고서 PDF 에만 들어가고 화면 출력과 MCP 응답에는 싣지 않습니다.
- **HTML 질문지.** 고객이 브라우저에서 직접 채우는 파일 하나(`질문지/양도소득세_질문지.html`)가 들어 있습니다. 외부로 전송하지 않고 답을 사실관계 JSON 으로 내려받습니다.
- **로컬 MCP.** `scripts/mcp_server.py` 로 다음 문항 받기, 답 넣기, 계산, 신고서, 지역 판정, 증빙 목록, 증빙 반영을 도구로 씁니다.

지금 계산하는 건은 2025-01-01 이후 매매와 경매(매각대금 완납일이 양도일)로 양도한 주택·토지·건물입니다. 조세특례제한법 감면은 계산하지 않습니다. 가산세는 예정신고를 한 번도 하지 않은 확정신고의 무신고가산세와 납부지연가산세만 계산합니다. 수용·교환·부담부증여·기타 원인으로 양도한 건, 상속·증여·입주권·분양권·겸용주택·비사업용 토지는 아직 다루지 않습니다.

기한후신고, 수정신고, 같은 해에 먼저 예정신고한 양도가 있는 신고, 대리 신고는 다루지 않습니다. 확정신고 가산세와 전액 비과세 자산의 처리에는 세무 전문가 확인이 남은 해석이 있고, 목록은 `skills/양도소득세/references/적용한계.md` 끝에 있습니다. 결과는 검토용이며 신고 전 최종 판단은 세무 전문가가 합니다.

## 법인세-통합고용

- **청년 간주는 2025년 1월 1일 이후 계약만 대상입니다.** 2024년 이전에 계약한 사람은 현재 연령만 봅니다. 회계사 확인을 거쳐 고친 값이고 근거 부칙은 SKILL.md 에 있습니다.
- **급여가 없는 달은 근무개월에서 뺍니다.** 원천징수와 국민연금 · 건강보험료 납부 사실이 확인되지 않기 때문입니다(시행령 제23조 제10항 제6호). 무급휴직은 회사 시트에서 켭니다.
- **2 · 3차 연도 판정은 종전 방식입니다.** 2024 · 2025 과세연도에 증가한 공제는 개정 부칙(법률 제21223호 제34조)으로 종전 규정을 따릅니다.
- **2026 과세연도는 기존공제와 신규공제를 함께 계산합니다.** 기존공제(2024 · 2025 증가분의 2 · 3차 연도)는 종전 서식(1)에, 신규공제(직전 과세연도 대비 새 산식, 법 제29조의8 제1항)와 추가공제는 별지 제10호의9서식(2)에 적습니다. 2025 증가분의 2차 연도는 근로자별, 2024 증가분의 3차 연도는 월말 합으로 셉니다(시행령 부칙 제36127호 제11조 제1항). 회계사 확인을 거친 판단입니다. 2027 과세연도는 전전 대비(B)가 더해지고 계산합니다(전전전 대비는 2024 이전 개시 과세연도를 비교에서 빼므로 2027 까지는 없습니다). 2022 과세연도 이전은 통합고용세액공제가 없어 계산하지 않습니다.
- **신고용 서식은 법제처 원본 그대로입니다.** `2 조서/통합고용_법정서식.pdf` 는 법제처 별지 제10호의9서식 · 제10호의10서식 PDF 쪽을 그대로 두고 칸에 값만 넣은 것입니다. 사업자등록번호 · 대표자 · 날짜 · 서명은 사람이 적습니다. 워크북의 서식 시트는 같은 값을 수식으로 보이는 검증용이고 인쇄하면 법정 용지와 쪽에 맞습니다.
- **2026 상시근로자 범위는 회계사가 봅니다.** 2026 과세연도부터 「근로기간 1년 미만」 · 「연평균 월 근로시간 60시간」 으로 바뀌었는데(시행령 제26조의8 제2항) 「근로기간」 을 풀이한 해석례가 아직 없어 엔진은 종전 기준으로 세고 확인 줄로 알립니다.
- **더존 급여대장 PDF 를 바로 붙입니다.** 달별 PDF 폴더를 kordoc(`npx -y kordoc@^4`)으로 표로 읽어 급여대장 시트에 넣고, 달마다 읽은 사람 수를 PDF 의 「합계(N명)」 과 맞춥니다. Node.js 18 이상이 있어야 합니다. 사원명부 · 회사정보 파일과 PDF 폴더를 한 번에 묶는 `python -m ctax.employ.assemble` 도 있습니다. 이전 판은 PyMuPDF 글자 좌표로 읽었고 파일 마지막 사람의 지급액에 합계 줄 숫자를 더하는 버그가 있었습니다.
- **샘플.** `--sample` 이 만드는 합성 회사 스무 명으로 설치를 확인합니다. 세액공제액 92,355,000원(2025 과세연도), `--sample-year 2026` 이면 78,180,000원, `--sample-year 2027` 이면 56,800,000원이 나오면 됩니다. 실제 회사 자료는 저장소에 없습니다.
- **판단은 회계사가.** 임원 · 최대주주와 친족 · 계약기간 · 장애 구분은 사원명부에 적힌 대로 씁니다. 엔진은 그 값이 맞는지 보지 않습니다. 납부 확인은 급여대장 공제액으로 대신했습니다.

엑셀 재계산 대조는 윈도우의 엑셀에서만 돕니다. 맥 · 리눅스에서는 엔진 값을 내고, 워크북을 엑셀로 열면 같은 검산이 보입니다.

## 회계기준검토

기준서 원문을 문단 번호까지 읽고, 질의회신과 웹으로 최신성을 확인한 뒤, 금감원 감리지적사례 · 회계기준원 질의회신 · IFRIC Agenda Decision · Big4 간행물 · 상장사 공시로 결론을 반증합니다. 반례가 나오면 원문으로 돌아가 결론을 고칩니다.

- **기준.** K-IFRS, 일반기업회계기준, 중소기업회계기준. 적용 대상부터 판별합니다.
- **원문은 각자 받아 둡니다.** 기준서는 저작권 때문에 이 저장소에 넣지 않았습니다. 한국회계기준원 「시행중 회계기준」에서 PDF 를 받아 한 폴더에 두고 `ACCOUNTING_STANDARDS_DIR` 로 알려 주면 그 폴더를 읽습니다. 폴더가 없으면 웹으로 잠정 검토하고 "기준서 원문 미검증"을 첫 줄에 적습니다.
- **결과.** 핵심쟁점 · 결론 · 회계처리(분개) · 상세설명 · 권위 사례 대조 순서의 자문 문서.

## 리스회계

계약서에서 개시일·기간·리스료·지급시점·보증금·할인율을 뽑아 조건 파일로 고정하고, 계산은 파이썬 엔진이 합니다. 현재가치, 유효이자율 상각, 정액 감가상각, 월별 전표를 만들고 엑셀 네 시트를 전부 셀 참조 수식으로 잇습니다. 입력가정의 할인율을 바꾸면 상각표와 전표가 따라 바뀝니다.

- **검산.** 엔진 값을 연금 현재가치 닫힌 식과 맞추고, 엑셀 수식을 `formulas` 로 독립 재계산해 엔진과 맞춥니다. 차대 일치, 리스부채·사용권자산 기말잔액 0, 총리스료 − 리스부채 = 총이자를 확인합니다.
- **판단은 회계사.** 내재이자율이 없으면 증분차입이자율 5% 를 자리값으로 두고 가정으로 표시합니다. 회사의 IBR 로 바꾼 뒤 확정합니다. 갱신·매수선택권, 단기·소액 면제도 회계사가 정합니다.
- **다루지 않는 것.** 변동리스료, 리스변경 재측정, 복구충당부채 전입액, 다통화.

## 매입매출장검토

완성된 장부를 원천자료(매출집계·주문·정산·세금계산서·카드·현금영수증·은행) 옆에 놓고 검토항목 32개로 봅니다. 10개는 스크립트가 자동으로 대조하고, 나머지 22개는 항목마다 적힌 검토 방법대로 회계사가 봅니다.

- **누락은 원천에서 보입니다.** 장부 안에서만 보면 빠진 매출(F1)과 일반전표로 간 세금계산서(F2)가 안 잡힙니다.
- **수정분개는 더존 양식으로.** 원건을 음수로 지우고 정건을 양수로 넣습니다. 원장에는 적용하지 않고, 반영한 사본으로 다시 검토해 정지가 0건인지 봅니다.
- **규칙은 CSV.** 채널의 총액·순액, 불공제 가맹점, 고정자산 계정을 고객사마다 CSV 로 적습니다. 들어 있는 규칙은 합성 예시입니다.

## 부가세신고서검토

장부가 맞아도 신고서는 틀릴 수 있습니다. 매입매출장검토로 장부를 닫은 뒤, 같은 장부에서 별지 제21호서식 본지를 다시 계산해 직원 작성본과 란별로 대조합니다. 검토항목은 40개이고 18개가 자동입니다.

- **부속명세 8종.** 매출처별·매입처별 세금계산서합계표, 신용카드 수령명세서·발행금액집계표, 공제받지 못할 매입세액 명세서, 감가상각자산 취득명세서, 영세율 매출명세서, 계산서합계표를 장부에서 만들고 본지와 공급가액·세액 둘 다 0원으로 맞춥니다.
- **놓치기 쉬운 것.** 전자신고세액공제 금액과 세무대리인 신고 여부, 법인의 신용카드 발행공제, 영세율 첨부서류(시행령 제101조) 누락을 따로 봅니다.
- **PDF.** 국가법령정보센터의 서식 원본 PDF 에 값만 얹어 신고서를 뽑습니다. 검토·보관용입니다. 제출용으로 쓰지 않습니다.

## 자금일보

계좌 거래내역 CSV 와 분류규칙 표 하나로 자금일보를 만듭니다. 은행 엑셀이든 데이터 플랫폼(예: Gridie)의 은행 연동 표든 열 이름만 맞추면 됩니다.

- **1원 검산이 먼저.** 계좌마다 거래 한 줄씩 잔액이 이어지는지, 날마다 전일 잔액 + 입금 - 출금 = 계좌 잔액 합계인지 봅니다. 하나라도 어긋나면 파일을 쓰지 않고 날짜와 차이를 내고 멈춥니다. 계좌 간 이체는 입출금에서 양쪽 다 빼므로 이체의 한쪽만 놓쳐도 여기서 걸립니다.
- **분류는 표로만.** 적요·거래처에 든 말로 자금코드를 붙입니다. 표에 안 걸린 거래는 비슷한 코드에 넣지 않고 「확인 필요」로 모읍니다. 규칙을 바꾸려면 표에 한 줄을 더하고 다시 돌립니다.
- **결과.** 대시보드 HTML 한 파일(기준일 달력, 마감 잔액 추이, 자금코드별 유입·유출, 앞으로 2주 일자별 예측, 계좌별 잔액, 확인 필요 거래, PDF 인쇄)과 자금일보 md.
- **예측.** 입출금 예정표는 그대로 쓰고, 판매 정산·매입처럼 반복되는 흐름은 최근 영업일 평균으로 채워 근거를 같이 적습니다. 평균이라 정산 주기와 계절성은 반영하지 않습니다.

예시는 지어낸 회사의 계좌 4개, 거래 688건입니다. 원화 계좌만 다루고, 은행 잔액 자체가 맞는지는 잔액증명과 따로 대조해야 합니다.

## 감사 스킬 셋(분개테스트 · DSD푸팅 · 감사대시보드)

외부감사 조서를 단계별 스킬로 나눠 만드는 감사 모듈에서, 감사 폴더 전체가 없어도 따로 돌아가는 두 단계를 떼어 공개합니다. 스킬마다 `scripts/audit` 에 감사 엔진 가운데 그 단계에 쓰는 부분만 들어 있습니다. 숫자는 엔진이 계산하고, 문서를 읽어 뜻을 정하는 일은 Claude 가 「확인 전」 으로 하고, 판단(중요성 · 결론 · 의견)은 회계사가 합니다.

- **분개테스트.** 위험 대응 단계(3600-JET). 분개장으로 시험 스무 가지와 분포 분석을 돌립니다. 그 가운데 자기 승인 · 결산 후 입력 등 네 가지는 작성자 · 승인자 · 입력일시 열이 있어야 돕니다. 예시는 가상 회사 가온정밀(가상)의 분개장입니다.
- **DSD푸팅.** 보고 단계. 회사가 낸 dsd 의 숫자와 문장을 검증합니다. 예시는 오류 11개를 심은 가온정밀(가상) dsd 와 정답표입니다.
- **감사대시보드.** 위 두 스킬이 감사 전체 흐름(다섯 단계 · 조서 58개 · 스킬)의 어디에 붙는지 보는 화면입니다. 감사 폴더의 `_색인` 을 읽어 단계별 조서 상태 · 스킬 적용 현황 · 이슈를 보입니다. 예시는 가온정밀(가상) 모의 감사 폴더의 `_색인` 과 완성 화면입니다.

예시 자료의 회사 · 사람 · 거래처 이름과 숫자는 모두 지어냈습니다. 고객 자료와 결과 파일은 저장소나 공유 폴더에 올리지 마십시오.
